# Product V2 项目上下文重新审计与控制面整理

## 1. 审计结论

控制面结构已经有 INDEX / project-context / plan / state / README 五类权威，但内容仍有四处实质漂移：

1. README 被登记为“实现唯一入口”，却保留约 6 万字 legacy renderer / Product V1 说明，并复制
   Product V2 阶段、下一任务、固定七坑位表和回归数字。新接手者会从“当前实现”入口读到旧业务模型。
2. 八份旧横切文档长期标记为 to-delete，删除条件又不可判定；文档正文包含“主流程抠图、固定七图、
   只有一格调模型”等已被 Product V2 否决的方案，虽然无权威仍会制造检索噪音。
3. 项目上下文 §2 复制了施工进度；§4.2 又把未定案的 V2.2 SemanticProvider 写成 requests 已用，
   与 SEL-003“待确认 openai SDK”冲突。
4. 产品计划 §1.3 保存了会过时的“当前不能声称”，其中 IndexedDB 尚未成为权威已被 Phase 1 的实现
   和证据推翻。计划不应兼任进度表。

旧守卫在修改前全绿（文档 53/53、依赖 6/6、模板 14/14），说明它能守结构一致，却没有守住
“README 不复制进度、当前入口不承载旧业务模型”这一语义边界。

## 2. 处置

- README 重写为当前实现投影：默认 V2 已落地边界、真实启动/验证、数据所有权、V1 回归入口和明确缺口；
  不再复制任务进度、任务 ID、固定七坑位表和历史事故流水账。
- 八份旧横切文档从 to-delete 统一改为 superseded / 历史证据；不物理删除，保留旧路线的第一手轨迹，
  但恢复流程默认不读。
- INDEX 登记表与历史保留策略同步；无限期、不可判定的“待删”状态被消除。
- 项目上下文 §2 改为稳定迁移边界与事实路由；SEL-001/002/004/005 标记为已生效，SEL-003 仍是
  唯一待确认选型；requests 登记恢复为 Product V1 实际用途。
- 产品计划只保留稳定的完成声明边界，并把 PoC 发现的 reasoning 预算约束写进 V2.2.2 验收。
- check_docs 改为检查 README 当前/历史边界，禁止 README 复制 next_action、Product V2 任务 ID、
  固定七坑位表和手抄回归项数。legacy 卡仍由生成器逐字校验。

整理过程中真实执行 README 验证命令时，首次发现 Playwright 不在 requirements.txt，直接运行验证脚本
会报 ModuleNotFoundError。README 已改为显式 `uv ... --with playwright`，随后五个验证入口全部通过。
