# 1. Candidate A — OpenAI Images API (gpt-image-1.5, bounded pin) PROVEN docs, PROPOSED pin（续）
[返回 image-candidate-review-20261002.md](image-candidate-review-20261002.md)

- Model/protocol + reference input [PROVEN docs]: `POST https://api.openai.com/v1/images/generations` and `/images/edits`; JSON edits accept up to 16 image references, `image_url` includes data URLs, `input_fidelity: high|low` is documented for 1.5 ([reference](https://developers.openai.com/api/reference/resources/images)). Auth: Bearer, organization verification may be required. Product ≤3 refs fits this count, but synchronous immediate bytes need a real neutral-contract cutover; the existing task-only submit/status/result contract does not fit unchanged. Eligible account/region must be confirmed before paid proof.
- Prompt transparency [PROVEN]: GPT image models do **not** return `revised_prompt` ([reference](https://developers.openai.com/api/reference/resources/images)); what we send is what is logged as sent. The Responses-API tool path **does** auto-revise prompts (`revised_prompt` field, [guide](https://developers.openai.com/api/docs/guides/image-generation)) — rejected for the adapter for exactly this reason (see §4).
- Output acquisition [PROVEN]: GPT image models return `b64_json` inline by default; `url` response format is unsupported for them ([reference](https://developers.openai.com/api/reference/resources/images)). `output_format: png|jpeg|webp` (+ `output_compression` 0–100 for jpeg/webp), `background: transparent|opaque|auto` (transparent needs png/webp). Bytes-inline output removes the entire signed-URL TTL/download-allowlist class the DashScope adapter carries.
- Async identity / recovery limitation [PROVEN]: the Images API is **synchronous** — no provider task id, no status/result polling endpoints observed on pages read. Consequence: submit-time timeout/5xx-after-send maps to `provider_unknown` with **no authoritative reconcile possible** (worse than DashScope, where a known task id can be re-queried); the adapter MUST surface UNKNOWN + forbid auto-resubmit per the existing timeout rule, and per R5.2 MUST NOT mint a fake provider task (synchronous-equivalent normalization: `task_id=None` + immediate bytes, not a pseudo-task). Latency can reach ~2 min on complex prompts ([guide limitations](https://developers.openai.com/api/docs/guides/image-generation)) — gateway timeout/budget must reflect that. No idempotency-key parameter observed [UNKNOWN — do not assume one].
- Sizes/counts [PROVEN docs]: the proposed `gpt-image-1.5` pin uses only explicit `1024x1024`, `1536x1024`, `1024x1536` and `n=1`, `quality=medium`, PNG. API reference's arbitrary ÷16 resolutions are explicitly for gpt-image-2/2.5, NOT evidence of 1.5 capability ([reference](https://developers.openai.com/api/reference/resources/images)). UI readiness must enforce the selected model's actual finite size set; no silent resizing or auto fallback.
- Prices, current [PROVEN]: token rates ([pricing](https://developers.openai.com/api/docs/pricing)) — `gpt-image-1.5`: image input $8.00 / cached $2.00 / image output $32.00 per 1M; text input $5.00 / cached $1.25 / text output $10.00 per 1M; Batch halves these. Worked output-cost examples at the three standard sizes ([guide cost tables](https://developers.openai.com/api/docs/guides/image-generation)): 1.5 at 1024×1024 ≈ **$0.009 low / $0.034 medium / $0.133 high** per image output **plus** text+image input tokens. Bounded-pin estimate: `medium/1024/n=1` ≈ $0.04–0.06/all-in per submit; a 10-submit PoC ≈ **<$1 output + small inputs** (confirm from `usage` in PoC; docs, not a quote).
- Region / private-material terms [PROVEN]: API content is **not used for training** (since 2023-03-01 unless opted in); `/v1/images/*` have **no application-state retention**, 30-day abuse-monitoring retention, and are **Zero-Data-Retention eligible** (with the CSAM-scan carve-out) ([data controls](https://developers.openai.com/api/docs/guides/your-data)). Regional processing/storage (US/EU/others) with +10% uplift for post-2026-03-05 models ([pricing](https://developers.openai.com/api/docs/pricing)). Output-ownership clause NOT verified this pass (ToS page not successfully read) [UNKNOWN — R4.2 must confirm before commercial-use commitment].
- License / dependency / removal [PROPOSED]: API is a paid service governed by [OpenAI Services Agreement](https://openai.com/policies/services-agreement/), not consumer Terms of Use or an OSS license. Official search excerpt §4.1 says customer retains Input and owns Output to extent permitted by law; full-page fetch returned 403, so full conditions/non-uniqueness/third-party rights must still be reviewed before commercial use. Existing locked requests + JSON can implement raw HTTP without new package. Removal cost: adapter/registry/capability records; synchronous contract normalization affects consumers and is not a trivial task-only plug-in.

## 2. Candidate B — Google Gemini 3.1 Flash Image (`gemini-3.1-flash-image`, "Nano Banana 2") — runner-up, NOT recommended for first proof

Primary sources: [Image generation guide](https://ai.google.dev/gemini-api/docs/image-generation), [gemini-3.1-flash-image model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-image), [legacy 2.5 Flash Image page](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-image), [Pricing](https://ai.google.dev/gemini-api/docs/pricing), [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), [Additional Terms](https://ai.google.dev/gemini-api/terms).

- Reference input [PROVEN docs]: current guide uses `/v1beta/interactions` with `x-goog-api-key`, text/image input and image/text output. The complete guide explicitly documents **up to 14 reference images**, including up to 10 object images and 4 character images for 3.1 Flash ([guide, reference section](https://ai.google.dev/gemini-api/docs/image-generation#use_up_to_14_reference_images)). The earlier “no max-ref documented” finding was a partial-read error, not a candidate blocker. Product's ≤3 refs fits the documented count; real fidelity remains unmeasured.
- Output [PROVEN docs]: inline base64 `output_image.data`; generated images include SynthID ([guide](https://ai.google.dev/gemini-api/docs/image-generation)). [SynthID documentation](https://ai.google.dev/responsible/docs/safeguards/synthid) describes imperceptible digital watermarking, not necessarily a visible logo. Do not equate SynthID with visible Amazon-main-image watermark rejection; actual delivered pixels and applicable platform policy still need acceptance.
- Async identity / recovery [PROVEN gap]: synchronous interactions observed; no image-task/status polling observed. Batch API exists but is a token-enqueue mechanism with per-tier caps, not image-task reconcile ([rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)) — not a submit/status/result substitute. Same UNKNOWN-no-reconcile limitation as Candidate A, plus interaction-id traceability NOT verified [UNKNOWN].
- Sizes [PROVEN]: 0.5K/1K(default)/2K/**4K**, new 1:4/4:1/1:8/8:1 ratios, improved adherence ([model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-image)). 4K exceeds the contract's 2048 edge cap → must clamp to ≤2048 unless the contract changes with approval; ratio range matches the contract.
- Prices [PROVEN docs, not measured]: [pricing](https://ai.google.dev/gemini-api/docs/pricing) lists standard input $0.50/M text/image; image output $60/M, approx $0.045/0.5K, $0.067/1K, $0.101/2K, $0.151/4K; Batch halves. The quoted **$0.067/1K output is higher**, not cheaper, than OpenAI 1.5 medium's quoted $0.034/1024 output. Neither output-only figure is a total price bound; input and other applicable charges remain.
- Region / private-material terms [PROVEN]: Paid quota (billing-linked project) is **not used to improve products** and is processed under the Data Processing Addendum (abuse logging only, limited period); **Unpaid quota trains/improves models with human review** ([terms](https://ai.google.dev/gemini-api/terms)) — product BYOK policy must therefore **forbid free-tier keys**, a sharper foot-gun than Candidate A. EEA/UK/CH clients must use Paid Services; developer (non-consumer) use only; no competing-model development; rate/spend limits per project + tier caps and $10/10-min Tier-1 spend limit with 429s ([rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)).
- License / dependency / removal: paid API service terms (no OSS license); adapter would likewise reuse `requests` (no new dep) — but the `interactions` protocol is newer than OpenAI's Images API and the Python `google-genai` SDK shape is still shifting across doc pages, so raw-HTTP surface risk is higher. Removal cost small (same shape as A).
