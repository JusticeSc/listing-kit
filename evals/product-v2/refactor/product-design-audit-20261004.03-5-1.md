# 5.1 当前项目最重要的模型区分
[返回 product-design-audit-20261004.md](product-design-audit-20261004.md)

### 5.1 当前项目最重要的模型区分

- 用户编辑草稿 ≠ 已确认事实；模型提案 ≠ 事实。
- 可编辑套图/Prompt ≠ 已提交动作的不可变快照。
- 生图执行 Attempt ≠ 候选图 Candidate ≠ 人工采用 Selection。
- 用途（语义/图像/复核）≠ 模型配置 ≠ 协议 Adapter ≠ 凭据。
- 用户当前界面阶段 ≠ 业务就绪条件 ≠ 外部任务生命周期。

最后一项决定：可以把六步骤改成连续工作台，但不应因此推翻候选、任务恢复、事实权限和历史。需要审阅/确认是一条业务规则；“必须有一个先点的确认按钮，再找另一个生成按钮”不是业务规则。

### 5.2 最小改动的合理含义

目标是把有依据的变化限制在少数 Module，同时让不该变化的业务不变量保留；不是预测全部未来或承诺任意变化都廉价。

| 变化场景 | 合理的变化范围 | 不应被迫变化 |
|---|---|---|
| 六步引导改连续工作台 | 任务投影、页面与操作编排 | 事实权限、Candidate/Selection、Blob历史 |
| 增加已批准生图协议 | Adapter、注册/能力档；两种真实 Adapter 检验 Seam | 每个页面按钮增加供应商 if 分支 |
| 用户切换模型/key | 有效配置消费者、精确失效；旧动作按原身份恢复 | 改写旧候选/任务身份；key进入数据包 |
| 增加图片类型/品类事实 | 领域模板/依赖与任务编辑 | 固定七坑位页面和全流程硬编码 |
| 本地单人改云端多人协作 | 必须重审权威位置、鉴权、并发、同步、隐私、运维 | 不能承诺仅替换repository就完成 |

业务语义分离能降低根本变化的迁移成本，但不能消除新问题固有复杂度。既不为未来构建万能平台，也不把当前已知BYOK当“日后再接”的预留接口。

## 6. 建议后续顺序：不重新启动大重构

下列是本轮设计建议，未实施、未修改现有任务依赖/状态。

### 0. 先纠正完成定义

把“能在客户端选择支持的模型并用自己的key完成主链”与“默认四图无需逐图技术编译”补回现有任务验收。R6.3/G6及最终矩阵不能继续按完整交付解读。保留已成立工程成果；不重跑已成立全部验证。发布模块字节差异先用现有部署产物/镜像检查定位，不先假定重部署可解决。

### 1. 一张真实任务流程草图，覆盖设置和生成

同时确定：进入任务前如何配置；事实确认后如何知道将生成什么；哪一个动作会付费；失败后在哪里继续；有哪些高级内容默认隐藏。不是先画一套视觉风格、再倒推业务。

默认四图的建议流程：系统准备适用Prompt（无外呼）→同一摘要展示图数/模型/规格/参考/风险→一个明确“确认并生成”入口。内部依然先冻结确认、持久化action再外发。用户改高级Prompt可保存新版本，但普通路径不要求逐图“编译并保存”。不足依据显示准确修复位置；不要显示“没有待生成的图”。

必要明确决策保留：模型推断事实、外发付费、人工采用、未知提交后新动作、破坏性删除。打开面板、编译、查看、导航、停止新增不增加确认弹层；风险和可逆性决定确认方式，不以“安全”为由给每步加一关。

### 2. 客户端配置纵向切片

设置入口始终可发现；按语义/生图/复核用途显示已支持配置，Adapter/能力由配置决定，不开放任意协议平台。BYOK秘密仅内存，可清除、作用域与刷新后需重输清楚；非秘密配置可按现有数据合同保存。

必须从设置UI贯通实际请求、能力投影、Prompt失效、原任务恢复和错误反馈；现有只有image请求头不够。语义/单图复核/整套复核消费者须一并接通相应用途，不能只做好生图输入框仍让第一步分析被closed卡住。多人共享无状态网关不得把某人的客户端配置改为进程全局配置；默认档保持关闭。

验收：页面选择/输入（用无价值测试key）→受控上游捕获对应用途和配置→仅凭据轮换不改Prompt→模型参数变化只使相关未提交准备过期→旧任务使用原身份→刷新key清除而项目/候选保留→包和日志无secret。不是DOM里有输入框就完成。

### 3. 连续生成到候选对照

落实上一步确认策略，把候选与生成进度衔接到同一任务上下文。参考图/旧/新候选直接并排，返工入口就地；结果到达不抢焦点。复用已有generation/domain，先验证是否足以承接，不为了UI目标另造执行系统。

验收：默认四图准备不要求4次技术编译；单次明确外发动作不重复提交；部分失败保留成功；Unknown不重提；生成后下一步和图像上下文可理解。单图返工/重新采用不修改无关图。

### 4. 页面+视觉主链与同版本上线

跑 §4 的从零页面动作主链，截图实际读图、实际浏览器zoom与键盘；复用现有行为判据，只补会漏掉本轮真实问题的检查。单个切片先受影响验证，最终发布沿用现有必要回归合同；不擅自降低现有计划的两轮要求，也不在每个小改后全跑。

用户结果为截图/简短动作轨迹/实际ZIP/准确版本，而不是增加一张全绿矩阵。新付费真链须按原次数上限取得必要授权；离线交互/配置工作不因此暂停。C15/C17真实用户验收不由AI截图审查替代。

## 7. 意图—规约—实现 gap 的最小控制

每项重要需求只保留一个可执行场景，贯穿五处：用户结果 → 输入/判断/反馈 → Module职责和不变量 → 页面动作及独立后置证据 → 同版本线上观察。

客户端设置例：不是“实现统一registry”，而是“用户在设置选择火山并临时输入key，在本项目生成；他看到的模型和真实请求一致；刷新只丢key不丢候选；历史任务仍按原身份恢复”。这条链任一处缺失，设置就没交付。

设计水平应由这类结果、选择理由和变更影响范围判断，不由术语、文件数、模型数或测试数判断。当前工程最大的纠偏是把人的任务重新作为 Interface，而不是要求人理解内部实现顺序。
