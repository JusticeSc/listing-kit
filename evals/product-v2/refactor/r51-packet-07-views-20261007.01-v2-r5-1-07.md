## 生成视图：一次失败的切片（已回退，工作区无残留）

- 子代理先建出 `ui/generation-view.ts`（1244 行）并把 4 条 Module 回调改道到视图，但**把旧实现的删除留到「下一轮」**，因此同一份逻辑在 workspace.js 与视图里同时活着（重复实现）。
- 该状态下 `npm run build:frontend` / `check:types` / `check:generated` / `node --test`（227）仍全绿；两个 headless 验证器串行跑时 300s 超时被中断。**超时不能归因于该状态**：干净基线上 `verify_v2_3_5_pre_generation_confirm.py` 同样挂住（1500s 超时；`python -u` 日志为空），见下「既有缺陷」。真正的结论是：静态闸门与 Node 契约测试覆盖不到浏览器路径，而该脚本当前不能作为生成阶段的验收网。
- 按「宁可回退也不留半套」处置：`git checkout -- app/product_v2/workspace.js jsconfig.json`、删除 `ui/generation-view.ts/.js`；回退后 `git status --porcelain -- app/product_v2 jsconfig.json` 无输出，闸门复测全绿。
- 结论（后续切片规则）：**file-owner 式切换必须一个切片内完成「新建 + 改道 + 删除旧实现」三步**；禁止把删除留到下一轮。生成视图按段拆分（prompts / confirm / attempts+batch），每段独立完成切换与验收。
