这是意图 → 任务规约 → 实现 → 验收压缩时丢了用户结果。建议后续纠正现有 R6.3/G6/矩阵，而不是另起一套完成框架。本轮只报告矛盾，没有擅自改 state。

R6.1 报告 `:9–15` 只有状态派生时机修复，并称其余无需新增 UI；R6.2 报告 `:9–11` 是装载与工具锚点修复。可操作原型虽研究了同屏比较/dialog，但原型通过不等于正式界面已采用；不能用这两个报告证明交互重设计已交付。

### 3.3 重复成本及判断限制

- R7.1 报告记 40×2 全量离线回归；R6 各切片还各自跑多套验证，其中一些调整只是验证器锚点/fixture/种子身份。

## 4. E2E 与视觉证据分级

- `tools/run_remote_real_e2e.py` 有真实页面动作、上传、下载、刷新；历史最新记录 `v2.7.2-remote-real-e2e-20261001-091400.txt` 是重构前版本。旧全链不能证明当前部署版本。
- `tools/verify_v2_r5_2_two_adapters.py:783–786` 在资料输入后 `page.evaluate(SEED_SLOTS, project_id)` 直接写事实，跳过分析与事实确认。它有执行合同价值，不是从零开始的真人主链。
- `tools/verify_v2_volc_adopt_export.py` 有真实火山生成及采用/ZIP闭环，但资料事实是种子、整套复核是假通道；不能扩称全用途真链。
- `tools/verify_v2_ui_2_interaction_visual.py:523–535` 的截图判据主要是 DOM、卡片/按钮数量及文件 size>0；截图生成不等于读图检查布局、语义和衔接。
- 同工具 `:625–636` 把 viewport 改到720×450称200%等价视口。计划 §2.1/§12.3 要实际浏览器缩放，二者不能互换。R2基线/原型确有真实 Chrome zoom 证据，但不是当前最终产品的新鲜证明。
- `v2.ui.2-walkthrough-record.md` 有旧 AI 截图复核记录；不能说历史从未用视觉。多份 v273 预演报告的人工视审补充仍“待补充”。
- 当前矩阵线上证据是健康/能力/输入守卫，不能证明新版用户页面全链。

后续最小视觉主链：设置 → 新建 → 上传 → 分析 → 事实确认 → 套图调整 → 查看发送摘要 → 明确提交 → 候选对照 → 单图返工 → 改选旧/新图 → 导出 → 刷新/重开。动作只从页面发生，禁止内部业务调用/播种跳过待验步骤；测试替身只替模型外部响应。

视觉在关键状态先截图、实际读图，再结合可访问名/DOM定位；截图检查主次、上下文、禁用原因、图片加载、遮挡、焦点和下一步含义。观察失败时回到截图而不是盲点。坐标点击不是必需，已知selector也不是视觉验收。下载/请求次数/IDB/ZIP作为独立后置证据。图像保真/文字/审美及最终人审与软件主链分开，fake结果不证明图片可投放。C15/C17仍未通过。

## 5. 设计分析框架：七个视角，不是七层脚手架

| 视角 | 核心问题 | 应产生的最小设计判断 |
|---|---|---|
| 产品意图与业务 | 谁在什么情境下把什么做成什么？什么决定价值？ | 主任务、成果、非目标；已知需求不归入未来扩展 |
| 任务与人因 | 人做哪些判断，系统做哪些劳动？错误/等待/恢复如何理解？ | 任务路径、信息架构、反馈、决策点及其风险；原图/候选的同屏上下文 |
| 领域建模 | 事实、方案、版本、执行、候选、采用各是什么？谁有权改变？ | 对象身份、关系、不变量、业务状态转换 |
| 数据建模 | 当前值/历史/Blob/配置/秘密分别归谁？如何原子更新？ | 权威位置、版本、事务、并发、导入导出与恢复合同 |
| 应用与架构 | 变化由哪个 Module 承担？调用方要知道多少？ | 高 Depth 的 Interface、职责与 Seam；删除重复编排，不增加 pass-through |
| 外部协议与运行 | 模型/目标/凭据/同步异步/失败/费用/部署如何受约束？ | Adapter、能力投影、冻结执行身份；安全与运行限制可解释 |
| 规约与交付证明 | 用户意图如何变成可观测条件，再到实际发布？ | 少量用户场景+关键不变量，证据范围匹配；缺一必需功能即未完成 |

人因工程贯穿任务、系统和操作情境，不只是CSS/按钮位置。工作记忆负担、决策疲劳、错误预防/恢复、知觉反馈与控制感都会改变流程与领域操作。浏览器UI只是其中一个载体。后端也不能等同于业务：本项目大量业务在浏览器，Python主要是外部协议网关。

理论对应：任务分析与以人为中心设计负责使用问题；领域建模负责语义；信息隐藏/高内聚低耦合负责变化的 Locality；数据权威/事务负责正确性；场景化规约负责意图和实现的落差。不因引用这些理论而增加框架。
