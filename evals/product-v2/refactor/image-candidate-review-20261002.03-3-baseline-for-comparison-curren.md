## 3. Baseline for comparison — current DashScope `qwen-image-3.0` [PROVEN]

- T2I + I2I (1–3 refs) in one model; refs JPG/JPEG/PNG/BMP/TIFF/WEBP/GIF, 384–2048 px, ≤10 MB; prompt ≤4500 tokens; three access modes: OpenAI-compatible **sync** (`POST …/compatible-mode/v1/images/generations`, `image` extension field, NOT `/images/edits` multipart), DashScope **sync** (recommended, `multimodal-generation/generation`), DashScope **async** (task id + poll — what the current adapter speaks) ([reference](https://help.aliyun.com/en/model-studio/qwen-image-generation-and-editing-api-reference)). Output PNG URLs **valid 24 h** (sync + compat) — current async adapter already downloads to bytes; any sync-mode use must do the same, never persist URLs. Usage metering `qima_input/output_1k|2k` by output area ≤/>2.25M px.
- Prices (model page, USD/image, [qwen-image-3.0](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-image-3-0)): Beijing/Global-1K&2K: input $0.00275 + generation $0.024754; Singapore: $0.003 + $0.03. RPM 20 all regions. Region binding: model, endpoint, and key must share a region or calls fail ([reference](https://help.aliyun.com/en/model-studio/qwen-image-generation-and-editing-api-reference)).
- Why it is not the "second" proof: same supplier/protocol family (SEL-010) — a `qwen-image-3.0-pro` or `wanx` entry would not demonstrate the purpose/capability/adapter/credential split the Goal demands. Rejected as second adapter; retained as baseline.

## 4. Recommendation (bounded) + rejected alternatives + revisit criteria [PROPOSED]

- **Recommend for R4.2 PoC (only after budget/material/region approvals): Candidate A pinned as `openai-image-1.5` via Images API JSON (`/images/edits` with `image_url` data-URLs + `/images/generations`), `n=1`, sizes ⊂ {1024×1024, 1536×1024, 1024×1536} ∩ contract, `quality=medium`, `output_format=png`, prompt sent verbatim, bytes-only acquisition, sync-equivalent normalization (no fake task id), default-key trial CLOSED until §5 policy lands.** Reasons: documented multi-ref edit path (≤16, we use ≤3) + explicit `input_fidelity` + mask; no hidden prompt rewrite on this path; bytes-inline kills URL-TTL handling; ZDR-eligible + no-training-default terms fit private product photos; cheapest documented per-image evidence (~$0.034 medium) bounds the PoC.
- Rejected for first bounded proof [PROPOSED]: Responses image tool auto-revision/conversation retention; unmeasured 2/2.5 variants rather than claiming their lower $30/M output rate is “higher” than $32/M; same-supplier upgrades that cannot prove cross-supplier decoupling; chat-only paths; persisted supplier URLs. Gemini remains a viable alternate with documented multi-reference support: tradeoffs are interactions protocol, paid-tier data policy, output price and watermark acceptance—not a nonexistent reference-limit gap.
- **Revisit criteria:** 1.5 fidelity inadequate in approved PoC → escalate to `2.5-flare/medium` with fresh budget sign-off; org-verification or budget blocked → re-open Candidate B after resolving max-ref count, 4K-clamp decision, and SynthID/Amazon ruling; EU-only deployment → re-weigh OpenAI residency uplift vs Gemini Paid-mandatory posture; contract ratio/size change approved → re-check intersections.

## 5. BYOK + allowlist + default-key deployment policy assessment [PROVEN current, PROPOSED policy]

- BYOK auth in request memory [PROPOSED on top of PROVEN seams]: session-held key → per-request `Authorization` only for the BYOK-selected provider id; never written to IndexedDB/localStorage/ZIP/log/error/evidence (extends the existing `redact()` + `no-store` + no-secret-result posture). Missing-key and bad-key paths return explicit non-secret errors (pattern exists: `PROVIDER_NOT_CONFIGURED`). A user-supplied base URL MUST NEVER inherit the deployment default key — fail closed (R4.3 rule, not yet code).
- Safe target allowlisting [PROVEN pattern, PROPOSED extension]: keep the DashScope precedent per provider — exact-suffix HTTPS allowlist (`api.openai.com:443` for Candidate A), no userinfo/query/fragment, `allow_redirects=False`, response-bytes validation (PNG signature + content-type gate), DNS-rebinding/private-range review as R4.3 work (current guard is suffix-based, not IP-based — recorded gap, not a claim).
- Default-key policy [PROPOSED, not current-network proof]: recommend **default paid trial OFF** until owner authorizes access scope and enforceable spending limits. Existing Caddy TLS/reverse_proxy can stay; [`http.handlers.rate_limit`](https://caddyserver.com/docs/modules/http.handlers.rate_limit) is explicitly a **non-standard module that does not come with Caddy** (official module search excerpt), so do not claim native rate limiting or install xcaddy/plugin without a separate gate. Billing alerts/RPM limits are not a hard dollar cap. Current Caddyfile has no auth/rate-limit proof; do not assert current routes are already private. A future closed trial must demonstrate its boundary and stop behavior; no new application account framework.
