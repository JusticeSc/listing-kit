## 4. 后续实施顺序与边界

以下是人因改进内部的建议顺序，不是当前整体施工顺序。用户后续提出先收敛可信基线，整体优先建议更新为 §9；仍合并到既有任务与验收口径，不新增 Goal 或验证平台：

1. 先修 H1 操作对象绑定和 H2/H6 状态语义，降低改错版本、反复处理非阻断提醒的风险。
2. 再消除 H3/H4 的机械步骤与重复录入，保持明确外发、人工事实确认与现有报告当前性围栏。
3. 在行为稳定后调整 H5 的审核工作区与 H7 的摘要/交付层次；先做一条主图比较→返工→采用→交付纵向路径，不先重画全部页面。
4. 原定旧运行面清退、RC19、规定的两轮离线验收及发布前置仍须按原计划闭合；本走查不替代它们。C17/C15 保持待真人，不用截图数或脚本成功冒充。

每项只复用必要行为验证，再运行该实际交互路径并读图。后续真人任务观察关注是否改错候选、是否误把提醒当阻断、是否需要帮助找到下一步；本报告没有预设真人得分或声称这些指标已改善。

## 5. 纠正与测量限制

- 更正先前表述：旧 6730px 生成截图不能代表当前默认页面。此次默认高级 Prompt 收起，生成就绪页为约 2080px；主动作在文档 Y1087。不能以旧长度批评“默认展开所有 Prompt”。真正问题是摘要层次、首次授权状态说明和重复执行区。
- 初始脚本假图为 64px，被真实 1000px 硬门拒绝，这是夹具尺寸限制，不是产品误阻断。明确改为同源 1200px 假供应商后经 UI 新动作恢复；旧结果、失败与 Unknown 没被清除，没有弱化检查。
- 截图辅助先拍全页再读取 DOM，可能改变滚动位置/焦点时序。因此不以这些 scrollY 推断自然导航跳动；只用固定视口、实际页面与控件文档坐标讨论空间距离。
- 早期“可见控件数”包含部分关闭 details 后代，不作为真实选择数量或键盘负担。填值差异与 detached-click 工具事件保留记录，但没有证明人类输入丢失或点击失败，不列为产品人因缺陷。
- 没有真人任务时间、错误率、NASA-TLX 或满意度数据。专家分析能提出并定位风险，不能替代用户真实工作负荷与感受的测量。

## 6. 第四步深化：发送界面应随任务阶段变形，而不是上下两套清单

本节与 §7 根据同一轮实际运行记录进一步分析，没有重开浏览器、重跑模型或改产品。`docs/product-v2-ui-contract.md` §4.6–4.7 仍是设计草案；它已写一次明确提交、同图工作区与就地返工，不能据此声称当前实现已达到。

### 6.1 实际布局与主次问题

- 08 截图：顶部高级 Prompt 入口已经折叠，随后“实际发送摘要”列四张任务；下面“生成执行”再次列相同四张。摘要区没有参考照片缩略预览，主要是用途、字数、版本、参数与风险文字。
- 09/10：发送后原摘要仍占据页面上半部，成功图片和处理异常位于第二套列表。10 的主按钮实际为禁用的“确认并生成 0 张”；可操作的重试、比较和 Unknown 新动作在下面。
- 成功行先列“AI 复核这条候选”，然后“比较候选”，另有“再生成一张（新建 action）”。这些入口有真实用途，但不是相同优先级的决定。

`[INFERENCE]` 用户需要把上方的发送对象与下方执行结果重新配对；任务已经进入看图/恢复阶段，页面最显著的位置却仍是旧发送摘要。默认先出现 AI 复核也可能引导人在看图前购买额外调用。这不是无反馈，而是反馈和当前意图的层次没有对齐。

**建议：保留同一组稳定图片行，以状态替换内容。** 待发送时呈现参考缩略、用途、必要上图文字和缺项；发送后同一行变为真实状态、结果缩略与对应操作。已发送摘要折叠为可查记录，不持续伪装成当前可发送计划。成功行主动作是查看/比较；额外生图与可选 AI 复核是有费用说明的次操作。

### 6.2 主操作与范围转换

| 当前情形 | 默认主动作与解释 | 不应发生 |
|---|---|---|
| 首次待发送 | 确认并生成 N 张；列出准确集合、模型、参考内容与费用说明 | 隐藏排除项；把一次发送拆成授权、保存、提交三个必经动作 |
| 生成中 | 显示真实逐图状态；有成功图即可审核；可停止尚未外发的队列 | 虚构百分比/剩余时间；“停止”被描述为撤销已受理请求；结果到达抢走当前焦点 |
| 部分结果 | 先查看成功图；明确失败可打开其重试摘要，Unknown 独立核对或明确另发 | 用一个“继续/重试全部”混入成功、在途、Unknown |
| 没有可新增发送 | 显示已有结果和可做的下一步，不把蓝色“生成 0 张”留作主按钮 | 让零发送按钮看起来像主要任务仍不可完成 |
| 用户另选模型或改参数 | 对新动作说明变化；已开始的任务仍属于原身份，原队列按原摘要恢复 | 把旧任务重定向给新模型；设置应用后自动外发 |

主按钮变化不能改变已经确认的发送范围：实际请求仍须与人看到的当前摘要一致，摘要/身份过期就停止并说明，而非偷偷发送新内容。默认集合是否包含某张图必须在行上可辨；硬缺项不能静默忽略，更不能被“已进入第四步”视为已满足。

### 6.3 文案与知情决策

- 10 的“新建 action（放弃核对）”应改成人可理解、准确说明后果的另发入口。“放弃核对”容易被理解为原请求已经取消；原请求可能受理/计费的事实仍必须保留。不能无 task id 时伪装成可查询。
- 首次摘要应让人看见实际参考照片，知道自己发的是哪一件商品，而非仅看到“primary”与参考数量。
- 摘要的语言风险涉及中文“必须保持的商品特征”，并建议把事实改成英文。输入描述语言、不可改的品牌原文、实际上图文案语言必须区分。**本轮没有核对该规则的消费者，不能据假图断言其误判。** 后续应核对究竟哪个字段计划上图；不能让用户为消除警告去翻译不应改变的事实或品牌。
- 此处的验收是对象、范围、状态与下一动作可理解，不是统计一次少了几个按钮。复用当前发送身份与门禁，不新增万能 UI 状态框架。

## 7. 第五步深化：应该是审图工作台，不是卡片列表加页尾编辑器

### 7.1 概览与精看应是两个信息尺度

实际页面先展示四张大图卡及重复报告，再整套一致性，再候选比较，再返工。22 的图像比较支持参考原图与可指定对照；本轮默认“不指定对照”时，中间仍占有一块空白对照区域。

`[INFERENCE]` 套图概览需要迅速找到下一张需要决定的图；单图审核需要足够大、稳定的图像和相邻操作。把两个尺度纵向叠加，既重复占空间，也使返工离开刚才判断的图像。没有指定对照时固定空列还压缩真正需要看的原图与当前候选。

建议使用紧凑套图导航与单图主区：默认原图/当前候选两列；用户明确指定旧候选后才增加或切换对照。保持原比例、不裁商品；已有放大能力应保留，不能用一个放大弹层代替正常比较空间。整套检查置于可见摘要或独立概览，不插在单图与返工之间。

### 7.2 四个对象不能靠用户猜

- **当前查看**：我正在判断哪一个候选。
- **当前采用**：下游交付会引用哪一个候选。
- **对照候选**：用于比较，不因此被采用。
- **返工依据**：本次请求明确以哪一个候选为来源。

这是现有业务身份在界面的投影，不是新建后端概念。22 明确显示查看 v2 且已采用，是已有正确反馈；20 从显示 v2 的卡片进入返工却落到 v1，是需要解决的入口上下文问题。候选按异常优先排序不应暗中决定卡片操作对象。

建议候选历史使用稳定、可辨的版本与状态标记；异常可筛选，不以它替代当前任务导航。“下一个待处理”应明确是下一个未采用/当前有硬问题的图片任务，还是历史问题；已弃用 v1 的阻断不应变成修复已采用 v2 的义务。
