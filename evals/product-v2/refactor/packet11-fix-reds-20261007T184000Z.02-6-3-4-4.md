### 7.3 `4_3` `-09`（停止）机制：消费门与"停在第一张"互斥

产品批次是**顺序** for 循环（`app/product_v2/generation.ts` `runBatch`：逐张 `await performSubmitAttempt` 再 `pollActiveAttempts`，循环头检查 `running.stopped`）。而 `shared.confirm_and_submit` 的消费门要求"本次授权的每一张都已外发"，与"停在第一张"逻辑互斥 ⇒ 旧写法必然等门闩超时（30s）后才点到停止，`window=3`。修法：停止用例不走消费门，改为"直接点 `#confirm-action` → 等 `arrived` 门闩 → 点 `#batch-stop` → 放行"，并断言本轮授权**恰好新增 1 条确认文档** + `window=1` + 后两张零记录 + 首张核对出结论。

### 7.5 端口 TOCTOU：`ERR_CONNECTION_REFUSED` / `gate=unavailable(Error)` 的真实成因（基础设施，非产品）

只读探针 `_working/_probe_port_race.py` 实测（Windows）：

```
free_port() 连续两次: 38321 / 38322  -> 同端口=False
A 已监听 38321，探测 = 'A'
B 绑定同端口成功；此时该端口返回 = 'A'
```

即同一端口可被**第二个服务器静默绑定成功**（SO_REUSEADDR），于是并发/交错时会出现"自己的请求被别人的服务器应答"或"无人应答"⇒ 页面 boot fetch 失败 → `setHomeControlsBlocked(true)`、`gate=unavailable(Error)`、`ERR_CONNECTION_REFUSED`。这解释了 `4_2` r1 红/r2 绿（同脚本同参数、串行、仅时间戳不同）与 `4_3`/`4_4` 本轮并发期的假红；按"flake 要刻画不要掩盖"，修法是让产品服务器**直接绑定 0 号端口**并从 `server.server_address[1]` 读回（去掉 `free_port()` 的 TOCTOU 窗口），而不是放宽任何断言。
