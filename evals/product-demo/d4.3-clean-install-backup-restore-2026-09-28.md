## 任务定义（外键）

- 依赖：D4.2。
- 交付：安装记录、工作空间备份、恢复和版本清单。
- 验收：换目录后可打开并继续；原图/候选/hash 一致。
- 约束：恢复不覆盖较新 Workspace；冲突另存副本。

## 新增工具

`tools/workspace_backup_restore.py`（仅标准库）：

- `backup --workspace <目录> --out <目录>`：文件级复制 + `manifest.json`（相对路径、sha256、字节数、mtime）+ `version.json`（代码/依赖指纹）；
- `verify --backup <目录>`：逐文件重算 sha256，报告 missing/mismatched/extra，失败 exit 1；
- `restore --backup <目录> --into <目录>`：先校验再恢复；目标已存在时**永不覆盖**，另存 `<名称>-restored-<时间戳>`；恢复后再逐文件校验。
- 运行期锁文件 `.workspace.lock` 不进备份（进程锁不是业务数据）；备份自身的 manifest/version 不会混进恢复出的工作空间。

## 演练中发现并修复的缺陷

- 现象：第一次恢复报 `missing: exports/export_*_*/manifest.json`（2 个文件），恢复被判定失败。
- 根因：恢复用 `shutil.ignore_patterns("manifest.json", "version.json", …)` 排除备份自身元数据时，把导出包里同名的业务文件一起排除了。
- 修复：`ignore` 只排除 `.workspace.lock`，复制完成后单独删除目标顶层的 `manifest.json`/`version.json`；重跑后 46 文件全部一致。失败现场保留在 `d43-drill\restore-root\workspace`（作为演练记录，不删除）。

## 局限

- 备份是文件级全量复制（非增量、非加密）；冲突判定只展示 `workspace.json.updated_at` 供人判断，工具策略是永不覆盖。
- 恢复不保留 `.workspace.lock`；正在运行的另一个进程若同时写同名工作空间，本工具不提供跨进程互斥（工作空间自身的锁机制仍生效）。
- 未演练磁盘损坏、断电中断恢复等场景。
