# D3.6 导出前方案/提示词漂移提示

> EVIDENCE-SNAPSHOT: current · NOT-AUTHORITY
> 权威定义：`docs/product-demo-goal-and-implementation-plan.md` 中 D3.6 行；本文件只记录本轮实现与证据。

## 任务定义（外键）

- 依赖：D3.4。
- 要求：操作员只改了某张图的提示词、没有更新方案文本时，导出前能看到“标题与这张图的提示词不一致”的提示并跳回方案编辑；不得静默导出不一致标题。
- 约束：不改写任何已保存记录；改方案还是改提示词由人决定（改方案会使整套 Prompt 失效，这一点必须在提示里说明）。

## 实现（本轮改动）

- `src/application_service.py::_export_selection`：导出时对每张已选图取最新提示词版本，计算 `plan_wording_warnings`：
  - `delivered_with_older_prompt`：交付候选的提示词版本落后于工作空间最新版本；
  - `manual_prompt_edit`：交付候选所用提示词为手动改写（方案文本可能已过时）。
  警告写入导出响应、`manifest.json.plan_wording_warnings` 与 README 的“注意：方案文本与提示词可能不一致”段落；不修改任何已保存记录。
- `app/product_v1/product.js`：新增 `planWordingDrift()`；点击导出先 `window.confirm` 列出漂移项，给出“确定继续导出 / 取消返回核对”两条路；导出后若响应带 `plan_wording_warnings`，状态栏补充提示。

## 局限与未覆盖

- 该机制是“提示 + 记录”，不是强制阻断：点“确定”仍会导出（任务定义允许由人决定改方案还是改提示词）。
- 只检测“交付候选 vs 最新提示词”的漂移；不检测未被选中图片的文本漂移。
- 仅覆盖“手动改写”与“版本落后”两类；提示词未改但方案文本被改的情形不在本任务范围。
