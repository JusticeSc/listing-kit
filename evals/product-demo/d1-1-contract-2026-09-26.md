| 要核对 | 值 | 来源 |

| 模型 | `qwen-image-3.0`（同系列 `-pro`）；**同时支持 T2I 与 I2I** | official_doc + 实测 |
| 区域 | 必须与模型、endpoint、API Key 同地域；本项目在用 **cn-beijing**（`dashscope.aliyuncs.com`）。文档另给业务空间专属域名作推荐迁移目标 | official_doc + 实测 |

## 3. 本项目自己的实测证据（不是文档转述）

Phase 0 的夹具设计里已经有 **4 次真实 I2I 调用**（另 3 次 T2I），请求与响应都落盘：

| 证据 | 说明 |
|---|---|
| `evals/product-demo/fixture-design/C/request.json` + `response-create.json` + `response-task.json` | T2I：创建返回 `task_status: PENDING`，查询返回 `SUCCEEDED`；`usage.input_image_count = 0` |
| `evals/product-demo/fixture-design/ref-02-upper-closeup/…` | I2I：`usage.input_image_count = 1`，`reference_sha256` 与参考图一致 |
| `evals/product-demo/fixture-design/ledger.jsonl` | 7 次可计费调用的账本（3 T2I + 4 I2I），含 task_id、seed、size、image sha |

**四条对产品设计有直接约束的读数**：

1. `usage.input_image_count` 把「模型请求确实携带参考图并非 mock」变成了**可直接核验的字段** ——
   G1 与完成审计都该用这个字段，而不是靠调用方自称。
2. 结果 URL 只有 **24 小时**：候选必须**当场下载并落盘**，不能只存 URL。
3. `task_id` 同样 24 小时：异步任务超时后**不能靠重建**来核对，只能查原 id —— 这直接决定 D1.3 的
   Unknown 处理方式。
4. `prompt_extend=false` 时**发出的提示词就是实际提示词**（实测 `rewrite_status=not_use`），
   所以「查看并版本化编辑实际发送给模型的完整提示词」不需要额外的回显接口 —— 我们自己记的就是真话。

## 4. 唯一未解项：模型下线/过期日期
