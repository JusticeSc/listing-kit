# D4.11 导出检查与交付界面证据

> EVIDENCE-SNAPSHOT: current · NOT-AUTHORITY

## 结论

D4.11 已完成。正式前端新增 S4 交付检查屏：点“检查并导出”先进入只读预检（`POST /api/exports/preflight`），显示已选图片（含命名、尺寸与模型）、缺失与硬检查摘要、一致性问题、追溯清单内容与导出位置；未选全、硬规则失败或未确认一致性时 `导出交付包` 保持禁用。导出走正式命令 `POST /api/exports`（旧 `/api/export` 仅作兼容路由，正式前端不再调用）；成功后显示导出目录并可“打开文件夹”，该动作只消费已完成的 ExportVersion。重导生成新版本，不覆盖旧包。

**一致性语义（D3.6 → D4.11）**：方案文本/提示词漂移仍按 D3.6 的定义检测（交付版本落后于当前提示词，或当前提示词为手动改写），但正式交付界面把它从“确认框提示”升级为默认阻断：预检逐项列出问题与返回位置（返回审核重新生成并采用 / 打开方案），只有操作员在交付界面显式勾选“我已知悉……仍按当前选择导出”后，服务端才接受 `acknowledge_consistency=true`，并照旧把警告写入 manifest 与 README；未勾选时服务端以 `EXPORT_CONSISTENCY_ACK_REQUIRED` 拒绝且不创建任何 ExportVersion。这样既保留“新版不如旧版时重新选择旧图”的人工决定（D4.10 验收口径），又不允许静默导出不一致标题。

## 实现结果

- 服务：新增只读 `ApplicationService.export_preflight`；`export_selection` 增加 `acknowledge_consistency` 参数，`_export_selection` 在硬检查之后增加一致性确认门（`EXPORT_CONSISTENCY_ACK_REQUIRED` 附逐项 issues）。预检返回 `blockers / missing_shots / hard_failures / consistency / manual_notes / checks / selected / platform / export_location / manifest_preview`。
- HTTP：新增 `POST /api/exports/preflight`、`POST /api/exports`、`POST /api/exports/reveal`；`POST /api/export`、`POST /api/export/reveal` 继续指向同一服务方法、同一语义。
- 前端：新增 S4 `#delivery-screen`（已选图片、缺失/硬检查摘要、一致性问题与确认、追溯清单内容、导出位置、`返回审核` / `导出交付包` / `打开文件夹`）；`#export-selection` 改为“检查并导出”并进入 S4；移除旧 `window.confirm` 漂移提示与前端直调 `/api/export`；刷新时若同一会话仍停留在交付检查则恢复 S4 并重跑预检。
- 缺陷修复：原“打开导出文件夹”按钮的请求不带 export_id，服务端必然返回 `EXPORT_NOT_FOUND`；现在按钮发送当前已完成的 export id，服务端在缺少 id 时也消费工作空间当前已完成导出投影。
