# D4.1 Windows 启动器、设置与 doctor

> EVIDENCE-SNAPSHOT: current · NOT-AUTHORITY
> 权威定义：`docs/product-demo-goal-and-implementation-plan.md` 中 D4.1 行；本文件只记录本轮实现与证据。

## 任务定义（外键）

- 依赖：G3。
- 要求：一键启动、端口/目录/key/provider 检查、清晰错误页；无开发机绝对路径；缺配置给出可执行修复。
- 约束：doctor 不修改业务文件；旧启动方式保留到发布冻结。

## 实现（本轮改动）

- `app/server.py`：新增只读 `run_doctor(host, port)` 与 `--doctor` 参数，检查项：
  1. Python ≥ 3.10（打印实际解释器路径，过低给出 uv 修复命令）；
  2. 必需项目文件齐全（server 入口、product_v1_server、product_prompt、providers.json）；
  3. Pillow / requests 可导入（缺失给出 pip/uv 修复命令）；
  4. `config/product-v1/providers.json` 可解析，且默认图片 provider（dashscope-qwen-image / qwen-image-3.0）与语义 provider（dashscope-qwen-semantic）角色/模型正确；
  5. `DASHSCOPE_API_KEY` 存在性（缺失为 warning，不阻断）；
  6. 端口占用（占用为 fail，并给出 `--port <另一个> --open` 命令）；
  7. 近期索引/数据目录可写（用临时文件探测）。
  doctor 不启动服务、不写业务文件。
- `start_product.bat`（仓库根）：先跑 doctor，通过后启动并自动打开浏览器；支持 `start_product.bat --doctor` 单独体检；失败 pause 并以 exit 2 结束；优先走 uv，其次 `.venv`，最后系统 `python`；脚本刻意保持 ASCII，避免控制台代码页乱码。

## 验证（新鲜证据，2026-09-28 23:49）

| 命令 | 结果 | 说明 |
| --- | --- | --- |
| `<temp venv>\Scripts\python.exe app\server.py --doctor` | exit 0，全部通过、0 警告 | 默认端口 8780 空闲 |
| 同上 `--doctor --port 8787` | exit 2 | 8787 被占用 → 正确报 fail 并给出 `--port 8788 --open` 修复建议 |
| `cmd /c start_product.bat --doctor` | exit 0 | 启动器走 uv 分支，体检全通过 |
