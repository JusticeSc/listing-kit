## 2. 三条守卫，逐条给出"它真的会失败"的证据

一条判据如果不会失败，就只是装饰。三条守卫的失败路径都被实际执行过：

| 守卫 | 它拦什么 | 被证明能失败的输入 | 自检项 |
|---|---|---|---|
| `G-MODE` | 正式路径只接受 `image_to_image` | `mode=text_to_image` → 拒绝（Goal 明文禁止文生图冒充参考图生成） | D3 |
| `G-IMG` | 请求体里必须真有与参考图**一一对应、顺序一致**的图像字段 | 删掉图像字段 / 两张参考图顺序颠倒 / 参考图不是 data URI → 全部拒绝 | C1、C3 |
| `G-EP` | 创建端点只取契约，且不接受 legacy 文生图端点 | 把端点换成 wanx `text2image/image-synthesis` → 拒绝 | D4 |

参数边界同样有证伪：`size` 超区间（D5）、`seed` 越界（D6）、`n=7`（D7）、
`negative_prompt` 超 500 字符（D8）、未显式允许就 `prompt_extend=true`（D9）。
其中 D8 的口径值得记一笔：契约对超长 `negative_prompt` 的行为是**截断**，
那会让"发送的"与"记录的"不相等，所以这里直接拒绝，而不是悄悄截断。

参考图数量守卫：0 张（等于纯文生图）与 4 张（超出契约 1-3）都被拒绝（D1、D2）。
契约允许的 2 张分支另有正向证据 C2/C2b：两张**像素不同**的参考图按序进入
`content[0]` 与 `content[1]`，且解码后的哈希逐张对上。

"我们的适配器能重建真的发出去过的那个请求" —— 这比任何自我声明都硬：

多张参考图时把各图哈希按序用 `|` 连接，顺序变了身份就变。

## 4. D1.3：幂等、Unknown 与核对

离线替身（`FakeTransport`）把这四条跑成可复现的判据：

| 判据 | 实测 |
|---|---|
| E1 一次提交成功并落盘原始 PNG | `SUCCEEDED`，`usage.input_image_count=1` |
| E2 同一 action 重复运行不重复 submit | 第二次返回 `SKIPPED_HAS_RESULT`，替身 `post` 次数仍为 1 |
| E3 账本一行、可按 action 检索 | 1 行；`by_action()` 命中 |
| E4 轮询超时 → UNKNOWN | 返回 `UNKNOWN`（不是失败） |
| E5 UNKNOWN 之后不自动重发 | 第二次调用返回 `UNKNOWN_PENDING_RECONCILE`，`post` 次数仍为 1 |
| E6 原 task_id 可核对 | 用 `task_id` 查询拿到真实终态 `SUCCEEDED` |
| E7 未收尾动作可被列出 | `unresolved()` 不含静默丢弃 |
| E8 无 key → 拒绝且不产 mock | 抛 `ProviderGuardError`，不写 intent |
| E9 拒绝没有副作用 | attempt 目录为空、账本为空、没有占位图 |

**两处口径是本轮明确改定的**（都是自检先红、再改实现）：

1. **账本一行 vs 两行。** 第一版在"提交成功"和"收尾"各写一行，E3 立刻报红 ——
   一次付费动作两行会让成本核对重复计数。现在只在收尾写一行；在途动作由
   `intent.json` 表达；HTTP 非 200（服务没接受，不是付费动作）不进账本。
2. **`api_key=""` 不得回落环境变量。** 第一版 `api_key or os.getenv(...)` 让
   "我明确没给 key"被环境变量悄悄满足，E8 判据成了假话。现在只有 `api_key=None`
   才读环境变量。

## 5. 与 legacy 的边界

- 本模块**没有 mock 分支**：无 key 直接拒绝，不产占位图（Goal 禁止 mock 冒充参考图生成）；
- 不 import `src/imagegen.py`，因此 v2 的变化不会把新路径的行为改掉；
- legacy 的文生图端点在本模块里是一个**被断言的常量**，出现在正式路径即拒绝；
- legacy 的 T2I 单元能力保留但只用于历史回归，不进入新产品正式路径。
