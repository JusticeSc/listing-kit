- `config/product-v1/providers.json` 将 `dashscope-qwen-semantic` 配为默认语义 Provider，模型为 `qwen3.7-plus`；`src/providers/dashscope_semantic.py` 从环境读取 `DASHSCOPE_API_KEY`，默认使用百炼 OpenAI-compatible Chat Completions，文本提案使用 strict JSON Schema，并在本地再次验证 draft。
- 新鲜离线合同测试：`uv run --no-project --with-requirements requirements.txt python tools/verify_semantic_provider.py`，10/10 通过，覆盖默认配置、缺少凭据阻止且不回退 Fake、地区端点校验、严格结构化输出、本地 draft 校验、哈希门禁与脱敏错误。
- 一次真实调用：默认 Provider 执行 `propose_prompt_blocks`，仅输入通用合成资料（不含真实商品/客户资料）；百炼返回后，本地 schema 校验通过。记录为 `model=qwen3.7-plus`、`schema_mode=json_schema`、`block_count=5`、`request_id=66160b88-0214-9bae-b076-7fb9bb529de2`、`usage=2413 tokens`。未写入工作空间。

## 结论边界

以上只证明当前凭据与端点可连通、默认模型接受所用结构化请求、响应符合本地草案结构。它不证明商品理解、提示词或图片的业务质量，也不是质量基准或用户验收。Provider 适配器本身不依赖 WorkspaceStore；应用层后续如何编译、审阅和持久化草案，仍由 D1.2 及后续任务验证。
