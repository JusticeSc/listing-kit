## 0. 一句话

把「拿到商品资料 → 得到一套可交付的图」编译成一条阶段式工作台：任何时刻只有一个当前阶段的主视图；系统先理解商品、再推荐方案、再执行生成；运营只做三件事——补资料、改方向、看图做决定；其余走系统默认。

## 1. 失败基线（v1.22 E1–E5）与本版对策

| 编号 | 上一版失败模式 | 本版对策 | 原型里的可见证据 |
|---|---|---|---|
| E1 | 固定三栏，未来阶段以大片空态出现 | 阶段式单主视图；已完成阶段折叠为一行摘要，未来阶段只有灰色标签；主区只渲染当前阶段 | 从空白表单新建开始，全程只有一个阶段占主区 |
| E2 | 普通路径常驻 F1–F8，运营被要求打表 | 无异常只给一行「未发现阻塞」；异常才出现摘要；检查详情放在高级区，不到达运营 | 审核页右侧只有检查摘要 + 采用/重做两个动作 |
| E3 | 「推荐方案」不使用输入，直接映射固定定义 | 方案由类目 playbook + 商品资料 + 平台规则编译；Aster 01 得到 3 张、Bex 02 得到 2 张 | 两份示例商品得到不同张数、不同用途、不同提示词 |
| E4 | Prompt 是商品常量，换商品仍得保温杯语义 | 提示词按「事实锁 + 卖点 + 平台 + 全组视觉 + 本张方向」编译；换商品即换商品段 | 提示词按 5 个块展开，可编辑、有版本、可恢复推荐 |
| E5 | 自审只有正向覆盖 | 设计层给出反向探针清单（§10），原型里各留可跑红位置 | 固定张数、常驻表、Aster 泄漏都有对应探针 |

## 2. 业务对象（用户能理解的七个）

| 对象 | 谁产生 | 用户可读 | 用户可写 | 状态 | 不变量 |
|---|---|---|---|---|---|
| 商品资料 ProductInput | 用户 | 参考图（含角色）、名称、类目、平台、卖点、可选视觉偏好 | 全部 | 缺料 / 齐套 | 卖点只是「用户声明」，不自动升级为商品事实 |
| 商品理解 ProductBrief | 系统，用户修正 | 身份事实、颜色分色、表面规则、Unknown、可变化范围、平台约束、来源 | 修正字段、补 Unknown | 待确认 / 已确认 / 已修正 | 事实与 Unknown 分列；每项带来源 |
| 套图方案 PlanDraft | 系统，用户调整 | 张数、每张用途/画面方向/参考图/推荐理由、全组视觉 | 调整单张、调整全组视觉、增删张 | 草案 / 已确认 | 张数由类目 playbook 决定，不是固定 4/7 张 |
| 提示词 PromptPreview | 系统编译，用户可覆盖 | 5 个块（商品锁定/空白表面/形状否定/场景/构图）+ 负向提示词 + 版本 | 编辑任意块、恢复推荐 | v1 / v2 … | 商品锁定只由事实锁生成，不允许卖点改写 |
| 生成批次 BatchRun | 系统 | 每张离散状态、失败原因、Unknown、已就绪可提前打开 | 重试单张、查证 Unknown | 排队 / 生成中 / 就绪 / 失败 / 未知 | 单张失败不污染其他张；无假百分比 |
| 候选与选择 CandidateReview | 系统 + 用户 | 每张候选、来源、版本、历史候选 | 采用、切换候选、比较 | 待审核 / 已采用 / 需更新 | 旧候选不删除；一次只动一张 |
| 返工请求 ReworkRequest | 用户 | 原因、补充说明、将改变/保持什么 | 选原因、写补充 | 待提交 / 执行中 / 已产出 | 只新增目标张候选，其他张版本不变 |
| 交付预览 ExportPreview | 系统 | 已选套图、缺失项、文件清单 | 导出（演示为清单预览） | 未就绪 / 可导出 / 已导出预览 | 未满足条件不给假成功 |

## 3. 阶段与屏幕（Screen Map）

| 阶段 | 主视图 | 主动作 | 后置/隐藏 |
|---|---|---|---|
| S0 资料接入 INTAKE | 居中的商品资料表单（参考图网格 + 基本信息 + 卖点 + 可选视觉偏好） | 分析商品资料 | 方案、候选、返工、交付、任何检查矩阵 |
| S1 商品理解 BRIEF | 理解摘要（事实/颜色/表面规则/Unknown/可变化范围/平台约束，逐项带来源） | 确认，生成套图方案 | 模型参数、内部 Attempt、完整检查矩阵 |
| S2 套图方案 PLAN | 全组视觉条 + Shot 卡片（用途/方向/参考图/理由/默认提示词） | 一键生成套图 | 空候选区、逐张强制写提示词 |
| S3 生成中 GENERATING | 逐图离散状态网格，已就绪可提前打开 | 查看已完成 | 假百分比、全页锁死 |
| S4 审核与定向返工 REVIEW | 缩略条 + 当前大图 + 候选 + 操作区；提示词在高级区 | 采用这张 / 重做这张 | 常驻 F1–F8、与本张无关的控制 |
| S5 交付 DELIVERY | 已选套图 + 缺失项 + 文件清单预览 | 导出套图 | 未满足条件的假成功 |

阶段推进规则：已完成阶段在阶段条上折叠为一行摘要（可展开回看）；未到达阶段只显示灰色标签，不占版面；REVIEW 内才出现单图导航、候选与上下文操作。


## 4. 逐屏设计（视图 → 按钮 → 状态规则 → 布局）

### 4.1 S0 资料接入

视图构成与理由：

| 视图块 | 为什么需要 |
|---|---|
| 商品参考图（含角色标注：正面全身 / 杯口细节 / 下部细节） | 它是事实锁、Shot 参考图和提示词商品段的唯一证据来源；角色决定每张图能参考什么 |
| 基本信息（名称 / 类目 / 平台） | 决定类目 playbook 与平台硬约束（Amazon US 主图：纯白底、无文字、无道具、1:1） |
| 卖点列表 | 用户声明，不自动升级为商品事实；系统标注每条卖点准备在哪张图表达 |
| 视觉偏好（可选，默认折叠） | 只形成 StyleBrief（全组共享），不改变商品身份 |
| 资料检查行 | 把「能不能进流程」读给用户：缺什么、有没有冲突 |
| 加载示例商品 | 让任何人随时得到一套齐套输入；只是快捷输入，不是另一条产品路径 |

按钮：

| 按钮 | 为什么需要 | 前置 | 结果 | 失败 / 边界 |
|---|---|---|---|---|
| 添加图片 | 建立商品身份证据 | 未开始生成 | 新参考图入列，要求标注角色 | 未标角色 → 行内提示，不阻断保存 |
| 替换 / 移除 | 资料纠错 | 未开始生成 | 事实锁、引用该图的 Shot 与提示词重算 | 提示会影响到哪些对象 |
| 加载示例商品 | 走查起点 | 初始或重建任务 | 固定夹具填入同一表单 | 虚构商品，表单里明示 |
| 分析商品资料（本阶段唯一主动作） | 把原始资料变成可检查的理解 | 名称 + 至少 1 张参考图 + 至少 1 条卖点 + 平台 | 进入 S1 商品理解 | 缺料 → 按钮禁用并点名缺什么，停在原地 |

状态与规则：空白态 = 全空表单 + 禁用主动作 + 「还差：名称、参考图、卖点」；卖点与图不一致不在这里拦截，交给理解页标出。

布局：居中单列（约 880px）。图片网格一行 3+1（添加位）；基本信息一行两项；卖点行式列表（可增删）；底部动作条常驻，右侧主动作。

### 4.2 S1 商品理解

视图：六个区块——① 商品身份（形状与比例）② 颜色与分色 ③ 表面规则（无文字/标识）④ Unknown（材质/容量/保温性能）⑤ 可变化范围（场景/光线/构图/背景/镜头）⑥ 平台约束。每块带来源标记（参考图 / 事实卡 / 平台规则 / 用户输入）。Unknown 单独成块、可补。

按钮：修正理解（切换可编辑）、补充 Unknown（逐字段）、确认，生成套图方案（主动作）、返回资料。

规则：用户只修正重要错误与 Unknown；确认前不改方案；本页不出现检查矩阵与内部对象。

布局：主列 720px 文本卡 + 右侧窄栏（Unknown 与平台约束）；底部动作条。

### 4.3 S2 套图方案

视图：顶部「全组视觉」条（光线 / 色调 / 氛围 / 道具密度 + 来源标记：系统默认或用户已改）；Shot 卡片若干——序号、用途、画面方向、参考图、推荐理由、「默认提示词」折叠（5 个块 + 负向）；末尾「+ 添加一张」。

按钮：

| 按钮 | 为什么需要 | 前置 | 结果 | 失败 / 边界 |
|---|---|---|---|---|
| 调整全组视觉 | 视觉方向是全组共享的，改动要可见 | 任意 | 重编译全部 Shot 的场景/构图段 | 已生成过 → 相关张标记「待更新」 |
| 调整此张（用途/方向/参考图） | 单张定向调整 | 任意 | 只重编译该张 | 只影响该张 |
| 查看默认提示词 | 让用户能看见系统编译了什么 | 任意 | 展开 5 块提示词（只读预览） | 编辑入口在审核页高级区 |
| 添加一张 / 删除此张 | 补齐或收紧套图 | 任意 | 张数变化，理由同步更新 | 低于 1 张不允许 |
| 一键生成套图 / 更新 N 张待更新 | 整组执行，不要七次手点；重跑只覆盖尚未就绪或已标记待更新的张 | 方案已确认 | 进入 S3，逐图离散状态 | 已就绪且未标记的张不会重跑 |
| 返回修正理解 | 上游纠错 | 任意 | 回 S1 | 改回后需重新确认 |

规则：张数由类目 playbook 决定（本示例 Aster 01 = 3 张，Bex 02 = 2 张），不是固定四张/七张；不要求逐张写提示词才能开始。

布局：全组视觉条通栏；Shot 卡片两列；卡片底部操作行；页脚动作条。

### 4.4 S3 生成中

视图：逐图网格。每格 = 用途 + 状态（排队中 / 生成中 / 已就绪 / 失败 / 结果未知）+ 已就绪缩略图（可提前打开）。顶部一行「已完成 x/N」；不使用假百分比。

按钮：查看（已就绪 → 打开预览）、重试此张（失败，显示原因）、查证（结果未知 → 先查证再决定重试或收下）、先审核已完成（部分失败时）。

规则：单张失败不锁全页；其余结果保留；Unknown 必须先查证，不允许直接重试。

### 4.5 S4 审核与定向返工

视图三区：

| 区 | 内容 | 为什么 |
|---|---|---|
| 左：套图缩略条 | 每张用途 + 状态（待审核 / 已采用 / 需更新） | 一眼看整套进度，点击切图 |
| 中：当前大图 + 候选缩略 + 元数据行 | 当前候选大图；候选缩略（候选 1/2/…）；元数据：来源、日期、提示词版本 | 决策对象是「这张的候选」，不是抽象指标 |
| 右：操作区 | 检查摘要（无异常 = 一行）/ 采用这张 / 重做这张 / 完整提示词（高级区） | 无异常不要求重复确认；高级区承载 5 块提示词、版本、保存与恢复 |

按钮：采用这张、切换候选、并排比较（有旧候选时）、重做这张、保存提示词新版本、恢复推荐提示词、导出套图（全部采用后可点）、返回方案。

规则：无候选的图不显示返工表单；提示词改动只让本张候选标记「需重新生成」；旧候选不删除。

### 4.6 返工对话框（只动目标图）

视图：当前图缩略 + 原因单选（6 项封闭集：商品走形或变色 / 背景或场景不合适 / 光线或色调不合适 / 构图或裁切 / 文字或水印问题 / 其他）+ 补充说明 + 修正句预览（显示「将追加到哪个提示词块」）+ 影响说明（只重新生成这张；旧候选保留；其他张不动）。

按钮：开始重做（主动作，需先选原因）、取消。

规则：原因必选；提交后该图在审核页内进入生成中，产出新候选并标记「新」与版本；其他张版本不变。离线演示缺少对应素材时，新候选席位显示「模拟返工候选」占位卡，不伪造图片。

### 4.7 S5 交付

视图：已选套图网格（每张标所用候选版本）+ 缺失项（全部采用时为空）+ 文件清单预览（01-main、02-lifestyle、03-detail、manifest.json）。

按钮：导出套图（生成清单预览，并明确「离线演示：未写文件」）、返回审核、开始新任务。

规则：未全部采用不可导出；不把清单预览说成已写文件。


## 5. 因果与失效传播（改什么 → 影响什么）

| 用户改动 | 系统重编译 | 已生成结果怎么办 | 界面表现 |
|---|---|---|---|
| 改一条卖点 | 引用该卖点的 Shot 的场景/文案方向 | 只有该 Shot 标记「需更新」 | 该卡片出现「需更新」徽标与「按新方向更新此张」 |
| 换/移除一张参考图 | 事实锁重算 → 引用该图的 Shot 商品段 | 受影响 Shot 标记「需更新」 | 变更说明列出生效范围 |
| 改全组视觉 | 全部 Shot 的场景/构图段 | 全部已生成 Shot 标记「待更新」（已采用保留） | 顶部提示「全组视觉已更新：N 张待更新」 |
| 改单张提示词 | 仅该张提示词新版本 v2 | 该张旧候选保留，标记可比较 | 「提示词 v2」+「旧候选可比较」 |
| 提交返工 | 按原因追加修正句 → 仅该张新版本 | 只新增该张候选；其他张版本不变 | 新候选带「新」标记；其他缩略条无变化 |
| 未支持的输入 | 只做输入校验 | 不套用任何已有商品的事实或候选 | 明示「该商品暂无演示候选」，停在原地 |

## 6. 通用机制落在哪里（三个参考包对照）

| 机制层 | 出处（参考包） | 本设计的落点 | 换商品零改代码的判据 |
|---|---|---|---|
| 执行控制：幂等 / 重试 / Unknown / 不覆盖 / 预算 / dry-run | ecommerce-skills 的 gen.mjs、run_loop.mjs；ecom-details-image 的异步轮询 | S3 离散状态、失败重试、Unknown 先查证、旧候选不删除、导出前清单预览 | 重试与查证逻辑不含商品语义 |
| 中间表示 | ecommerce-image-suite 的结构化商品 JSON；ecom-details-image 的 brief | ProductBrief（身份/颜色/表面/Unknown/可变化范围/平台/来源） | 界面只读 Brief；换商品只换卡 |
| 编译器 | ecommerce-image-suite 引擎编译每张提示词；ecom-details-image 模板 + variants | PromptPreview：事实锁 + 卖点 + 平台 + 全组视觉 + 本张方向 → 5 块 + 负向；用户改动=覆盖，可恢复 | 编译函数零商品常量 |
| 注册表 | ecommerce-skills 的 tasks.json；ecom-details-image 的 25 场景模板 | 类目 playbook / 场景库 / 返工修正句库 / 平台规则，全部数据化 | 新类目只加数据，不改页面 |
| 责任路由 | ecommerce-skills detect-task 的风险等级与修正句 | 返工原因（封闭集）→ 修正句 → 只动目标图 | 原因→修正句是查表，不写死在按钮里 |
| 证据绑定 | run_loop manifest；check_listing 机检 | 候选带来源/版本/日期；导出带清单 | 来源字段由夹具声明，不由页面硬编码 |

## 7. 视觉与交互规范

- 色彩：底色 #F6F7F9；卡片 #FFFFFF；正文 #101828、次级 #475467；边线 #E4E7EC；主色 #2457D6；成功 #18794E；提醒 #B54708；危险 #B42318；信息 #6941C6。
- 字号：12 / 13 / 14 / 16 / 20 / 24；行高 1.5；仅系统字体，不引入第三方字体。
- 间距：4 的倍数；卡片圆角 12px；阴影只用于对话框与浮层。
- 图片：套图统一 1:1；大图 contain；缩略 72–96px；生成中的格子显示离散状态而不是百分比。
- 状态不只靠颜色：所有状态徽标带文字。
- 动效：120–180ms；遵守 prefers-reduced-motion。
- 响应式：≥1024px 三区；640–1024px 两区；<640px 单列、缩略条横滑；390px 无横向溢出；200% 缩放可完成任务。
- 可访问性：原生 button / input / select / dialog / details；label 可见；focus-visible 明显；通知集中在 live region；图片替代文本带业务含义；不使用 div 按钮、正 tabindex、只靠颜色的状态或自动轮播。

## 8. Mock 边界与演示控制

模拟什么：模型执行、等待时间、费用、写盘。
不模拟什么：商品理解、方案推荐、提示词编译、返工影响——这四项由同一份通用编译器按输入推导；Aster 01 与 Bex 02 得到的理解、张数、用途与提示词互不相同，就是这项的可见证据。

演示控制条放在产品界面之外的独立深色条（页面顶部），只提供：情形注入（正常 / 局部失败 / 结果未知）与复位。业务界面内不出现场景开关、重置按钮或测试入口。
