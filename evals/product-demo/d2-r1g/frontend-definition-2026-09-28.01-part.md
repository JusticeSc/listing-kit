## 0. 一句话

把「拿到商品资料 → 得到一套可交付的图」编译成一条阶段式工作台：任何时刻只有一个当前阶段的主视图；系统先理解商品、再推荐方案、再执行生成；运营只做三件事——补资料、改方向、看图做决定；其余走系统默认。

## 1. 失败基线（v1.22 E1–E5）与本版对策

| 编号 | 上一版失败模式 | 本版对策 | 原型里的可见证据 |
|---|---|---|---|
| E1 | 固定三栏，未来阶段以大片空态出现 | 阶段式单主视图；已完成阶段折叠为一行摘要，未来阶段只有灰色标签；主区只渲染当前阶段 | 从空白表单新建开始，全程只有一个阶段占主区 |
| E2 | 普通路径常驻 F1–F8，运营被要求打表 | 无异常只给一行「未发现阻塞」；异常才出现摘要；检查详情放在高级区，不到达运营 | 审核页右侧只有检查摘要 + 采用/重做两个动作 |
| E3 | 「推荐方案」不使用输入，直接映射固定定义 | 方案由类目 playbook + 商品资料 + 平台规则编译；Aster 01 得到 3 张、Bex 02 得到 2 张 | 两份示例商品得到不同张数、不同用途、不同提示词 |
| E4 | Prompt 是商品常量，换商品仍得保温杯语义 | 提示词按「事实锁 + 卖点 + 平台 + 全组视觉 + 本张方向」编译；换商品即换商品段 | 提示词按 5 个块展开，可编辑、有版本、可恢复推荐 |
| E5 | 自审只有正向覆盖 | 设计层给出反向探针清单（§10），原型里各留可跑红位置 | 固定张数、常驻表、Aster 泄漏都有对应探针 |

## 2. 业务对象（用户能理解的七个）

| 对象 | 谁产生 | 用户可读 | 用户可写 | 状态 | 不变量 |
|---|---|---|---|---|---|
| 商品资料 ProductInput | 用户 | 参考图（含角色）、名称、类目、平台、卖点、可选视觉偏好 | 全部 | 缺料 / 齐套 | 卖点只是「用户声明」，不自动升级为商品事实 |
| 商品理解 ProductBrief | 系统，用户修正 | 身份事实、颜色分色、表面规则、Unknown、可变化范围、平台约束、来源 | 修正字段、补 Unknown | 待确认 / 已确认 / 已修正 | 事实与 Unknown 分列；每项带来源 |
| 套图方案 PlanDraft | 系统，用户调整 | 张数、每张用途/画面方向/参考图/推荐理由、全组视觉 | 调整单张、调整全组视觉、增删张 | 草案 / 已确认 | 张数由类目 playbook 决定，不是固定 4/7 张 |
| 提示词 PromptPreview | 系统编译，用户可覆盖 | 5 个块（商品锁定/空白表面/形状否定/场景/构图）+ 负向提示词 + 版本 | 编辑任意块、恢复推荐 | v1 / v2 … | 商品锁定只由事实锁生成，不允许卖点改写 |
| 生成批次 BatchRun | 系统 | 每张离散状态、失败原因、Unknown、已就绪可提前打开 | 重试单张、查证 Unknown | 排队 / 生成中 / 就绪 / 失败 / 未知 | 单张失败不污染其他张；无假百分比 |
| 候选与选择 CandidateReview | 系统 + 用户 | 每张候选、来源、版本、历史候选 | 采用、切换候选、比较 | 待审核 / 已采用 / 需更新 | 旧候选不删除；一次只动一张 |
| 返工请求 ReworkRequest | 用户 | 原因、补充说明、将改变/保持什么 | 选原因、写补充 | 待提交 / 执行中 / 已产出 | 只新增目标张候选，其他张版本不变 |
| 交付预览 ExportPreview | 系统 | 已选套图、缺失项、文件清单 | 导出（演示为清单预览） | 未就绪 / 可导出 / 已导出预览 | 未满足条件不给假成功 |

## 3. 阶段与屏幕（Screen Map）

| 阶段 | 主视图 | 主动作 | 后置/隐藏 |
|---|---|---|---|
| S0 资料接入 INTAKE | 居中的商品资料表单（参考图网格 + 基本信息 + 卖点 + 可选视觉偏好） | 分析商品资料 | 方案、候选、返工、交付、任何检查矩阵 |
| S1 商品理解 BRIEF | 理解摘要（事实/颜色/表面规则/Unknown/可变化范围/平台约束，逐项带来源） | 确认，生成套图方案 | 模型参数、内部 Attempt、完整检查矩阵 |
| S2 套图方案 PLAN | 全组视觉条 + Shot 卡片（用途/方向/参考图/理由/默认提示词） | 一键生成套图 | 空候选区、逐张强制写提示词 |
| S3 生成中 GENERATING | 逐图离散状态网格，已就绪可提前打开 | 查看已完成 | 假百分比、全页锁死 |
| S4 审核与定向返工 REVIEW | 缩略条 + 当前大图 + 候选 + 操作区；提示词在高级区 | 采用这张 / 重做这张 | 常驻 F1–F8、与本张无关的控制 |
| S5 交付 DELIVERY | 已选套图 + 缺失项 + 文件清单预览 | 导出套图 | 未满足条件的假成功 |

阶段推进规则：已完成阶段在阶段条上折叠为一行摘要（可展开回看）；未到达阶段只显示灰色标签，不占版面；REVIEW 内才出现单图导航、候选与上下文操作。


## 4. 逐屏设计（视图 → 按钮 → 状态规则 → 布局）

### 4.1 S0 资料接入

视图构成与理由：

| 视图块 | 为什么需要 |
|---|---|
| 商品参考图（含角色标注：正面全身 / 杯口细节 / 下部细节） | 它是事实锁、Shot 参考图和提示词商品段的唯一证据来源；角色决定每张图能参考什么 |
| 基本信息（名称 / 类目 / 平台） | 决定类目 playbook 与平台硬约束（Amazon US 主图：纯白底、无文字、无道具、1:1） |
| 卖点列表 | 用户声明，不自动升级为商品事实；系统标注每条卖点准备在哪张图表达 |
| 视觉偏好（可选，默认折叠） | 只形成 StyleBrief（全组共享），不改变商品身份 |
| 资料检查行 | 把「能不能进流程」读给用户：缺什么、有没有冲突 |
| 加载示例商品 | 让任何人随时得到一套齐套输入；只是快捷输入，不是另一条产品路径 |

按钮：

| 按钮 | 为什么需要 | 前置 | 结果 | 失败 / 边界 |
|---|---|---|---|---|
| 添加图片 | 建立商品身份证据 | 未开始生成 | 新参考图入列，要求标注角色 | 未标角色 → 行内提示，不阻断保存 |
| 替换 / 移除 | 资料纠错 | 未开始生成 | 事实锁、引用该图的 Shot 与提示词重算 | 提示会影响到哪些对象 |
| 加载示例商品 | 走查起点 | 初始或重建任务 | 固定夹具填入同一表单 | 虚构商品，表单里明示 |
| 分析商品资料（本阶段唯一主动作） | 把原始资料变成可检查的理解 | 名称 + 至少 1 张参考图 + 至少 1 条卖点 + 平台 | 进入 S1 商品理解 | 缺料 → 按钮禁用并点名缺什么，停在原地 |

状态与规则：空白态 = 全空表单 + 禁用主动作 + 「还差：名称、参考图、卖点」；卖点与图不一致不在这里拦截，交给理解页标出。

布局：居中单列（约 880px）。图片网格一行 3+1（添加位）；基本信息一行两项；卖点行式列表（可增删）；底部动作条常驻，右侧主动作。

### 4.2 S1 商品理解

视图：六个区块——① 商品身份（形状与比例）② 颜色与分色 ③ 表面规则（无文字/标识）④ Unknown（材质/容量/保温性能）⑤ 可变化范围（场景/光线/构图/背景/镜头）⑥ 平台约束。每块带来源标记（参考图 / 事实卡 / 平台规则 / 用户输入）。Unknown 单独成块、可补。

按钮：修正理解（切换可编辑）、补充 Unknown（逐字段）、确认，生成套图方案（主动作）、返回资料。

规则：用户只修正重要错误与 Unknown；确认前不改方案；本页不出现检查矩阵与内部对象。

布局：主列 720px 文本卡 + 右侧窄栏（Unknown 与平台约束）；底部动作条。
