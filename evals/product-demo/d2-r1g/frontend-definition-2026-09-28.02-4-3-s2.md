# 4.3 S2 套图方案
[返回 frontend-definition-2026-09-28.md](frontend-definition-2026-09-28.md)

### 4.3 S2 套图方案

视图：顶部「全组视觉」条（光线 / 色调 / 氛围 / 道具密度 + 来源标记：系统默认或用户已改）；Shot 卡片若干——序号、用途、画面方向、参考图、推荐理由、「默认提示词」折叠（5 个块 + 负向）；末尾「+ 添加一张」。

按钮：

| 按钮 | 为什么需要 | 前置 | 结果 | 失败 / 边界 |
|---|---|---|---|---|
| 调整全组视觉 | 视觉方向是全组共享的，改动要可见 | 任意 | 重编译全部 Shot 的场景/构图段 | 已生成过 → 相关张标记「待更新」 |
| 调整此张（用途/方向/参考图） | 单张定向调整 | 任意 | 只重编译该张 | 只影响该张 |
| 查看默认提示词 | 让用户能看见系统编译了什么 | 任意 | 展开 5 块提示词（只读预览） | 编辑入口在审核页高级区 |
| 添加一张 / 删除此张 | 补齐或收紧套图 | 任意 | 张数变化，理由同步更新 | 低于 1 张不允许 |
| 一键生成套图 / 更新 N 张待更新 | 整组执行，不要七次手点；重跑只覆盖尚未就绪或已标记待更新的张 | 方案已确认 | 进入 S3，逐图离散状态 | 已就绪且未标记的张不会重跑 |
| 返回修正理解 | 上游纠错 | 任意 | 回 S1 | 改回后需重新确认 |

规则：张数由类目 playbook 决定（本示例 Aster 01 = 3 张，Bex 02 = 2 张），不是固定四张/七张；不要求逐张写提示词才能开始。

布局：全组视觉条通栏；Shot 卡片两列；卡片底部操作行；页脚动作条。

### 4.4 S3 生成中

视图：逐图网格。每格 = 用途 + 状态（排队中 / 生成中 / 已就绪 / 失败 / 结果未知）+ 已就绪缩略图（可提前打开）。顶部一行「已完成 x/N」；不使用假百分比。

按钮：查看（已就绪 → 打开预览）、重试此张（失败，显示原因）、查证（结果未知 → 先查证再决定重试或收下）、先审核已完成（部分失败时）。

规则：单张失败不锁全页；其余结果保留；Unknown 必须先查证，不允许直接重试。

### 4.5 S4 审核与定向返工

视图三区：

| 区 | 内容 | 为什么 |
|---|---|---|
| 左：套图缩略条 | 每张用途 + 状态（待审核 / 已采用 / 需更新） | 一眼看整套进度，点击切图 |
| 中：当前大图 + 候选缩略 + 元数据行 | 当前候选大图；候选缩略（候选 1/2/…）；元数据：来源、日期、提示词版本 | 决策对象是「这张的候选」，不是抽象指标 |
| 右：操作区 | 检查摘要（无异常 = 一行）/ 采用这张 / 重做这张 / 完整提示词（高级区） | 无异常不要求重复确认；高级区承载 5 块提示词、版本、保存与恢复 |

按钮：采用这张、切换候选、并排比较（有旧候选时）、重做这张、保存提示词新版本、恢复推荐提示词、导出套图（全部采用后可点）、返回方案。

规则：无候选的图不显示返工表单；提示词改动只让本张候选标记「需重新生成」；旧候选不删除。

### 4.6 返工对话框（只动目标图）

视图：当前图缩略 + 原因单选（6 项封闭集：商品走形或变色 / 背景或场景不合适 / 光线或色调不合适 / 构图或裁切 / 文字或水印问题 / 其他）+ 补充说明 + 修正句预览（显示「将追加到哪个提示词块」）+ 影响说明（只重新生成这张；旧候选保留；其他张不动）。

按钮：开始重做（主动作，需先选原因）、取消。

规则：原因必选；提交后该图在审核页内进入生成中，产出新候选并标记「新」与版本；其他张版本不变。离线演示缺少对应素材时，新候选席位显示「模拟返工候选」占位卡，不伪造图片。

### 4.7 S5 交付

视图：已选套图网格（每张标所用候选版本）+ 缺失项（全部采用时为空）+ 文件清单预览（01-main、02-lifestyle、03-detail、manifest.json）。

按钮：导出套图（生成清单预览，并明确「离线演示：未写文件」）、返回审核、开始新任务。

规则：未全部采用不可导出；不把清单预览说成已写文件。


## 5. 因果与失效传播（改什么 → 影响什么）

| 用户改动 | 系统重编译 | 已生成结果怎么办 | 界面表现 |
|---|---|---|---|
| 改一条卖点 | 引用该卖点的 Shot 的场景/文案方向 | 只有该 Shot 标记「需更新」 | 该卡片出现「需更新」徽标与「按新方向更新此张」 |
| 换/移除一张参考图 | 事实锁重算 → 引用该图的 Shot 商品段 | 受影响 Shot 标记「需更新」 | 变更说明列出生效范围 |
| 改全组视觉 | 全部 Shot 的场景/构图段 | 全部已生成 Shot 标记「待更新」（已采用保留） | 顶部提示「全组视觉已更新：N 张待更新」 |
| 改单张提示词 | 仅该张提示词新版本 v2 | 该张旧候选保留，标记可比较 | 「提示词 v2」+「旧候选可比较」 |
| 提交返工 | 按原因追加修正句 → 仅该张新版本 | 只新增该张候选；其他张版本不变 | 新候选带「新」标记；其他缩略条无变化 |
| 未支持的输入 | 只做输入校验 | 不套用任何已有商品的事实或候选 | 明示「该商品暂无演示候选」，停在原地 |

## 6. 通用机制落在哪里（三个参考包对照）

| 机制层 | 出处（参考包） | 本设计的落点 | 换商品零改代码的判据 |
|---|---|---|---|
| 执行控制：幂等 / 重试 / Unknown / 不覆盖 / 预算 / dry-run | ecommerce-skills 的 gen.mjs、run_loop.mjs；ecom-details-image 的异步轮询 | S3 离散状态、失败重试、Unknown 先查证、旧候选不删除、导出前清单预览 | 重试与查证逻辑不含商品语义 |
| 中间表示 | ecommerce-image-suite 的结构化商品 JSON；ecom-details-image 的 brief | ProductBrief（身份/颜色/表面/Unknown/可变化范围/平台/来源） | 界面只读 Brief；换商品只换卡 |
| 编译器 | ecommerce-image-suite 引擎编译每张提示词；ecom-details-image 模板 + variants | PromptPreview：事实锁 + 卖点 + 平台 + 全组视觉 + 本张方向 → 5 块 + 负向；用户改动=覆盖，可恢复 | 编译函数零商品常量 |
| 注册表 | ecommerce-skills 的 tasks.json；ecom-details-image 的 25 场景模板 | 类目 playbook / 场景库 / 返工修正句库 / 平台规则，全部数据化 | 新类目只加数据，不改页面 |
| 责任路由 | ecommerce-skills detect-task 的风险等级与修正句 | 返工原因（封闭集）→ 修正句 → 只动目标图 | 原因→修正句是查表，不写死在按钮里 |
| 证据绑定 | run_loop manifest；check_listing 机检 | 候选带来源/版本/日期；导出带清单 | 来源字段由夹具声明，不由页面硬编码 |

## 7. 视觉与交互规范

- 色彩：底色 #F6F7F9；卡片 #FFFFFF；正文 #101828、次级 #475467；边线 #E4E7EC；主色 #2457D6；成功 #18794E；提醒 #B54708；危险 #B42318；信息 #6941C6。
- 字号：12 / 13 / 14 / 16 / 20 / 24；行高 1.5；仅系统字体，不引入第三方字体。
- 间距：4 的倍数；卡片圆角 12px；阴影只用于对话框与浮层。
- 图片：套图统一 1:1；大图 contain；缩略 72–96px；生成中的格子显示离散状态而不是百分比。
- 状态不只靠颜色：所有状态徽标带文字。
- 动效：120–180ms；遵守 prefers-reduced-motion。
- 响应式：≥1024px 三区；640–1024px 两区；<640px 单列、缩略条横滑；390px 无横向溢出；200% 缩放可完成任务。
- 可访问性：原生 button / input / select / dialog / details；label 可见；focus-visible 明显；通知集中在 live region；图片替代文本带业务含义；不使用 div 按钮、正 tabindex、只靠颜色的状态或自动轮播。
