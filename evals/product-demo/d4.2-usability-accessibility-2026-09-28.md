## 发现并修复的缺陷：未附图时“保存商品资料”静默无响应

- 现象：资料页填入商品名称、不选图，点“保存商品资料”——没有请求、没有错误文字、界面毫无变化（浏览器把焦点移到不可见的 file input，验证气泡无法显示）。
- 根因：`#reference-images` 用 `setCustomValidity()` 表达“至少 1 张参考图”，而表单未关闭原生校验；浏览器在 submit 事件之前就拦截提交，`saveIntake()` 里的错误提示分支（`updateImageChoice({revealError:true})`）永远不会执行。
- 修复：`app/product_v1/index.html` 的表单加 `novalidate`，提交始终进入 JS 校验路径；JS 仍用 `form.reportValidity()` 决定是否发请求，并显示 `role=alert` 的错误文字。修复后同一操作给出“请先选择至少 1 张商品参考图。”，输入框带 `aria-invalid=true`。
- 复核：当前脚本的 `blank.error_association` 检查通过；`tools/verify_product_v1_ui.py`、`tools/verify_product_v1_ui_rework.py`、`tools/verify_product_v1_ui_shot_retry.py` 在修复后复跑全部通过。

## 局限与未覆盖

- 200% 缩放用等价 CSS 视口模拟（1440x1000 → 720x500）：能覆盖布局溢出与按钮可达性，不能覆盖真实缩放下的字号放大与图片缩放。
- loading 由注入的假 provider 触发；真实模型延迟下的 loading 形态未在本脚本重复验证（历史真实全闭环 run-05 已包含真实等待与部分失败路径）。
- 本脚本覆盖 空白 / 有数据 两种形态与键盘主路径；生成中/部分失败/返工/导出的状态细节由 `ui`、`ui_rework`、`ui_shot_retry` 三个套件覆盖（修复后已复跑通过），未在本脚本内重复。
- 未做真实读屏软件（NVDA/Narrator）走查；`role`/`aria-live` 为 Chromium 可访问性语义层面验证。
