## 1. 目的与边界

- 把业务模型编译成界面模型：对象 + 信息 + 行为 + 状态 + 规则 + 反馈 + 导航 + 表现。
- 适用范围：项目首页、全局模型设置，以及同页六个任务入口（资料—理解—方案—生成—审核返工—交付）。
- 保留：领域事实/采用权限、IndexedDB 权威、冻结执行身份、Unknown 不重提、历史与单图隔离；不换框架或另造执行系统。用途配置与凭据消费者的实际接线由既有 R4.3/R4.4/R5/R6 任务承接，不宣称现有 API 已满足。
- 本轮产物：任务流程、三个关键屏结构草图、确认/恢复规则；不是可点击原型或视觉验收。工程完成条件仍在计划，真实页面走查与最终人审不由纸面检查替代。

## 2. 业务对象与全局规则

**对象（用户视角）**

| 对象 | 用户看到什么 | 可以做什么 |
|---|---|---|
| 项目 Project | 名称、状态、更新时间、参考图、当前套图 | 新建、打开、重命名、复制、导出项目包、删除 |
| 参考图 Reference | 缩略图、角色（主图/细节/场景/竞品…）、数量 | 添加、设角色、删除 |
| 商品事实 FactSlot | 名称、值、来源（用户/模型）、确认状态、置信 | 确认、修改、标未知、移除、增删自定义槽位 |
| 套图计划 SuitePlan | 有序图片任务（角色、目的、依据） | 生成推荐、添加模板/自定义、复制、删除、排序、编辑 |
| 公共风格 StyleSpec | 背景、光线、色调、构图、避免项、版本 | 编辑、保存为新版本、恢复上一版本 |
| 单图规格 ShotSpec | 每图的保留项/允许变化项/审核清单 | 编辑、保存新版本、恢复 |
| Prompt 版本 | 可读全文、编辑状态；版本/hash 在详情 | 查看、人工编辑并保存、明确放弃人工文本后重新编译 |
| 生成记录 Attempt | 状态、进度、基于哪份方案；任务编号在详情 | 明确提交、核对已知任务、恢复未提交队列；未知结果不自动重提 |
| 候选 Candidate | 图片、尺寸、哈希、检查报告、来源 | 预览、比较、返工（生成新候选）、采用 |
| 采用 Selection | 每图当前选中的候选与状态 | 采用、改选、取消采用 |
| 交付 | 选择总览、硬阻断与风险分别列出 | 导出完整项目包或仅包含采用成果的交付包 |

**全局规则**

1. 当前任务区有一个突出主操作；次操作与逐图操作保留，不能把“一个视觉主操作”解释为全页只能有一个按钮。
2. 工程信息（Prompt 全文、hash、action/task id、协议身份、版本与指纹）默认收进详情；生成摘要始终可见，查看详情不是提交前必经关卡。
3. 状态来自 repository/domain 和有效能力，DOM 不是第二状态源；fake provider 只替代外部模型响应。
4. 上游变化显示受影响范围与原因，不覆盖历史候选/采用。缺失或过期的系统 Prompt 可自动准备；人工文本不被静默重编或覆盖。
5. 模型提案不是事实，浏览候选不是采用，检查通过不是自动采用；交付硬门与 VLM 风险分开。
6. 失败说明发生了什么、影响哪项、下一步在哪里。异步完成仅更新状态，不抢焦点、不自动切任务；用户明确导航才切换。
7. 页面不预填示例商品；空白启动是默认路径。

## 3. 信息架构

首页（项目）+ 常驻设置入口 + 同页工作台六个导航入口；不是六次必须确认的流程关卡：

| # | 阶段 | 目标 | 完成条件 | 默认展开 | 完成后的摘要 |
|---|---|---|---|---|---|
| 1 | 资料 | 收集生成依据 | 名称 + ≥1 张主图 | 参考图与商品资料 | 名称 · 参考图 n 张 |
| 2 | 理解 | 把提议变成已确认事实 | 关键事实全部确认 | 异常/低置信优先，已确认折叠 | 已确认 n 项 · 未知 m 项 |
| 3 | 方案 | 决定拍哪些图、什么风格 | ≥1 张图且无未满足硬依赖 | 图片任务列表；风格与规格折叠 | n 张图 · 风格 v |
| 4 | 生成 | 产出候选并看清执行状态 | 有成功候选即可审核，不等待整套终态 | 生成摘要 + 自动准备状态 + 逐图进度 | n 成功 · m 失败 · k 待核对 |
| 5 | 审核返工 | 处理问题并人工采用 | 每张必需图有当前采用 | 图片为中心的候选与清单 | n/m 已采用 · 问题 k |
| 6 | 交付 | 通过门禁并导出 | 全部门禁通过 | 选择总览与阻断清单 | 就绪 / 阻断原因 |

导航规则：阶段条与设置入口始终可达；能打开一个任务区不等于能执行外发/采用/导出。无结果时展示有解释的空态与来源入口，不把整个区域锁死。导航不改事实或采用，不授权外发；进入生成区可触发 §4.6 的本地准备。返回保留当前图、候选与滚动位置；异步结果不自动推进。启动可定位待处理任务，但不把历史“完成”当作本次操作授权。

## 4. 逐视图契约

### 4.1 项目首页

| 层 | 内容 |
|---|---|
| 信息（默认） | 产品名与数据归属说明（一行）；新建输入框与主按钮；导入项目包（次）；项目列表：名称、状态徽标、更新时间、打开 |
| 信息（展开） | 每行的更多操作（重命名、复制、导出项目包、删除）；存储诊断（仅异常时） |
| 行为 | 新建、打开、导入、重命名、复制、导出项目包、删除 |
| 状态 | 空白（无项目）、列表、创建中、导入中、导入失败、存储能力失败 |
| 规则 | 空列表时突出“新建项目”；删除需二次确认；导入失败不产生半份数据 |
| 反馈 | 创建中禁用提交并显示进度；导入显示进度与结果；失败给分类原因与重试 |
| 导航 | 打开项目 → 工作台；返回 → 首页 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 新建项目（主） | 空白启动的唯一起点 | 名称非空 | 创建 IndexedDB 项目并进入工作台 | 名称缺失/存储失败的行内错误 |
| 导入项目包（次） | 跨浏览器/机器恢复 | 无 | 校验后写入本机并出现在列表 | 包损坏/版本过高等分类原因，不写入 |
| 打开 | 继续一个已有项目 | 项目存在 | 进入工作台并定位到当前阶段 | 打开失败 → 行内错误 |
| 更多：重命名/复制/导出项目包/删除 | 低频管理动作收进菜单，避免列表噪音 | 项目存在 | 对应结果或二次确认 | 行内错误，删除失败不改变列表 |

### 4.2 工作台外壳

| 层 | 内容 |
|---|---|
| 信息（默认） | 返回入口；项目名；六入口导航（当前/待处理/就绪）；模型设置及对应缺凭据状态；当前任务区；真实保存状态 |
| 信息（展开） | 项目元数据（创建/更新时间、schema 版本、存储用量）收进“项目信息” |
| 行为 | 切换任务区、打开设置、返回首页、重命名（低频）、导出项目包（交付区次操作） |
| 状态 | 草稿、就绪、处理中、部分失败、Unknown、可交付、存储错误 |
| 规则 | 操作就绪由领域与能力派生；导航/展开不授权外发、不改事实或采用；允许 §4.6 的本地准备记录，设置关闭回原任务 |
| 反馈 | 保存状态常驻；异步状态以 live region 提示，不抢焦点；明确跳到问题才将焦点落在问题标题 |
| 导航 | 错误靠近受影响操作，并提供“设置此用途/查看缺项/核对原任务”等具体入口 |

### 4.3 阶段一：资料

| 层 | 内容 |
|---|---|
| 信息（默认） | 参考图网格（缩略图、角色、数量）；商品名称（必填）、介绍、卖点、本次重点；草稿保存状态 |
| 信息（展开） | 单张参考图的原始尺寸/哈希/去重说明；角色说明 |
| 行为 | 添加参考图、设角色、删除参考图、编辑资料、保存草稿（自动+手动） |
| 状态 | 缺输入、保存中、已保存、分析中（进入下一阶段的过渡）、失败 |
| 规则 | 名称与至少一张主图齐全前，“分析商品资料”禁用并说明缺什么；相同内容图片不重复登记 |
| 反馈 | 字段旁提示；失败保留资料；成功提示“商品理解已准备”，用户仍在本操作等待区时可展示结果，否则不抢其正在编辑的任务 |
| 导航 | 分析是明确外发动作，按钮旁显示语义模型与费用提示；缺凭据就地打开对应设置，配置完成不自动分析 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 添加参考图 | 生成必须以真实商品图为依据 | 无 | 登记参考图（按内容去重） | 非图片/超限/重复给行内说明 |
| 分析商品资料（主） | 让系统提出商品理解，而不是要求用户写提示词 | 名称 + ≥1 主图 | 调用语义 provider，写入“模型提案”，进入阶段二 | 分类错误 + 重试；不静默，不覆盖用户输入 |
| 保存草稿（次，自动） | 用户不应担心丢失 | 有改动 | 写入 IndexedDB | 保存失败常驻提示，可重试 |

### 4.4 阶段二：理解

| 层 | 内容 |
|---|---|
| 信息（默认） | 待处理项（冲突、未知、低置信、必确认）：名称、提议值、来源、置信、操作 |
| 信息（展开） | 全部事实（含已确认）、来源与依据、依赖关系；新增自定义槽位表单 |
| 行为 | 确认、修改、标未知、移除、新增槽位（可授权模型提议） |
| 状态 | 未分析（空）、分析中、待确认 n 项、已确认 |
| 规则 | 模型提议不自动确认；关键事实未确认阻断相应方案操作而非浏览任务区；每个决定写新版本而不是覆盖 |
| 反馈 | 每项操作即时更新进度（已确认 n/m）；阻塞项直接指向第一条未处理 |
| 导航 | 主操作推进到“方案” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 确认 / 修改 / 标未知 / 移除（行内） | 事实决定后续全部内容，必须逐项可控 | 槽位存在 | 写入新记录并更新依赖状态 | 行内错误，旧值保留 |
| 显示全部事实（次） | 渐进披露，默认只看异常 | 无 | 展开已确认项 | —— |
| 新增自定义槽位（次） | 允许扩展，不锁死在预设 | 标识/名称/值合法 | 新增并纳入依赖统计 | 校验错误行内提示 |
| 继续编辑方案（主） | 关键事实已由行内操作确认，此按钮只导航，不重复确认 | 必须事实满足 | 进入方案任务区 | 缺必须事实时列出具体项；非阻塞未知不误锁 |

### 4.5 阶段三：方案

| 层 | 内容 |
|---|---|
| 信息（默认） | 图片任务列表：缩略/角色、名称、目的、依据满足或阻断、顺序操作 |
| 信息（展开） | 公共风格（背景/光线/色调/构图/避免）、单图规格（保留项/允许变化项/审核清单）、模板说明 |
| 行为 | 生成推荐方案、添加模板图、添加自定义图、复制、删除、排序、编辑风格与规格、恢复上一版本 |
| 状态 | 理解未满足时可浏览但相应操作不可执行、空、编辑中、依赖阻断、就绪 |
| 规则 | 列表顺序即最终顺序；条件依赖（对比图必须有竞品参考图等）精确阻断并说明原因 |
| 反馈 | 每次操作写到新版本；依赖阻断时在主操作旁列出缺什么 |
| 导航 | 主操作推进到“生成” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 生成推荐方案（空态主） | 默认方案降低门槛 | 必须事实满足 | 本地派生 1..N 张图的推荐列表，不外呼 | 缺事实可定位，不能伪造满足 |
| 添加模板图 / 添加自定义图 | 支持人工增减 | 相应事实/依赖满足 | 追加图片任务 | 依赖不足时标记阻断 |
| 复制 / 删除 / 上移 / 下移（行内） | 常规编排 | 至少一张图 | 更新顺序或集合 | 失败不改旧计划 |
| 编辑风格/规格（折叠区） | 需要时精确控制 | 有图 | 新版本并标注影响范围 | 保存失败保留旧版本 |
| 查看生成摘要（主） | 看清本次发送内容，不再要求逐图技术编译 | 有图片任务 | 进入生成区，系统准备适用 Prompt；无外呼 | 缺项在摘要中定位；人工文本过期时保留并要求处理 |

### 4.6 阶段四：生成

**默认路径**：查看生成摘要 → 一次“确认并生成 N 张” → 逐图进度与成功候选。删除独立的“生成前确认”、常规逐图“编译并保存”、另找“整套生成”的必经串联；内部确认记录、冻结身份与先登记再外发仍保留。

| 层 | 内容 |
|---|---|
| 信息（默认） | 本次新提交的图数/任务、模型与规格、参考图缩略、实际发送的资料摘要、费用提示、风险与硬缺项；逐图进度与成功候选入口 |
| 信息（展开） | 每图将实际发送的完整 Prompt、高级参数、编辑/来源状态；hash/原动作身份/历史在技术详情 |
| 行为 | 自动准备系统 Prompt、展开并编辑、明确确认并生成、停止新增、继续未提交图、核对原任务、处理明确失败、查看候选 |
| 状态 | 准备中、待修复、待确认发送、提交中、生成中、部分成功、已停止新增、结果待核对、已有候选 |
| 规则 | 确认绑定用户看到的摘要与实际请求；提交前再校验指纹。摘要变化即使按钮已点击也中止该次提交，展示变化，不偷偷发送新内容 |
| 反馈 | 按图片行显示状态；不能只用颜色或虚构进度百分比。成功即有“比较这张图”入口，其他图继续生成 |
| 导航 | 用户点击成功行进入同图比较；后台任务继续但不改变当前候选/焦点；已开始的动作不随设置变化重定向 |

**自动准备与发送边界**

- 打开生成区仅对缺失/过期的系统文本准备版本；依据相同不重复制造版本，不触发模型外呼。准备期间显示原因并禁用发送。
- 人工编辑文本过期时保留原文/草稿及变化原因。用户可以检查并保存为基于当前依据的新版本，或明确选择“放弃人工文本并重新编译”；不得自动替换，放弃时提示内容损失。
- 摘要展示每张图实际会发出的资料/参考图；详细全文随时可查。语义用途不支持参考图时不能宣称图像已发送，按实际能力说明。
- 主按钮只提交摘要明确列出的集合。默认是未提交的图；成功、在途、Unknown 不混入。单图生成同样有范围为1的摘要；再生成成功图是明确的新付费动作。
- 批次建立时冻结已确认集合的非秘密请求身份；之后设置变化只用于新动作。已停止、尚未外发的旧队列按原摘要恢复；原凭据缺失时提示补给，不偷偷换当前目标。
- 金额只有来源/时间/适用参数可核实时才给估算，并标为非账单；不能估算就明确“无法估算，供应商按实际调用计费”，不能显示免费或捏造上界。本轮工程付费门仍服从计划预算/次数授权，不新增计费平台。

**按钮与确认规则**

| 操作 | 人的决定与前置 | 系统结果 | 失败/恢复 |
|---|---|---|---|
| 确认并生成 N 张（主） | 在同屏摘要明确授权外发；准备、依据、能力、凭据就绪 | 确认记录与冻结集合持久化，再登记每个 action 后外发；双击不增新动作 | 保存/指纹校验失败则零外发；发送后不确定归 Unknown |
| 查看/编辑完整 Prompt（次） | 可选高级控制，不是普通路径必经步骤 | 保存新版本，更新摘要及就绪状态 | 草稿保留，失败不声称已保存 |
| 停止新增提交（次） | 只停止还没发出的图，无确认弹层 | 保留已提交任务的观察与结果 | 显示“已提交的任务仍可能完成”，不假称取消上游 |
| 继续未提交 N 张（主或次，随状态） | 查看原批次摘要后明确授权 | 原集合中尚未外发的图继续；不重复成功/在途/Unknown | 原目标/凭据不可用时先恢复，不改写原集合 |
| 核对原任务（次） | 已有 task id；使用原身份与匹配凭据 | 查询/取回结果，不新增 submit | 无凭据提供原目标专用补给入口；无 task 不伪装可查 |
| 重新生成失败的 N 张（次） | 明确失败且允许新动作；显示费用/集合摘要 | 只为所列失败图创建新动作 | 不包含可能已受理的 Unknown |
| 比较这张图（行内） | 有已保存成功候选 | 打开同图比较上下文 | 缺结果字节如实提示，不显示成功可用 |
| 无任务编号的未知结果：另发新请求（危险次操作） | 无法查询的原请求可能已计费；先显示原请求与重复扣费风险，用户专门确认后才可另发 | 创建独立新动作；原Unknown不改成失败或成功 | 默认不选、不自动触发；不称“恢复原任务”，预算/权限门仍约束新调用 |

### 4.7 阶段五：审核返工

| 层 | 内容 |
|---|---|
| 信息（默认） | 图片任务条及采用进度；当前同图工作区：参考原图、对照候选、当前查看候选；问题与采用状态紧邻图片 |
| 信息（展开） | 完整报告、当前候选原 Prompt/执行身份、历史；高级返工 Prompt |
| 行为 | 切换图片/候选、指定对照候选、等比例放大、局部返工、明确采用/改选、取消采用 |
| 状态 | 无候选、有问题、报告待运行/过期/未知、返工中、当前采用/尚未采用、旧候选、原任务待核对 |
| 规则 | 当前查看、对照、人工采用三者分开；候选切换不修改 Selection。未满足当前采用合同的历史候选可查看但说明不可采用原因，不暗改其身份 |
| 反馈 | “已采用：候选X”和“当前查看：候选Y”分别可辨；新图到达只提示可查看，不自动改选、换当前图或夺焦点 |
| 导航 | 从生成行带 shot/candidate 身份进入；切换任务与返回时保留位置。可在其他图生成时审核成功图 |

- 桌面主区横向直接对照，图片 `contain` 不裁商品，标明原图/候选与采用身份；缩略列表可裁但须能看原图。放大与共同尺度可选，不用截图差异替代肉眼比较。
- 返工区就地展开：选择问题/写方向 → 系统本地准备摘要 → “确认并返工这张图”。默认不要求先按“预览 Prompt”；高级全文可查可改，人工文本保护同生成区。
- 返工摘要明确目标图、作为依据的候选、参考图、模型、参数与新增费用；这次提交只影响该图，不改写其旧候选/旧采用，也不改变其他图记录。
- “采用当前候选”是明确的人工决定，直接保存并反馈，无第二个重复确认面板；改选显示将替换哪条采用。可通过历史再次改选或取消，不用导航代替采用。
- 确定性硬问题与 VLM 建议分别展示；复核模型调用是另一种外发用途，按钮说明费用，不因为打开比较或采用而偷偷启动付费复核。

| 操作 | 前置与结果 | 恢复/反馈 |
|---|---|---|
| 切换任务/候选、指定对照、放大 | 只改变查看上下文，无提交/采用 | 保留当前图位置；缺字节提示真实恢复条件 |
| 采用当前候选（主） | 候选符合既有采用合同；保存 Selection | 成功显示精确候选；失败保留原采用；不能先给成功反馈 |
| 取消采用（次） | 明确撤销该图选择，不删候选 | 显示未采用；可再次选历史候选 |
| 确认并返工这张图（返工区主） | 目标及方向有效，摘要当前 | 先冻结登记再外发；失败/Unknown规则同生成；旧图保留 |
| 运行此图复核 / 整套复核（次） | 对应用途可用；说明发送内容及费用 | 报告绑定当时的候选/选择集合；异步期间改选则结果只能作历史，不能贴给新选择 |
| 查看交付条件（导航） | 始终可打开交付区；导出仍需硬门 | 精确定位缺采用/复核条件，不多加一个“确认采用”关卡 |

### 4.9 常驻模型设置

**入口/作用域**：首页和项目工作台同一位置的“模型设置”；桌面使用可滚动侧面板，小宽度改为全宽设置视图。不是第七个必须完成阶段。打开保留项目/当前图，关闭回触发器，Esc 关闭，焦点在面板内循环；操作有未应用变更时可显式应用或放弃，放弃提示将丢的是设置草稿，不是项目资料。

**支持范围**：按商品理解、生图、图片复核三个用途选择已接入的有效配置，复核同时覆盖单图/整套消费者。不建设任意协议/任意端点模型平台，不新增模型选型。当前可供设计接线的真实档来自 `config/product-v2/providers.json`：语义 DeepSeek、复核 qwen-vl-max、图像 qwen-image-3.0 与大陆火山 doubao-seedream-5-0-flash-260915；部署实际可用性由有效能力返回，fake 只供独立测试环境，不能伪装真实选项。

| 信息/动作 | 设计决定 |
|---|---|
| 默认信息 | 用途、实际模型、官方目标、相关能力、凭据状态；“未提供”与“已提供、尚未验证”分开，输入非空不显示已验证 |
| 目标/参数 | 不允许任意 URL；本轮仅选择已支持目标和其能力允许的参数。高级信息按需展开，不在普通页面写供应商分支 |
| key 输入 | BYOK password 输入，可粘贴；状态只显示有/无/待验证/无效，不显示原文或尾号。保存按钮语义为“应用到本次会话”，不误导为持久保存 |
| 作用域 | 非秘密用途选择/参数可按既有浏览器配置合同持久保存；秘密仅当前标签页内存，刷新/关闭后需重输，不跨标签、项目包、日志、诊断复制。同标签页同目标可供多个项目使用，非秘密范围说明可见 |
| 百炼共用凭据 | 同一官方目标可使用一份内存 key 供三个相关用途引用，不要求用户重复粘贴；用途/模型能力仍分别解析。火山独立凭据，不转送百炼 key |
| 应用设置（主） | 无模型外呼，显示变化和影响后应用；回原任务，恢复就绪但不自动分析/生成/复核 |
| 清除本会话凭据（次） | 明确本次操作范围；清除key而不清项目、候选或采用，不自动改走部署key。进行中的任务可能需要重新提供原目标凭据才能核对 |
| 默认档 | 生产默认关闭如实显示；既有获批受限环境另按计划执行，UI无“开启公众共享key”开关，也不回显部署秘密 |
| 验证状态 | 本轮不增加会产生费用的“测一下”按钮；由真实业务调用更新验证状态，设置应用不暗发探测请求 |
| 旧任务补给 | 原任务提示中可打开原目标的凭据输入，不必切换新动作选用的模型。冻结身份+原目标凭据引用用于核对，不猜原key、不偷用当前目标；轮换后是否可访问旧task取决于供应商授权，失败需明确提示 |

```text
模型设置                                         [关闭]
商品理解      已支持模型 ▼       百炼凭据：未提供
生图          百炼 / 火山 ▼      当前档能力与规格
图片复核      已支持模型 ▼       单图与整套使用同用途
-----------------------------------------------------------------
百炼 key [密码输入]    火山 key [密码输入]（选用时需要）
只在本标签页内存；刷新后重新输入；不导出、不自动外呼
影响：更换生图模型需重新准备未提交内容；已提交任务不变
[应用到本次会话]       [清除本会话凭据]
```

**配置变化的准确边界**

- 只换 key：不使无关 Prompt/候选失效；仅影响后续请求及核对能否认证。
- 换生图模型/请求参数：只对依赖这些参数的未提交内容重新准备，人工文本按 §4.6 处理；不改写已提交动作与候选来源，不自动换图或再生成。
- 换语义/复核模型：用于下次对应调用，不自动把已确认人工事实变成未确认，不强制重跑历史报告。资料/候选/采用集合变化造成的过期另按领域依赖规则。
- 刷新：保存的非秘密配置及项目恢复；凭据状态回“未提供”。旧任务缺凭据时给原目标补给入口，不能因为刷新创建新action。
- 同一无状态网关服务多人：客户端配置限单请求有效，不改服务进程全局模型、默认档或其他浏览器配置。


## 5. 表现层基线

**token（单一来源：`app/product_v2/styles.css` 的 `:root` 变量，组件不写死颜色/间距）**

- 颜色：中性底 `--bg` / 面板 `--surface` / 边界 `--border`；主色 `--accent`（一个品牌蓝，深浅两档）；
  语义 `--success` / `--warn` / `--danger` / `--info`；文本 `--text` / `--text-muted`；焦点 `--focus`。
- 字体：系统字体栈；字号 12 / 13 / 14 / 16 / 20 / 24；行高 1.4–1.6；字重 400 / 600；等宽仅用于 hash 与 id。
- 间距：4 的倍数（4 / 8 / 12 / 16 / 24 / 32）；圆角 6 / 10；边框 1px；阴影仅用于浮层，不用于普通卡片堆叠。
- 图片：缩略 64 / 96 可裁切，比较/审核图用 `object-fit: contain` 并保持原图比例；不得为统一卡片裁掉商品。预留图像区域避免结果加载后布局跳动。

**组件与状态**：按钮（primary / secondary / ghost / danger / link；default / hover / focus-visible / disabled / loading）、
输入与文本域（label / 帮助 / 错误 / 只读）、卡片（标题 + 说明 + 内容 + 动作区）、列表行（含徽标与行内动作）、
状态徽标（空白 / 进行中 / 成功 / 警告 / 失败 / 未知 / 过期）、步骤条、进度条、空态、错误条、
设置侧面板、就地比较/返工区、`<details>` 渐进披露区；采用不另开重复确认面板。

**无障碍与响应式**：正文与控件对比度 ≥ 4.5:1；移动端触控目标 ≥ 48px；所有输入有可见 label（不用 placeholder 代替）；
表单使用语义元素；`:focus-visible` 2px 可见轮廓；tab 顺序与视觉顺序一致；异步结果用 `role="status"`/`role="alert"`；
1440/1366 以图片比较为主区；125%/200% 实际浏览器缩放及390px改自适应布局、保留任务/候选身份和关键操作，不能用只缩 viewport 冒充 zoom。小宽度参考图可折叠，候选缩略及当前身份固定可找；不声称390px能达到桌面三图同屏比较效果。固定栏不得遮挡内容/焦点。
