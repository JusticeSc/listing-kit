# 技术选型报告模板

> **填写时机**:`06` 的 ②.5 技术选型门;一个待定能力填一份。
> **流向**:本报告经人类确认后,结论记入 `PROGRESS.md` 的 ADR(重大选型单独立 `docs/adr/` 文件,见 `ADR_TEMPLATE.md`);如引入新依赖,同步登记进 `00` 第 2 节依赖表。

## 1. 问题

<一句话:需要什么能力。再列 3~5 条具体要点,不要写“最好的 XX 是什么”式提问。>

## 2. 约束

- 技术栈:<如 Python 3.11 / FastAPI;Redis 已存在>
- 性能/规模:<如 日任务量 < 10 万;单机起步>
- 部署/运维:<如 不希望新增运维组件>
- 成本/许可:<如 拒绝 AGPL>

## 3. 已有能力盘点(按复用阶梯顺序)

- 仓库内:<搜到的现有实现,或“无”>
- 现有依赖:<已有依赖的等价能力,或“无”>
- 标准库/框架:<标准库或框架自带能力,或“无”>

## 4. 候选方案

- A:<方案 + 版本>
- B:<方案 + 版本>
- C:自己实现<作为一个候选,必须列出>
