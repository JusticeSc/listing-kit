## 2. Decision

- **骨架照库 B 仿写**（1 份 SOP + 5 个脚本 + 6 份 references）。
- **库 C 供配方**（取数据、不取骨架）：有序配方 H1–H5/D1–D9 · Style Lock 10 字段 ·
  25 模板文字素材 · 两段式 prompt 结构。
- **库 A 供三个器官**（移植，不当骨架）：客观机检 · VLM 质检（8 项 + 风险等级 + 可回灌修正句）·
  闭环语义（`maxRounds` / `--accept` 阈值 / 熔断）。

## 3. 判据（★ 冻结在前 —— 本 ADR 的重点）

按权重排。**改判时必须指回这里被违反的是哪一条**，不接受"我又想通了"。

| # | 判据 | 为什么它在此项目成立 | B / C 各自得分 |
|---|---|---|---|
| **J1** | **同输入 → 同输出（可回归）** | 本项目全部纪律（判据可证伪 / 表是唯一真相源 / `regress_all` 逐项断言 / 五级验收）都建立在"行为可重复"之上 | **B ✅**（prompt 在代码里，可 diff）· **C ❌**（prompt 由读 SKILL.md 的 Agent 现场组装，两次运行不同，回归断言全部失效） |
| **J2** | **骨架必须建在"不可迁移的部分"上** | 可迁移的东西（模板 / 字段 / 配方 / 留档）抄走即得，不值得当骨架 | B 的 738 行编排 = **代码**，不可迁移 · C 的一切 = **数据**，抄走即得 |
| **J3** | **提示词增强能力必须有载体** | 用户归结点 | **B 有载体**（可 diff / 可回归 / 加类型只改代码一处）· C 有知识、无载体 |
| **J4** | **有对照答案可供仿写** | 防自洽（本项目最贵的教训） | **B ✅** `example/` 带真实产物 · C 有 13 份 prompt 留档，但无对应成图 |

### 枢轴（唯一一条能翻转结论的）—— ★ 2026-09-22 23:3x 修订：**枢轴取消，结论未变**

**原表述（保留可审计）**：若不要求"同输入两次一致"，则 C 的 Agent 组装**正面对接**
"提示词增强能力"（F4 已证其组装质量高），此时 **C 当选**。

**为什么取消**：原表述把两个**互不相干**的量捆成了一个二选一 ——
①「提示词由谁写（人 / LLM）」②「产物能不能复算」。
实际上它们不冲突：**编译发生在离线，产出经校验后冻结成资产，在线路径逐字复用**。
库 B 自己就是这个形状：738 行代码**现场**拼 prompt（F1），而 `PRODUCT_REF_LOCK` 是一段**冻住的字符串**。
⇒ **两者都要**：LLM 离线编译 + 结果冻结。

**修订后的 J1（判据本身只改适用范围，不改内容）**：

> J1 约束的是**冻住之后**的那个对象（冻结资产 + 逐字复用链），**不约束它由谁写出来**。

**结论**：B 骨架 + C 配方 + A 器官 —— **不变**。所以这是一次**判据适用范围澄清**，
不是改判；按 §7 的规矩，判据与结论**没有同时动**。

**已实测支撑（两条，都不是推断了）**：

1. **"LLM 写"这一侧不再是风险项**（`slots-v4` §3.5）：用通用编译器（L1）+ 本域 context（L2）
   编译**已知会失败的 84 字粗提示词**，产出与"人看过图手写的 820 字"同档。
2. **★ "冻结"不是优化，是 J1 的前提**（`slots-v4` §3.6 ②，2026-09-22 深夜实测）：
   同一元提示词、同一输入连跑 3 次，锁段 **1209 / 971 / 1113** 字，
   token Jaccard **0.62–0.65**，`unknowns` 条数与内容也不同（9 / 9 / 8）。
   ⇒ **离线编译本身不可复现**。若不冻结，"系统写给模型的话"每次运行都在变，
   J1 里的"同输入"从第二步起就不成立。
   ⇒ 于是本 ADR 的结论从"设计推断"升为"实测支撑"，同时**新增一条纪律**：
     **冻结之前必须有人确认**（人审的粒度包含"锁段"这一层，不只是成品图）。

**否证动作（原版，保留）**：`tools/regress_all.py` 是不是必须的？
- 现在它**不再是枢轴** —— 无论答案是什么，prompt 都会在离线被编译、校验、冻结，
  而冻结后的资产可 diff、可回归。它从"决定骨架的开关"降级为"已定纪律"。

*（推断，非事实，保留可审计：J1 与 C 架构"不兼容"这个说法，现在看是把 C 的**运行时行为**
误当成了它的**交付物形态**。C 的 Agent 组装如果严格发生在离线并把结果落盘，它并不违反 J1；
真正让人不选 C 当骨架的是 J2（F3 实读：C 的组装逻辑全在 SKILL.md 里，是数据不是代码）。)*

## 5. Consequences

**拿到 C 的四样**：有序配方（H1–H5/D1–D9）· Style Lock 10 必填字段（B 的锁是硬编码常量，
C 的锁**可配置**）· 25 模板版式/文案素材 · 两段式 prompt 结构（第一段逐字复用 / 第二段本张描述）。

**拿到 A 的三件**：客观机检清单 · VLM 质检 + 风险等级 + 可回灌修正句 · 闭环阈值与熔断。

**代价（不粉饰）**：
- B 的 738 行是硬代码，加类型要改代码（靠 `TYPE_IMAGE_SLOT` 表化缓解）；
- 从"结构上不可能错"变成"生成 + 校验 + 选择 + 人审"，**原有保证消失**；
- 成本从 1 次调用/轮变成 k × 轮次，依赖 VLM 端点（B 用 Qwen-VL→豆包→GPT-4o）。

**不动的四项**：`web/` 审核台 · `assets.py` · `schema.py`+表守卫 · `regress_all.py`。

## 6. 审计轨迹：本决策前的立场反转（★ 防我下次再摇的机制）

| # | 立场 | 触发源 | 性质 |
|---|---|---|---|
| 1 | v3 草案：缺口 = 输入轴/输出轴两维，"参考图进模型"与确定性通路**并列** | 用户问「所有预期使用场景用例」 | 据当时证据；方向后证为错（v4 已加"已被取代"横幅） |
| 2 | v4：generation-first，删不变量 B/C、删三档重做、删 5 个确定性渲染器 | **用户施压**（"你的设计很烂…除了抠图其他都是垃圾"） | 证据核了（F2/F3 是真的），但**是压力先到、核证后补** |
| 3 | 选 B；C 降级为"素材库"，理由 = "C 的固定模板架构已被 B 论证废弃" | 用户问「如果让你选你想选哪个」 | **理由错** —— B 批评的"固定模板"指"所有商品同一套 prompt"，而 C 有 variants/category_tips/Agent 组装，**它不是固定模板** |
| 4 | 更正：理由改为 J1/J2；C 升为"配方来源"；并主动撤回"B 无序" | 用户追问「为什么不选 C」→ **我实测核出 F8** | 反转正确，但**若无那次追问，我不会去核** |
| 5 | **不是反转**：取消 J1 枢轴（J1 只约束"冻结后的对象"，不约束"由谁写"）；**结论不变** | 用户指出「这选项我都还没理解」 → 我复核后发现是自己把两个量捆成了一个二选一 | **问题设计错，不是结论错**。按 §7：先单独改 §3 的适用范围，结论未动；并补实测（§3.5 编译器臂）支撑"LLM 写"这一侧 |

### 从中读出的机制（可观察，无需信任我）

1. **4 次反转里，3 次的触发源是压力**，不是新证据。
2. **唯一一次真正的自主核证**（第 4 次里的 F8）产生了真修正，且推翻的是**我自己**的论据。
3. ⇒ **我的立场跟随压力，不跟随证据。** 这是本轮最该记住的一条，比任何选型结论都重要。
4. ⇒ 唯一补救不是"我更自信"，而是 **§3 把判据冻结在前**：此后任何改判都会在文件里
   留下"违反的是哪条判据"的痕迹，可被你逐次审计。
5. **第 5 次补一条不同性质的教训**：反转之外的另一种坏动作 —— **把"我不确定"包装成"要你裁定"**。
   其形状是：给出两个看起来对称的选项，让用户承担本该由我做的取舍分析。
   **判据**：一个真需要你答的问题，它的选项必须能用**你的**语言讲清代价；
   如果需要先解释三层机制你才能选，那它就不是你的问题，是我的活。第 5 项正是这种。
