## 1. 问题：主体不可复现

同一商品、**同一提示词**、连续三次生成（实测）：

| 次 | 主体 | 杯盖 | 版式 |
|---|---|---|---|
| overlay | 银灰金属细筒 | 银色顶盖 | 底部横条叠字 |
| native #1 | 深灰粗筒 + 腰线 | 黑色盖 + 按钮 | 两侧卡片 + 图标 + 引线 |
| native #2 | **白色**粗筒 | 白色盖 + 按钮 | 左侧纯文字 |

产品外观三次都不同，是**形态与颜色级**的差异，不是细节随机。

### 根因

位置 2—7 走 `generate` 路径：一句提示词进去，模型**整张重画** —— 主体、背景、文字全在模型手里。
位置 1 走 `compose` 路径：主体来自实拍抠图。

**两边主体来源不同，七张图就不是同一个商品的七张图。**

这不是随机性参数没调好。是**模型从来就没有被要求复用那个杯子** —— 我们只给了它一段文字描述。
在电商语义里，位置 1 是"实物"，位置 2—7 是"实物旁边的图解"，后者画成近似品，直接构成"实物与图片不符"风险。

## 2. 第一性推导：谁持有事实

### 2.1 起点：这是一对矛盾

卖家必须让图片同时满足两件方向相反的事：

- **可售** —— 好看、有说服力、推转化
- **诚实** —— 与实物一致，否则是实物不符 + 虚假宣传

"好看"可以由生成承担，"诚实"不能。**整条链路的设计，就是这条分界线画在哪。**

### 2.2 分解：一张商品图只有三样东西

| 组成 | 它承载什么 | **谁持有这个事实** | 错了会怎样 | 模型可否生成 |
|---|---|---|---|---|
| **物体** | 商品长什么样 | **实拍照片** —— 唯一见过它的东西 | 实物不符 → 平台 + 法律风险 | **否** |
| **文字** | 卖家对商品的断言（"保温 24 小时"） | **卖家** —— 只有他知道 | 虚假宣传 → 同样是法律风险 | **否** |
| **环境** | 处在什么场景、什么氛围 | **没有人** —— 环境不是事实，是设计 | 图不好看 → 只影响转化 | **是（全部）** |

### 2.3 判据

> **模型只能创作它不承担事实责任的部分。**

模型的处境很具体：它既没见过这个杯子（不是"物体"事实的持有者），也不知道保温几小时（不是"断言"事实的持有者）。
**它唯一有资格创作的地方，恰恰是它没有任何事实主张的地方 —— 环境。**

这一条比"能不能被对照发现"更根本：后者描述症状，前者归属责任。

> 早期判据"版式复杂度高就走 native"是**错的**，而且错得很有信息量。
> 反例：native 实测里模型自动把四条卖点用引线连到杯身对应部位 —— 版式确实更自然。
> **但那份引线之所以画得出来，恰恰是因为模型看见了杯子** —— 而"看见杯子"正是它越权做出物体事实主张的那一刻。
> 同一次生成里它还自作主张加了水滴 logo 和 `THERMO` 字样。**版式收益换不来事实失控。**

### 2.4 四条不变量的逻辑根据

四条不变量不是工程约定，各自能一路推回 2.2 那张表：

| 不变量 | 逻辑根据 |
|---|---|
| **A** 主体只有一份 | **主语同一律**：七张图回答的是"这个东西怎么样"。若七张里的东西各不相同，这组断言就没有共同主语，逻辑上不成立 |
| **B** 生成层看不见主体 | 看不见主体 ⇒ 无法对物体做事实主张。它"顺手画一个杯子"就构成一个**虚构事实** |
| **C** 文字层不参与生成 | 文字是**断言**，断言必须有出处，而模型不是那个出处 |
| **D** 位置 1 零模型 | 位置 1 的**信息密度 100% 是事实**（整个画面都在陈述"商品长这样"），模型合法作用域为空 |

> **D 这条此前给的理由是错的（或说太浅）。** 之前写的是"纯白底 / 85% / 禁文字是平台硬规则、容错为零"——那是**外部理由**。
> 第一性理由更强：不是规则不允许，是**没有环境可生成**。平台规则只是这个事实的外部投影。

### 2.5 由这条判据改掉的三处结论

**① 坑位不是平台的格位，是买家决策问题的枚举。**

买家从点进来到下单，要问完一串问题：这是什么 → 有什么好处 → 多大 → 用在什么场景 → 质量如何 → 买回来有什么 → 比别的好在哪。

**"七张"不是一个数字约定，是这串问题的枚举长度。** 平台上限 9 张、桌面端显示 7 张，都只是外部约束。

> **推论（改变了做法）**：模板不该"拿运营现存的手工七张反向抽取"，而应**先枚举买家问题，再拿现状去对照** —— 现状可能答错了问题，也可能漏了问题。
> 照抄现状 = 把现状的错误一并固化成模板。

**② 分期依据不是技术风险，是决策阶段。**

- **决策必需**（没有它没法看）：主图 + 卖点 —— 回答"是什么"和"好在哪"
- **决策充分**（没有它下不了决心）：规格 / 场景 / 细节 / 内容物 / 对比

第一版做两张，理由从"先跑最难路径"升级为 **"先交付决策必需的两问"**。技术风险控制只是附带收益。

**③ 验收口径有了定义。**

不再需要"你挑，挑不出来算不合格"。

> **验收 = 每个买家问题都被一个「可发布的事实性回答」覆盖。**
> "可发布" = 过平台规则；"事实性" = 物体与文字未被模型改写。

## 3. 三层分离 + 一个共享资产

```
一张成品图 = 主体层 + 背景层 + 文字层

  主体层   实拍抠图产物 · 全坑位共用同一份        [确定性]   ← 物体的持有者
  背景层   模型生成 · 提示词禁止出现产品本体      [生成性]   ← 唯一无事实责任
  文字层   字体文件绘制 · 逐字可校验              [确定性]   ← 断言的持有者

位置 1 主图：只启用主体层 + 纯白底
位置 2—7 副图：三层全启用
```

### 四条不变量（逻辑根据见 §2.4）

| # | 不变量 | 性质 | 当前代码 |
|---|---|---|---|
| **A** | 主体只有一份，7 个坑位读同一个 PNG | **数据约束**，不是提示词期望 | ❌ `make_main_image` 内部消费掉抠图结果，未落盘 |
| **B** | 生成层看不见主体（提示词禁产品类词） | 提示词约束 | ❌ 当前 negative 只禁文字类，产品类一个没禁 |
| **C** | 文字层不参与画面生成 | 分层约束 | ✅ overlay 已实现 |
| **D** | 位置 1 零模型调用 | **合法作用域为空** | ✅ 已实现 |

A 是这套架构的地基。**它必须是数据层面的约束** —— 不是提示词里写"请使用同一个杯子"，而是七个坑位读同一个文件。指望模型理解"同一个"是上一版失败的根源。

## 4. 坑位 × 三层映射

坑位 = 买家问题（§2.5①）。下表右四列是每个问题的"事实 / 呈现"配比：

| 坑位 | 主体层 | 背景层 | 文字层 | 生成调用 |
|---|---|---|---|---|
| 1 主图 | 实拍抠图 · 居中 85% | 纯白底，不生成 | — | 0 |
| 2 卖点 | 实拍抠图 | 纯色底，不生成 | 叠字 | 0 |
| 3 规格 | 实拍抠图 | 纯色底，不生成 | 叠字 + 标注线 | 0 |
| 4 场景 | 实拍抠图 | **生成场景 · 需环境融合** | 叠字 | **1** |
| 5 细节 | 实拍局部裁切 | — | 叠字 | 0 |
| 6 内容物 | 实拍多件合照 | 纯色底，不生成 | 叠字 | 0 |
| 7 对比 | 实拍抠图 + 竞品图 | 纯色底，不生成 | 叠字 + 标注线 | 0 |

**模型只在"背景层"列有生成标记的位置出现。** 整条链路从"7 次整张生成"降为 **1 次背景生成**（仅位置 4）。

> 位置 2/3/6 由"生成留白 / 轻生成"降为纯色底，是本版最实际的一处简化：卖点图解与规格图要的是**可读性**，纯色底比生成背景更清晰、更便宜，效果不会更差。**能用确定性做的，就不调模型。**

两个附带结论：

- **位置 5、6 不需要抠图**：5 是实拍图局部裁切，6 是实拍多件合照，都是纯确定性链路。
- **位置 7 需要竞品图**，而当前输入 schema 只有单个 `product`，没有竞品图位 —— 这是个 schema 缺口。

## 5. 接缝：本架构唯一的新增风险

位置 1 没有接缝问题（纯白底无缝可拼）。位置 2/4 有：主体与背景来自两个来源，硬拼会露。

### 三个失败模式

| # | 症状 | 根因 | 对策 |
|---|---|---|---|
| 1 | **悬浮感**（像贴纸） | 主体与背景之间没有接地关系 | 接触阴影（`_draw_contact_shadow` 已存在，需从位置 1 独占改为合成层通用） |
| 2 | **光照/色温错位** | 两个来源各自成图 | **让背景迁就主体**：把主体光位写进提示词（新增控制面字段 `lighting`）。主体是事实，不能改 |
| 3 | **视角与尺度错位** | 生成层不知道主体多大、从哪看 | 提示词约束视角 + 坑位规范定义落点（新增字段 `subject_placement`） |

三个对策指向同一原则：**接缝不能靠"改主体"解决，只能靠"约束背景 + 后处理弥合"。**
这也是 §2.3 判据的直接推论：主体是事实，环境是设计 —— **冲突时只能改设计，不能改事实。**

### 设计决策点：α 还是 β

| | 方案 α：合成后适配 | 方案 β：mask 补背景 |
|---|---|---|
| 做法 | 模型只画空背景，主体确定性贴入 | 主体先贴好，mask 遮背景区，用 `qwen-image-edit` 补背景 |
| 主体保真 | **绝对**（像素级不变） | **近似**（保留区是否被改动未知） |
| 接缝自然度 | 靠工程；位置 4 可能偏"假" | 天然（模型看得见主体与光） |
| 依赖 | 现有 t2i 通道，已就绪 | image-edit 端点，当前未实现 |
| 可验证性 | 主体哈希可断言 | 只能肉眼看 |

**决定：第一版走 α。** 位置 2/3 是留白背景，接缝本来就弱，α 够用。
**位置 4 单独评估 β**，但前置条件是一次实测：验证 `qwen-image-edit` 在 mask 外区域到底有没有改动。**在验证之前，β 不是选项。**

## 6. 一个被关掉的决策项：方案③（native）

此前悬着的三种文字策略：

| `text_mode` | 文字怎么来 | 可复现 | 改一个字 |
|---|---|---|---|
| `none` | 不出字 | — | — |
| `overlay`（默认） | 生成层禁字 + 代码叠字 | ✅ | 重画文字层 · 0.1s · ¥0 |
| `native` | 模型直出 | ❌ | 重出整张 · ~70s · 1 次调用 |

native 唯一不可替代的价值是**引线标注** —— 文字与画面内容产生空间关系。

**但 α 路线下它结构上不成立：** 模型看到的背景是**一个没有主体的空场景**，它不知道杯子在哪，画不出指向杯子的引线。

> 主体确定性 ⇒ 背景必须"看不见主体" ⇒ native 失去存在理由 ⇒ **方案③ 砍掉。**
> OCR 校验需求与"不可复现"两笔账一并归零。

更根本的理由在 §2.3：**引线之所以能画出来，靠的是模型看见了主体 —— 而那正是它越权做事实主张的时刻。** native 的价值与它的失控是同一件事。

唯一能救它的是 β，而 β 未验证。**结论：③ 是"结构上不成立"，不是"暂缓"。**

## 7. 与现有代码的差量

六处，都是收窄而非扩张：

| # | 文件 | 改动 |
|---|---|---|
| 1 | `src/synth.py` | 抽出 `cutout_subject()` 为独立产物，落盘 `subject.png` + `subject.json`（bbox / alpha 覆盖率 / 抠图方式）。位置 1 从"函数内部自己抠"改为"读共享产物" |
| 2 | `src/compose.py`（新增） | `place_subject(bg, subject, spec)`：落点、缩放、接触阴影、光照匹配。位置 1 也改用它（纯白底 + 主体是它的一个特例） |
| 3 | `src/planner.py` | 提示词从"描述整张图"改为**只描述背景**；新增 `SUBJECT_EXCLUSION_CLAUSE`（禁产品 / 商品 / 杯子 / 容器 / 包装 / 人物 / 手） |
| 4 | `config/slots.yaml` | 新增 `subject_placement`、`lighting`、`bg_kind` |
| 5 | `src/pipeline.py` | `generate_then_text` 拆为 `gen_bg → compose_subject → overlay_text`；位置 4 预留 `inpaint_bg` 分支（未实现，显式标注） |
| 6 | `src/validators.py` | 新增 `subject_identity`：每坑位在日志记录 `subject_hash` |

### 第 6 条为什么最值钱

**只要七个坑位的日志共享同一个 `subject_hash`，就构成"七张图的主体是同一个"的可断言证据。**

它把"主体一致性"从**要肉眼看的感觉**，变成**日志里可校验的断言**。
这是当前系统做不到、而新架构天然能做到的事 —— 也是这套设计相对"多调几遍提示词"的根本差别。

## 8. 设计收益

1. **主体一致性从"感觉"变成"断言"** —— `subject_hash` 跨坑位比对。
2. **成本下降** —— 7 次整张生成 → **1 次背景生成**（仅位置 4）。
3. **单张重做回到廉价** —— 重做 = 重贴主体 + 换背景（+ 重画文字），主体不必再赌一次。
4. **文字正确性不受生成影响** —— 文字层与生成层解耦。
5. **决策项收敛** —— 方案③ 被结构性地排除，不再占用讨论。
6. **失败面收缩到一层** —— 只有"环境"可能出错，而环境错了只影响观感，不影响合规。
   **运营敢用的真正原因不是省钱，是失败面小。**

## 9. 运行时执行路径

一次 `run.py` 调用的五个阶段：

| 阶段 | 做什么 | 产出 | 次数 |
|---|---|---|---|
| 1 建档 | 读控制面 + 校验输入（UPC / 类目 / 商品图） | 已校验的输入 | 每次 |
| 2 抠一次 | `cutout_subject()`：抠图、算 alpha 覆盖率、算 `subject_hash` | `subject.png` ★唯一共享资产 | **一次** |
| 3 规划 | 商品事实 → plan：每坑位的画布来源 / 背景提示词 / 主体落点 / 文案 | `plan.json` | 每次 |
| 4 扇出七路 | 每路：画布 → 贴主体 → 叠文字 | 七张候选图 | **×7** |
| 5 收敛交付 | 校验 → 推荐排序 → 按 UPC 命名导出 → JSONL 日志 | 成组素材 | 每次 |

**"一次与七次的边界"落在阶段 2 与阶段 4 之间** —— 这是整个架构的承重墙：主体资产在边界左侧生成一次，在右侧被读七次。

### 单路装配：七路是同一个函数

每路的差异只有参数：`bg_kind`、背景提示词、`subject_placement`、文案项。

| `bg_kind` | 画布来源 | 适用坑位 | 调模型 |
|---|---|---|---|
| `white` | 纯白画布 | 1 主图 | 否 |
| `solid` | 品牌纯色画布 | 3 / 6 / 7 | 否 |
| `generated` | 模型生成空背景 | **2 / 4** | **是** |
| `crop` | 实拍裁切（本身即主体） | 5 | 否 |

**七路里只有两路调用模型，且各调用一次。** 其余五路是全确定性路径。

### 不变量在运行时的强制点

架构写在文档里不算数。**每条不变量必须有一个消费它的代码位置，否则就是第四个死字段** —— 本项目已经出现过三个（`text_style`、`DASHSCOPE_IMAGE_MODEL`、`text_layout`，都是声明了但没人读）。

| 不变量 | 强制时刻 | 机制 |
|---|---|---|
| A 主体只有一份 | 阶段 2 产出，阶段 4 只读 | 文件系统；`subject_hash` 写入每路日志 |
| B 生成层看不见主体 | 阶段 3 组装提示词 | `SUBJECT_EXCLUSION_CLAUSE` 无条件拼接 |
| C 文字层不参与生成 | 阶段 4 叠字步骤与生成步骤代码路径分离 | overlay 分支独立 |
| D 位置 1 零模型 | 阶段 4 的 `white` 分支 | 无网络调用 |

### 两条回路

- **内环（单张重做）**：重放 plan 的第 k 项（`--only k`）。新架构下重做 = 重生成背景 + **重贴同一份主体** + 重画文字 —— 主体不必再赌一次。这才是"单张重做便宜"从愿望变成事实的地方。
  重做必须**先选原因**（文案 / 位置 / 背景），这不是 UI 设计，是 §2.2 那三层的直接映射：**修复动作必须落在出错的那一层上。**
- **外环（采纳率回流）**：日志按 坑位 / 分镜 / 提示词版本 分组统计，反哺模板。运行时日志是它的燃料。

### 失败隔离

- 单路异常不拖垮整批（已实现）：失败写日志，其他路照常交付 —— 这是"单张重做"能被运营接受的前提。
- 每路独立输出目录（已修）：目录名加微秒，避免并发运行互相截断日志。
- 降级链：抠图 `rembg` → `floodfill`；生成 `1600*1600` → `1024*1024` → auto。
- 位置 4 的 `inpaint_bg` 分支预留但未实现，必须在 `slots.yaml` 与代码中显式标注（不得成为第四个死字段）。

### 失败处理的分配原则

**按责任严重性分配修复成本，不按技术难度。**

| 层 | 失败的严重性 | 处置强度 |
|---|---|---|
| 主体层 | 实物不符（平台 + 法律） | **零容忍** —— 宁可要求重拍，也不许模型补画 |
| 文字层 | 虚假宣传（法律） | **严格** —— 字体绘制，必然正确 |
| 环境层 | 图不好看（转化） | **宽容** —— 随便重生成 |

这正是"重做三粒度"（文案 0.1s / 位置 1s / 背景 70s）的定价依据：**不是按耗时定价，是按责任层级定价。**

## 10. 接口契约：每个环节的输入 / 处理 / 输出

六个环节。**E1 是全链路唯一的前置**（七路都读它的产物），**E3 是唯一的扇出点**。

### E0 收件

| | |
|---|---|
| 输入 | `inbox/<UPC>/`：`main.jpg`（商品原图）、`copy.json`（卖点文案）、可选 `competitor.jpg` |
| 处理 | ① UPC 格式校验；② 原图可解码且 ≥1000px；③ 文案非空、条数 ≤6；④ **原图体检**：检测是否含文字 / 水印 / 多件商品 |
| 输出 | `job` 对象（内存）：`{upc, src_path, copy[], competitor_path}`；或**拒收** |
| 失败 | 拒收 —— 入口拦，不产生任何下游动作 |

> ④ 是关键：工具**修不了**不合规的输入（水印压在主体上抠不掉、道具擦不净）。必须在入口拦，不是等出口报错。

### E1 抠图（全局唯一一次）

| | |
|---|---|
| 输入 | `job.src_path` + 抠图配置（`CUTOUT_MODE`、模型目录） |
| 处理 | ① 加载 BiRefNet 会话（**本地优先，缺模型不下载**，直接降级 floodfill）；② 抠图得 RGBA；③ 取最大前景、去碎斑；④ 算 bbox / alpha 覆盖率 / `subject_hash`（alpha 通道 sha256 前 12 位） |
| 输出 | `subject.png`（RGBA）+ `subject.json`：`{mode, bbox, coverage, subject_hash, warnings[]}` |
| 失败 | **全局失败** —— 七路都依赖它，不能局部降级 |

> `subject_hash` 是"七张图主体同一"的断言依据，必须在这里算出并落盘，**不能是常量**。

### E2 规划

| | |
|---|---|
| 输入 | `job.copy[]` + `subject.json` + `config/slots.yaml` |
| 处理 | ① 读坑位模板（用途 / 尺寸 / 是否允许文字 / 主体占比 / 背景类型 / 校验强度）；② 把文案条目**分配到各坑位**；③ 生成排版参数（字号、位置、色值）；④ **仅位置 4** 生成背景提示词（禁产品本体 + 描述环境）；⑤ 算 `slot_hash` |
| 输出 | `plan.json`：每条 `{slot_id, purpose, bg_kind, subject_placement, callouts[], text_mode, prompt?, validate_level, slot_hash}` |
| 失败 | 无 —— 纯确定性。文案不足时降级（该坑位少几条），不报错 |

> **plan 是这条流水线唯一的状态。** 人可以在这里改（改文案、改排序），改了下游全部重放。落盘即"可复现"的定义：**复现的是 plan，不是图**（图有随机性）。

### E3 单路渲染（×7，彼此无依赖）

唯一有分支的环节，内部分三个子步。

**E3a 画布**

| | |
|---|---|
| 输入 | plan 单条 + `subject.png`（`crop` 时用原图） |
| 处理 | 按 `bg_kind` 分派：`white` → 纯白 RGB(255,255,255)；`solid` → 品牌色平铺；`crop` → 原图按比例裁切；`generated` → **调模型**出无主体背景 |
| 输出 | `canvas.png` 1600×1600 |
| 失败 | 单路失败，写日志，不影响其余六路 |

**E3b 贴主体**

| | |
|---|---|
| 输入 | `canvas.png` + `subject.png` + `subject_placement` |
| 处理 | ① 等比缩放主体到目标占比；② 按落点定位；③ 从 alpha 底部轮廓生成接触阴影；④ alpha 合成 |
| 输出 | `composed.png` |

**E3c 叠文字**

| | |
|---|---|
| 输入 | `composed.png` + `callouts[]` + 品牌色 / 字体文件 |
| 处理 | 用字体文件逐条绘制标题与正文 —— **不让模型画字** |
| 输出 | `final.jpg` 1600×1600 sRGB |

> 位置 5 走 `crop` 时，E3b 空跑（裁切结果本身就是主体）。这一路是纯确定性。

### E4 校验

| | |
|---|---|
| 输入 | `final.jpg` + 该坑位 `validate_level` |
| 处理 | `strict`（位置 1）：白底纯度 / 主体占比 ≥85% / 边缘带纯净 / 无文字块 / 尺寸 / 命名；`medium`（2/3/7）：尺寸 + 文字存在性；`light`（4/5/6）：尺寸 |
| 输出 | `validation`：`{passed, failed[], metrics{}}` 写进日志 |
| 失败 | **不阻断交付** —— 标 FAIL 交人工，运营看到的就是"这张要重做" |

> 校验在写盘之前跑，验的是自己刚生成的图。**所以它只能验它定义得了的东西**（尺寸、白底、占比），验不出"抠干净了没 / 有没有错字"。

### E5 交付

| | |
|---|---|
| 输入 | 七张 `final.jpg` + `plan.json` + `subject.json` + 全部日志 |
| 处理 | ① 按 `{UPC}_{序号}_{用途}.jpg` 命名；② 写 `run.jsonl` 逐环节结构化日志；③ 目录名加微秒防并发撞车；④ 汇总通过 / 失败清单 |
| 输出 | `out/<UPC>_<时间戳-微秒>/`：七张图 + `plan.json` + `subject.png/json` + `raw/` + `run.jsonl` |

### 流程控制规则（五条）

1. **唯一顺序依赖是 E1 → E3。** 抠图必须在七路渲染前完成，且只做一次。这是全链路唯一的"必须串行"点。
2. **E3 内部七路无依赖。** 可串可并。因为只有位置 4 调模型，实际耗时 ≈ 抠图 26s + 生成 70s + 装配数秒 ≈ **2 分钟**。
3. **失败隔离按层级分。** E1 失败 = 全局失败（没有主体，七路全废）；E3/E4 单路失败 = 局部失败（写日志继续，其余六路照常交付）。
4. **重做 = 重放 plan 第 k 条。** 只重跑 E3(k) → E4(k) → E5，不重新规划、不重新抠图。改文案只动 `plan.json` 的 `callouts`，`subject.png` 一个字节都不变。
5. **落盘边界 = 可复现边界。** 落盘的是 `subject.png` / `plan.json` / 日志 —— 这三样决定了能不能重做、能不能断言、能不能算钱。其余中间产物（canvas / composed）只作调试用。

## 11. 新增项准入判据

用来挡范围膨胀。任何要加进这个系统的功能，先问一句：

> **它是在扩大「事实保真」，还是在扩大「呈现能力」？**

- 扩大事实保真（更强的主体保真、更准的文字渲染、更严的合规检测）→ **属于能力，做**
- 扩大呈现能力（更多场景、更多版式、跨站点本地化）→ **属于能力，做**
- **都不是** → 它是外壳（权限、审批流、历史列表、仪表盘），**推迟**

**两者都不扩大，就不是这个系统在进化，只是它在变胖。**
