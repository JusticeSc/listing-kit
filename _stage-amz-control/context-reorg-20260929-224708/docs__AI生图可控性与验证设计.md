# AI 生图 · 可控性与验证设计

> CONTROL-STATUS: to-delete · AUTHORITY: none

> **本文只回答四件事**：① 商品图的要求到底是什么；② 用 AI 生成时能控什么；③ 一次运行怎么组织模板；④ 人在哪介入、生成后怎么验。

## 0. 问题定准

| 项 | 内容 |
|---|---|
| **目标** | 一个商品 → 一整套**可直接上架**的商品图（主图 1 + 副图 N） |
| **已知条件** | ① **产品实物**（可拍）② **产品介绍 / 规格参数**（卖家提供） |
| **未知（须设计）** | 每张图要什么 / AI 能控什么 / 模板怎么组 / 人在哪介入 / 生成后怎么验 |

**这两个已知条件就是全部的事实来源**，它们对应两样东西：

```
产品实物 ──拍摄──► 主体像素  ─┐
                              ├─► 成品图
规格参数 ──文案──► 文字断言  ─┘
```

**任何一件成品图，内容要么来自这两样，要么来自"环境"（无事实责任）。第三条路不存在。** 这是全文所有取舍的根据。

## 1. 商品图的要求

### 1.1 主图：规则密集，自由度 ≈ 0

【官方】亚马逊主图硬规则：

| 项 | 要求 |
|---|---|
| 背景 | 纯白 RGB(255,255,255) |
| 商品占比 | ≥ 85% |
| 构图 | 完整、不裁切、单件（多件装除外） |
| 禁止 | 文字 / Logo / 水印 / 边框 / badge / 道具 / 非售卖配件 |
| 素材类型 | 必须实拍或真实渲染，**禁插画** |
| 尺寸 | 最长边 ≥1000px（≥1600px 才启用放大镜；推荐 1600–2000） |
| 比例 | 1:1 |
| 色彩 | sRGB（CMYK 会偏色，且可能上传失败） |
| 格式 | JPEG / PNG / TIFF / GIF，≤10MB |
| 文件名 | **必须含产品标识**（UPC / EAN / ISBN / JAN） |
| 类目例外 | 成衣→模特上身；童装→平铺无模特；鞋→单只、左向、45°；服饰配件→平铺无模特 |

**结论（技术含义）：主图的自由度为零。它要的不是"画一张好看的图"，是"把实物干净居中地呈现出来"。**

→ 因此**主图不应走生成路线**。它是一条确定性管线：

```
实拍原图 → 抠图 → 摆位（占比校准）→ 纯白画布 → 1:1 → 尺寸 → 命名
```

这条链上没有任何一步需要概率模型。用生成模型做白底图 = 用概率工具做确定性任务，收益为零、风险为正。

### 1.2 副图：分用途，自由度分层

| 位 | 用途 | 必须说清什么 | 主体从哪来 | 背景 | 允许文字 |
|---|---|---|---|---|---|
| 2 | 核心卖点 | 好在哪（3–5 条） | 实拍 | 纯色/浅底 | ✅ |
| 3 | 尺寸规格 | 多大、多重、什么材质 | 实拍 | 纯色底 | ✅ |
| 4 | 使用场景 | 用起来什么样 | 实拍 | **场景（可生成）** | ✅ |
| 5 | 细节材质 | 做工如何 | 实拍裁切 | 无需 | ✅ |
| 6 | 包装内容物 | 买回来有什么 | 实拍 | 纯色底 | ✅ |
| 7 | 对比 | 比竞品强在哪 | 实拍 + 竞品图 | 纯色底 | ✅ |

**副图的自由度要拆成两种，不能混：**

| 自由度类型 | 内容 | 谁来定 | AI 可否代劳 |
|---|---|---|---|
| **内容自由度**（说什么） | 卖点、规格数字、对比项 | **卖家** | ❌ 不许（是断言，错了=虚假宣传） |
| **画面自由度**（怎么画） | 环境、氛围、光影 | 无人担责 | ✅ 可以 |

→ 副图里**只有位置 4 的场景/背景属于"画面自由度"**。其余五张的画面是纯色底或裁切，都不需要生成。

## 2. 人工正常流程（作为基线）

### 2.1 拍摄：一次拍，拍成"素材池"

关键认识：**拍摄不是"为某一张图拍"，是建一个池子，后面所有图从池里取。**

| 拍什么 | 供给哪张图 |
|---|---|
| 白底多角度（正/侧/背/45°/俯） | 主图、位置 2、3、6、7 的**主体来源** |
| 真实使用场景 | 位置 4 |
| 材质/工艺特写 | 位置 5 |
| 开箱、配件平铺 | 位置 6 |

**这一步的性质：唯一事实来源。** 系统对原片的态度是**只读、锁定、不改写**——一"美化"，事实就丢了。
（缺角度只能补拍；反光/指纹/色偏后期可修，因为它们是噪声不是事实。）

### 2.2 文案：按图位分派，不是写一段通稿

**这是"模板"的由来**——文案天然是分槽位的：

| 位 | 文案形态 | 示例 | 字数约束 |
|---|---|---|---|
| 2 | 3–5 条短句，每条配一个图标 | "12 小时保温" / "防漏杯盖" / "车载适配" | 每条 ≤8 字最优 |
| 3 | 数字 + 单位 | 500 ml / 8.5 in / 320 g / 304 不锈钢 | 短 |
| 4 | 一句场景描述（也可无字） | "办公室桌面随手可及" | 一句 |
| 5 | 一句工艺说明 | "304 不锈钢内胆，一体成型" | 一句 |
| 6 | 清单式 | 1× 杯身 / 1× 杯盖 / 1× 说明书 | 短 |
| 7 | 对比项 × 两列 | 保温时长：12h vs 6h | 短 |

→ **每张图的文案槽位数是固定的，内容由卖家填。** 这与"模板"是同一件事的两面。

## 3. AI 生成：能控制什么

### 3.1 先分技术栈 —— 参数不是同一批（**本节是全文关键**）

你列的那批参数（步数/采样器/VAE/强度/种子…）**属于本地 Stable Diffusion / ComfyUI 生态**。走云端 API 时，厂商只暴露一部分。**这是方向性决策，先定它，再谈调参。**

| 控制变量 | 本地栈（SDXL/Flux + ComfyUI） | 云 API（通义万相 / qwen-image） | 对**商品图**的影响 |
|---|---|---|---|
| **模型 ckpt** | ✅ 任意换 | 只能选厂商给的那几个 | 画风与能力上限 |
| **VAE** | ✅ | ❌ | 色彩/细节（次要） |
| **采样器 sampler / scheduler** | ✅ | ❌ | 画质微差（次要） |
| **步数 steps** | ✅ | ❌ | 画质（次要） |
| **CFG scale** | ✅ | ❌ | 提示词服从度 |
| **随机种子 seed** | ✅ | 部分支持 | **可否复现 —— 决定性** |
| **参考图**（img2img / ControlNet / IP-Adapter） | ✅ 全支持 | 仅有图生图 / 图像编辑端点 | **主体像不像 —— 决定性** |
| **强度**（denoising strength / ControlNet weight） | ✅ | 部分端点有 | **主体保留多少 —— 决定性** |
| **正向提示词** | ✅ | ✅ | 场景 / 风格 |
| **负向提示词** | ✅ | ✅（`negative_prompt`，≤500 字符【实测】） | 排除项 |
| **尺寸 / 分辨率** | ✅ | ✅（`size`【实测】） | 合规（须 1600×1600） |
| **数量 n** | ✅ | ✅ | 挑图成本 |
| — | — | `prompt_extend`（会改写提示词，**破坏可复现**）【实测】 | 坑 |
| — | — | `watermark`（须关掉）【实测】 | 合规 |
| **LoRA** | ✅ | ❌ | 主体/风格微调 |

**两条硬结论：**

1. **要控全这批参数，必须本地部署 SD 系。走 API 就只能控提示词 / 尺寸 / 负向词 /（部分）种子。**
2. **API 方案的"可控性上限"由厂商决定**，不是你调出来的。这一点在选型时就要认。

### 3.2 把参数分两类 —— 只有一类决定成败

| 类别 | 参数 | 作用 |
|---|---|---|
| **事实类** | 参考图、强度、seed | **决定商品像不像** |
| **画质类** | 采样器、步数、VAE、CFG | 决定画面好不好看 |

> **商品图的成败由"事实类"决定。画质类调得再好，主体不像就是废图。**

**这解释了一件事**：在这类任务上堆"采样器调优 / 步数调优"收益极低——那些是给艺术创作用的旋钮，不是给"这件商品长什么样"用的。

### 3.3 真正的关键：参考图，以及"让不让模型碰主体"

要让模型"认识这个商品"，有四条路，**本质完全不同**：

| 方案 | 机制 | 主体保真度 | 致命处 |
|---|---|---|---|
| **① img2img + 强度** | 拿实拍图当底重绘 | 低 → 中 | 强度高 → 主体变样；强度低 → 背景改不动。**这是个死结** |
| **② ControlNet** | canny/depth/seg 锁轮廓 | 中 | 轮廓锁得住，**纹理与颜色仍会漂** |
| **③ IP-Adapter** | 参考图作"主体/风格提示" | 中 | 仍是"参考"，**不是保证** |
| **④ 主体不进模型** | 模型只画**空背景**，主体事后确定性贴入 | **绝对保真** | 接缝要处理（光影/色温/接触阴影） |

【实测】支撑：同一提示词连跑三次，产出三个**形态级**不同的杯型（银灰细筒 / 深灰带腰线 / 纯白粗筒）。**说明 ①②③ 的"像"始终是概率，不是保证。**

> **只有 ④ 是"不让模型碰主体"，前三个都是"让模型尽量画得像"。**
> **商品图是事实断言，不是艺术创作 → 选 ④。**

方案 ④ 的代价是**接缝**，它的三个失败模式与对策：

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 悬浮感 | 主体像飘在背景上 | 补接触阴影 |
| 光照错位 | 光源方向/色温不一致 | 背景迁就主体（主体是事实，不能改） |
| 尺度错位 | 主体与场景比例不对 | 约束背景的构图描述 + 摆位校准 |

**原则：接缝不能靠改主体解决，只能靠约束背景 + 后处理弥合。**

### 3.4 可复现性：一个必须堵的漏洞

【实测】`prompt_extend=true` 时，服务端会**改写你的提示词**。于是：

- plan 里记的是改写**前**的提示词
- 实际执行的是改写**后**的版本
- → **"同输入同输出"不成立**

**处置**：要可复现，就关掉 `prompt_extend`，并显式传 `seed`。否则"重放 plan 第 k 条"这句话是空的。

## 4. 一次运行 × 多套模板

**能，而且这正是"七张"的实现方式。**

### 4.1 模板 = 坑位 × 参数组

| 模板字段 | 内容 | 例子（位置 4 场景图） |
|---|---|---|
| 用途 | 这张讲什么 | 使用场景 |
| 主体来源 | 从哪取 | `subject.png`（共享） |
| 背景类型 | white / solid / generated / crop | `generated` |
| 正向提示词 | 只描述**背景** | "warm home office desk, morning window light, soft shadow, copy space on right" |
| 负向提示词 | **无条件排除产品本体** | product, item, bottle, cup, container, packaging, logo, watermark, text |
| 尺寸 | 输出规格 | 1600×1600 |
| 主体摆位 | 位置/占比 | 居中偏左，占比 60% |
| 文案槽位 | 要几条、每条几个字 | 1 条 ≤12 字 |
| 是否叠字 | overlay / none | overlay |

**模板是控制面资产**（一次定义，长期复用）。**plan 是数据面**（每个商品实例化一次）。

### 4.2 一次运行的结构

```
一个商品 → 载入模板表 → 逐坑位实例化 plan → 扇出 N 路 → 收敛
```

**关键：N 路之间无依赖**，所以可串行也可并行。总耗时 ≈ 最慢那一路（位置 4，约 70s【实测】）。

**"一次运行设不同模板"在实现上就是遍历坑位表**——不需要额外机制。

### 4.3 成本与耗时（【实测】量级）

| 环节 | 耗时 | 调用次数 |
|---|---|---|
| 抠图（BiRefNet 本地） | ~27s | 0（本地模型） |
| 位置 4 背景生成（qwen-image-3.0） | ~66–70s | **1** |
| 其余六路（合成/裁切/叠字） | 每路 <2s | 0 |
| **合计** | **≈ 2 分钟** | **1 次** |

## 5. 人在哪几个环节介入

原则：**人只做两件事——提供事实、做判断。凡"手艺重复"，都不该由人做。**

| # | 环节 | 人做什么 | 不做的后果 |
|---|---|---|---|
| 1 | 商品事实录入 | 给规格数字 + 卖点文案 | 模型只能编 → **虚假宣传** |
| 2 | 原图体检 | 确认无水印/无道具/角度够 | 废输入，下游全废 |
| 3 | 模板选择 | 这个类目用哪套、要不要位置 7 | 跑偏 |
| 4 | 挑图 / 重做 | 采纳 or 指出哪层要改 | 废图流出 |
| 5 | 最终合规复核 | 主图白底/占比/文件名 | 下架 |

**人明确不该介入的**：PS 式精修、逐张调参、手工裁切。**一旦允许这些，工具就退化成"更慢的 PS"。**

**重做的粒度必须与"层"对齐**（这是设计里最省事的一处）：

| 改什么 | 成本 | 动哪一层 |
|---|---|---|
| 文案不对 | 0.1s，免费 | 文字层 |
| 位置 / 大小不对 | 1s，免费 | 合成层 |
| 背景不对 | ~70s + 1 次调用 | 背景层 |

**强制三选一 = 零成本的归因数据**（不用额外加"请填原因"的表单）。

## 6. 生成之后怎么验证

### 6.1 验证能力只取决于两样东西

| | **有规则** | **无规则** |
|---|---|---|
| **有参照物** | ✅ **可全自动验**：尺寸 / 白底纯度 / 占比 / 文件名 / 格式 —— 对着规格算 | ⚠️ **可半自动**：主体与原图的相似度（变形、串色）—— 对着 `subject.png` 算 |
| **无参照物** | ✅ **可自动验**：sRGB / 文字块存在性 | ❌ **只能人工**：好不好看 / 文案有没有说谎 |

**这张四象限就是验证问题的全部。** 任何"我们做了自动校验"的说法，先问它落在哪一格。

### 6.2 分层设计

| 层 | 验什么 | 手段 | 强度 |
|---|---|---|---|
| **L1 硬规则** | 尺寸 / 白底 RGB / 占比 / 格式 / 文件名 / 水印 | 像素级程序判定 | 位置 1 **零容忍** |
| **L2 主体一致性** | 是否与实物一致 | 与 `subject.png` 比对（色差 / 结构相似度） | 高 |
| **L3 文字正确性** | 有没有错字 | OCR 与文案原文比对 | 高 |
| **L4 语义** | 是不是这个商品 / 文案有没有虚构 | **人工** | — |

【实测】已知的 L1 假阳性陷阱：抠图失败时，四边留白是画布补的，边缘类校验会**"假通过"**。→ 必须加 `alpha 前景覆盖率` 检查（覆盖率过高 = 抠图失败）。

### 6.3 最要紧的一条

> **能自动验证的程度，取决于你把多少东西变成了确定性的。**

| 做法 | 验证负担 |
|---|---|
| 主体经过模型生成 | L2 必须验，而且**验不可靠**（相似度是概率判断） |
| **主体不经过模型** | L2 从"要验"变成 **结构上不可能错** |
| 文字交给模型画 | L3 必须验，中文零容错（未/末、己/已） |
| **文字用代码叠** | L3 从"要验"变成 **必然正确** |

**所以验证策略不是"多加校验器"，是"减少需要验证的东西"。**

这也是三层分离的真正收益：**它把两类最贵最难验的风险，直接变成了不存在。**

## 7. 结论

1. **一张商品图 = 主体（确定性）+ 背景（可生成）+ 文字（确定性）+ 排版（确定性）**
2. **模型的合法作用域只有"背景"**，且七张里**只有位置 4 真正需要生成**（位置 1 走确定性合成，2/3/5/6/7 走纯色底/裁切 + 叠字）
3. **参数里真正决定成败的只有三个**：参考图（且必须"主体不进模型"）、seed（可复现）、尺寸（合规）。其余是画质旋钮，对本任务**边际收益极低，不投入**
4. **选型前置问题**：要控全参数 → 本地 SD 栈；只控提示词/尺寸 → 云 API。**这个决定在写代码之前就要拍板**
5. **人工只做两件事**：提供事实（规格/文案）、做判断（挑图/重做）。其余全部自动化
6. **验证不是加校验器，是减少待验项**——主体与文字不经过模型，就等于把最贵的两项风险从"要验"变成"不存在"
