## 0. 先回答一个问题：AI 生成的方案，哪些能信

你问得对：`vison` 里那批文档、以及我前几轮给的方案，**都是生成物**。所以不能凭"读起来专业"就采信。

### 0.1 一条判据

> **一个主张可信，当且仅当它能从「人工现况」这个已知事实上独立推导出来。**

这条判据把主张切成两类：

| 类型 | 例子 | 能否从人工流程推出 | 处置 |
|---|---|---|---|
| **结构性主张** | "主体只有一份，七张图共用" | **能** —— 人工做图时主体就是同一个实物 | 采信 |
| | "模型只能画无人承担事实责任的部分（环境）" | **能** —— 人工搭背景时无人在做事实承诺 | 采信 |
| | "文字必须由卖家给，工具不能编" | **能** —— 人工写卖点也是运营定稿的 | 采信 |
| **世界状态主张** | "qwen-image 的端点是 `/text2image/...`" | **不能** —— 与人工流程无关，是外部系统的事实 | **必须实测** |
| | "平台主图最小 1000×1000px" | **不能** —— 平台规则是外部事实 | **查官方** |
| | "行业出图成功率 85%" | **不能** | 查不到出处 = 不采信 |

判据的锋利之处：它给了**验证路径**。"主体只有一份"这条，你不需要查任何资料——想想人工是怎么干的就知道了。而"端点是什么"，想一万遍也没用，只能跑一次。

### 0.2 实测抽查：`vison` 三份文件

**`providers.md` —— 幻觉，作废。** 证据：

| 文中写法 | 实际 | 
|---|---|
| `gpt-image-1.5`、`gemini-3.1-flash-image-preview`、`wan2.7-image-pro` | 模型名不存在 |
| `doubao-seedream-4-5-251128` | `251128` 是未来日期 |
| 千问端点 `/services/aigc/text2image/image-synthesis` + `qwen-image-2.0-pro` | **与【实测】不符** —— 实测是 `/services/aigc/image-generation/generation` + `qwen-image-3.0` + messages 结构 |

**`image-types.md` —— 混合。** 三处硬伤：

1. **文内自相矛盾**：一边写「场景必须来自商品分析的 `target_scenes`，绝不写死」，一边所有 Prompt 写死「阳光校园草坪 / 帆布包 / 年轻中国面孔女性模特」。
2. **要求 `Render all specified text labels directly into the image`** —— 这正是【实测】过不可控、不可复现的 native 文字；且**文生图模型不认识 px**，「42px size」是把 Canvas 的指令误塞进 Prompt。
3. **与自家 `providers.md` 打架**：后者末尾明明写着「Canvas 文案叠加规范」（确定性叠字），前者却全线要求模型直出文字。

**`platforms.md` —— 大体可用，有精度错。** 对照平台官方页：

| 文档 | 官方 | 判定 |
|---|---|---|
| 纯白底 RGB 255,255,255 | 一致【官方】 | ✅ |
| 商品占比 ≥85% | 一致【官方】 | ✅ |
| 「最小 1000×1000px」 | **最长边** ≥1000px 才启用缩放 | ⚠️ 精度错 |
| 「附图最多 9 张」 | 官方帖未给此数，随类目/变体变 | ⚠️ 来源不明 |
| 主图禁文字/水印/标识 | 一致【官方】 | ✅ |

### 0.3 更要紧的一件事：我们自己那份文档站得住吗

`架构设计.md` §2 的核心判据是「**模型只能创作它不承担事实责任的部分**」。**它是结构性主张**，能从人工流程独立推出（见 §4.3）——所以它是对的，与是谁写的无关。

**结论：判断主体是「能不能从人工现况推出来」，不是「像不像专业文档」。** 术语密度高 ≠ 事实为真。这也是本文为什么必须从人工流程写起。

## 1. 人工是怎么做的

先把**边界**和**性质**说清楚，再讲步骤。因为步骤会随人和类目变，性质不会。

### 1.0 这份工作的两层与三种劳动

**两层。** 「人工的工作」指的是**上架一个商品**（选品 → 写文案 → 做图 → 上传合规 → 看数据迭代）；「做图」只是其中一环。本文只谈这一环 —— 它是唯一能被工具整体吃掉的一段。

**三种劳动。** 「做图」这一环的性质，不是"创作"，是**复制作业**。拆开只有三件事：

| 劳动 | 干什么 | 一套七张图里的次数 | 性质 |
|---|---|---|---|
| **取真** | 拍、抠 —— 让实物的像进入图里 | 拍 1 次 ＋ **抠 8 次** | 唯一提供事实的一层 |
| **编排** | 摆位 / 背景 / 文字 / 标注 | 摆 7 次 ＋ **打字 6 次** ＋ 找背景 7 次 | 不涉事实的设计劳动 |
| **判断** | 够不够大 / 像不像真的 / 要不要重做 | **1 次** | 人独有，不可复制 |

**为什么必然重复** —— 这条不依赖任何具体数字，可从「七张图共用同一个实物」直接推出：

> 每张图都是一张**独立的扁平位图**，主体层与文字层不落盘。所以做第二张时，「第一张已经抠好的主体」和「已经定稿的文字」**一个字都继承不过来**，只能从头再来。

后面所有设计只需问一句：**这三种劳动，各自该由谁来做？**

> 以下流程是**亚马逊北美站、一个新品上架**的通行做法。`【推断】` 标在可推处处，涉及具体数字/角色分工处标 `【待确认】` —— **你才是这行的第一手信源，本文请你逐条校正。**

### 1.1 参与角色【待确认】

| 角色 | 干什么 | 是否常外包 |
|---|---|---|
| 运营 | 选品、写 listing、上传、看数据、改图 | 否（owner） |
| 摄影 | 拍原片 | 常外包 |
| 美工 / 设计 | 抠图、修图、排版、出七张 | 常外包（也可运营自己用 PS/Canva） |

小卖家常见形态：**运营一人分饰三角**，摄影外包、设计自己顶。这也解释了为什么"提效"对这个岗位是真需求。

### 1.2 现场：一个保温杯，从拿到手到上架

先说人。小卖家最常见的形态是**运营一个人全包** —— 他不是设计师，工具是 Photoshop 或 Canva，手上同时挂着好几个商品，摄影可能外包，也可能拿手机加一块白背景布自己拍。**后面所有环节的耗时，都发生在这一个人身上。**

**第 0 天 · 拿到杯子**

供应商寄来样品，或者只发几张照片。手上有一只杯子（或几张图）+ 一份供应商资料（Excel：容量 500 ml / 304 不锈钢 / 保温 12 小时）。**但供应商给的数字不一定可信，得自己验。**

**第 1 天 · 想清楚"它好在哪"（这一步不碰 PS）**

- 打开卖得最好的竞品页，看人家的五点描述怎么写
- 定自己的卖点："12 小时保温""防漏杯盖""适配车载杯架"
- 量尺寸、称重、确认材质

**产出两样东西：一段段文字 + 一张规格表。**

> 写下的每个字都是他对商品的**承诺**。"12 小时保温"没实测过就写上去，是虚假宣传。**这就是为什么工具不能帮他编文案。**

**第 2 天 · 拍**

他脑子里已经知道要做哪几张图，所以知道要拍什么：

- 白底正面 / 侧面 / 背面 / 45°（后面所有图的"主体料"）
- 桌面、办公室、车里（场景图素材）
- 杯盖螺纹、不锈钢杯身（细节图）
- 杯子 + 包装盒 + 说明书摆一起（内容物图）

拍 30 张左右，回来挑。

**先纠正一个说法：这一步不是"不可逆"——随时可以重拍。** 它真正的性质是 **「唯一事实来源」**：杯子长什么样，只有原片见过；系统没有第二条途径拿到这份事实，也无权替它编。

那反光、指纹、拍歪算不算"救不回来"？**算，但它们是可修的**——后期能压反光、能修掉指纹，而且修完反而更接近事实（这些是噪声，不是事实）。真正修不出来的是**缺角度、缺背面**，那只能补拍。

所以工具救不回的不是"拍照"，是**"没拍到的那个角度"**。

**第 3–4 天 · 做图（真正的战场）**

主图，他实际在干这些：

1. 打开白底原片 → **魔棒工具点背景 → 删除**；杯盖螺纹那里选不干净，得用钢笔沿边缘描一遍
2. 新建 1600×1600 纯白画布
3. 把抠好的杯子拖进去 → 缩放 → **目测**让它占 85%（他也不知道准不准）
4. 导出 JPG，文件名带上 UPC（平台硬性要求）

然后开始卖点图：

1. **再抠一遍** —— 主图那张已经导出成扁平 JPG 了
2. 铺浅灰底，杯子缩小靠左
3. 去图标网站找三个图标拖进来
4. 打字："12 小时保温""防漏设计""车载适配"
5. 调字号、行距、对齐 → 导出

规格图：**再抠一遍** → 画两端带箭头的标注线 → 标 8.5 in / 3.2 in / 500 ml。

场景图（七张里最贵的一张）：

- 找背景 —— 图库下载、自己补拍一张办公桌、或用 AI 生成，**光这一步就花掉大半天**
- **再抠一遍** → 贴上去 → **看着假**
- 因为还得补三样：光的方向（背景是窗光、杯子是顶光）、色温（背景偏暖、杯子偏冷）、接触阴影（不然杯子像飘在桌上）
- 然后才能打字

细节图：不抠，直接裁一刀 → 打字 → 导出。
内容物图：**再抠一遍**（杯子 + 盒子 + 说明书的合照）→ 铺底 → 打字 → 导出。
对比图：抠自己的杯子 + 抠竞品的杯子（从竞品页截图抠）→ 并排 → 加 OURS / OTHERS → 导出。

**第 4 天末尾 · 自查上传**

- 主图是纯白吗？拿吸管点一下，看是不是 255,255,255
- 最长边够 1000px 吗？
- 文件名带 UPC 了吗？
- 上传后台，提交

**之后 · 看数据改图**

一周后看点击率和转化率。如果转化低，猜"是不是场景图不行" → 重做那一张 → 重传。

### 1.3 七张图为什么是这七张

七张不是谁拍脑袋定的，是**买家从"看到"到"下单"要问完的七个问题**：

| # | 买家的疑问 | 对应图 | 出现在哪 |
|---|---|---|---|
| 1 | 这是什么东西？ | 主图 | **搜索结果页 —— 和几十个竞品并排** |
| 2 | 它好在哪？ | 卖点图 | 详情页，点进来第一眼 |
| 3 | 多大？放得下吗？ | 规格图 | 详情页 |
| 4 | 我用起来什么样？ | 场景图 | 详情页 |
| 5 | 做工怎么样？ | 细节图 | 详情页 |
| 6 | 买回来有什么？ | 内容物图 | 详情页 |
| 7 | 比别的强在哪？ | 对比图 | 详情页，犹豫时最后推一把 |

**这里有个关键区别**：位置 1 在搜索结果页，**和别的商品并排**；位置 2–7 在详情页，**独占整个屏幕**。

这一条解释了"为什么主图必须纯白无文字" —— **不是审美，是搜索结果页要视觉统一**，平台不允许你用花哨的图抢流量。也解释了为什么副图可以尽情堆文字、图标、信息图。

### 1.4 五个阶段（速查）

```
阶段 A 备料          阶段 B 拍摄          阶段 C 设计           阶段 D 上传      阶段 E 迭代
（运营 + 供应商）    （摄影）            （美工）              （运营）         （运营）
──────────────────────────────────────────────────────────────────────────────────────►
 商品事实            原片库              七张成品图            在售列表         改图重传
 A1 定商品           B1 白底原片         C1 挑七张             D1 后台填 UPC    E1 看 CTR/转化
 A2 写文案           B2 场景图           C2 逐张制作 ×7        D2 合规自查      E2 定位问题图
 A3 定规格           B3 细节图           C3 逐张定稿           D3 提交          E3 改图 ──┐
                     B4 包装/内容物                                                  │
                                                                              ┌──────┘
                                                                              └► 回到 C
```

**阶段 A · 备料**（产出：商品事实）

| 步 | 输入 | 处理 | 输出 |
|---|---|---|---|
| A1 | 供应商样品 / 竞品调研 | 选定要上的商品 | 商品实物 + 类目 |
| A2 | 供应商资料 + 市场调研 + 竞品 listing | 写标题、五点描述、A+ 文案、卖点 | **文案包**（文字断言都在这里） |
| A3 | 供应商规格书 / 自己实测 | 量尺寸、称重、确认材质型号 | **规格表** |

> **这一阶段最重要的性质**：A2/A3 产出的每一个字，都是卖家对商品的**断言**。"保温 24 小时"如果没测过就写上去，是虚假宣传。**所以文案不能由工具编。**

**阶段 B · 拍摄**（产出：像素素材）

| 步 | 拍什么 | 用途 |
|---|---|---|
| B1 | 白底原片，多角度（正/侧/背/45°/俯视） | 主图、卖点图、规格图的**主体来源** |
| B2 | 真实使用场景 | 场景图 |
| B3 | 材质 / 工艺特写 | 细节图 |
| B4 | 开箱、配件平铺 | 内容物图 |

通常拍 20–50 张，后期挑 7 张用。【待确认：实际拍多少张？】

> **这一阶段决定上限。** 但性质要说准：它是**「唯一事实来源」**，不是"不可逆的一段"。
>
> | 情况 | 能不能救 | 为什么 |
> |---|---|---|
> | 反光 / 指纹 / 拍歪 / 色偏 | **能**（后期修） | 是噪声不是事实，修掉更接近事实 |
> | 缺角度 / 缺背面 / 缺细节 | **不能**（只能补拍） | 事实压根没被记录过，凭空补=编 |
> | 实物已不在手上（样品退回、批次变了） | **真正不可逆** | 连"补拍"这条路都断了 |
>
> 结论：系统对原片的态度是**只读、锁死、不可改写**——不是因为原片不可再生，而是因为它是商品事实的**唯一权威**。系统一旦"美化"它，事实就丢了。

**阶段 C · 设计**（核心工作量）

| 步 | 做什么 |
|---|---|
| C1 | 从原片库挑出 7 张（主图必须白底） |
| C2 | 逐张制作 —— 抠图、修图、调色、搭背景、排文字、拉标注线 |
| C3 | 逐张定稿、导出 |

七张的通行分工：

| 图 | 内容 | 主体从哪来 | 背景怎么来 | 有文字吗 |
|---|---|---|---|---|
| 1 主图 | 商品孤立、纯白 | 实拍抠图 | 纯白，不画 | **无**（平台禁） |
| 2 卖点 | 商品 + 图标 + 卖点 | 实拍抠图 | 纯色/浅色底 | 有 |
| 3 规格 | 商品 + 尺寸标注线 | 实拍抠图 | 纯色底 | 有 |
| 4 场景 | 商品在使用场景里 | 实拍抠图 | **搭/找场景** | 有 |
| 5 细节 | 材质特写 | 实拍裁切 | 无（本身即特写） | 有 |
| 6 内容物 | 开箱 / 配件平铺 | 实拍合照 | 纯色底 | 有 |
| 7 对比 | 本品 vs 竞品 | 实拍抠图 + 竞品图 | 纯色底 | 有 |

**阶段 D · 上传**

后台填 UPC/SKU → 合规自查（主图纯白无文字、最长边 ≥1000px【官方】）→ 提交。

**阶段 E · 迭代**

看 CTR / 转化 → 定位是哪张图拖后腿 → 改图重传 → 回到阶段 C。

### 1.5 依赖关系：谁等谁

```
   A（商品事实）──┐
                  ├──► C（设计）──► D（上传）──► E（迭代）──┐
   B（原片库）  ──┘                                        │
                  ◄────────────────────────────────────────┘
                              （改图后重传）
```

两条关键性质：

1. **A 与 B 可并行**（一个写文案、一个拍图），但**都必须在 C 之前完成**。
2. **C 内部的七张图互相独立** —— 谁先谁后都可以，这决定了系统里七路天然可并行（呼应 `架构设计.md` §10 的流程控制规则 2）。

### 1.6 人工的另一种做法：直接用 AI 生图 —— **这才是面试现状**

> **面试官原话**（`03_transcript_corrected.md` 04:50—05:26，逐字）：
> "……我原来的布局是**我上传一张产品图片**让他帮我（生成），然后**上传一段（提示）词**让他帮我生成一个图文的**第一张图**，然后**再加上第二张图片**，让他帮我生成图文的**第二张图**……图文视频一般要**七张图**。**很重复。**"
>
> 补充（05:43—05:52）："再提供一些**参考链接**……然后你根据这些**产品卖点和这个商品图**，帮我直接（出）**七张可以发布图文的**……符合我要求的一些（素材）。"

**关键：这不是"美工做图"，是"一个人跟模型来回对话，一次产一张"。** 前文 §1.2 讲的美工流程是**另一种形态**，两者要分开——面试官要自动化的是**这一种**。

动作级拆解：

| # | 动作 |
|---|---|
| 1 | 打开生图工具（网页 / API）；手上有三样：**产品图 + 卖点文案 + 参考链接** |
| 2 | 上传产品图 → 写一段提示词 → 生成**第 1 张** |
| 3 | 看结果 → 不满意改提示词 → 再生成（常来 2–3 轮）→ 挑一张 |
| 4 | **把已有图再一起加进去** → 改提示词 → 生成**第 2 张** |
| 5 | 重复第 4 步，直到**第 7 张** |
| 6 | 手工收尾：裁尺寸、补白底、P 掉多余元素、**加文字**（模型画的字不敢直接用） |
| 7 | 按合规自查（主图纯白 / ≥1000px / 无字）→ 上传 → 隔周看数据、改图重传 |

**这套流程的病**（对应原话"很重复"）：

| 病 | 表现 |
|---|---|
| **重复** | 七张 = 七轮"传图 + 写词 + 等 + 挑"，每轮动作一模一样 |
| **上下文不共享** | 一轮生成完就断了，下一轮**从零开始** → 七张容易雷同或跑偏 |
| **产品不可复现** | 每次生成的产品**都不一样**（本机实测：同一提示词三次出三个杯型）→ 七张图里可能**不是同一个商品** |
| **文字不可控** | 模型画字会错、会自己编（实测自作主张画上 `THERMO` 品牌名） |
| **合规靠手工** | 白底、尺寸、占比，模型不管，得自己补 |
| **成本不固定** | 实际调用次数 = 张数 × 试错轮数 |

**与传统美工形态的一句话对比**：

> **传统美工**：主体是**拍**出来的 → 七张天然是同一个商品，毛病是**慢**。
> **AI 生图**：主体是**画**出来的 → 七张可能变成七个商品，毛病是**不可信**。

**所以面试官要的工具，准确表述是**：把"人工生图的七轮循环"换成**一次任务**。

**但注意一个陷阱 —— 不能只是把循环自动化。** 循环本身带着上面那个病（产品不可复现）。**顺序必须是：先把主体从模型手里拿出来（实拍抠图 + 七路共享），再谈自动化。** 这就是后面所有设计的由来。

## 2. 人工流程的瓶颈在哪

不提瓶颈，提效就没有靶子。

### 2.1 四个瓶颈【推断】

| # | 瓶颈 | 表现 | 严重度 |
|---|---|---|---|
| 1 | **时间** | 熟练美工做一个商品的七张 ≈ 1–2 天【待确认】 | ⭐⭐⭐ |
| 2 | **成本** | 外包 ¥50–300/张【待确认】，改一次再付一次 | ⭐⭐⭐ |
| 3 | **返工** | 改一个字 → 整张重做（**文字是烧进像素里的**） | ⭐⭐⭐ |
| 4 | **一致性** | 七张图之间主体大小/角度/光线的对齐，靠**设计师肉眼** | ⭐⭐ |

### 2.2 返工的本质

人工做出来的图，是一张**扁平位图**。"保温 24 小时改 48 小时"这一个字的变化，在人工流程里的代价 = **重新打开源文件 → 改字 → 重新导出**（如果有分层源文件），或者**整张重做**（如果已经是导出图）。

**根源：文字和像素绑死了。** 这是"改字要重做整张"的全部原因。

### 2.3 一致性的本质

同一商品的七张图，主体应该在七张里看起来是**同一个东西**。人工怎么保证？靠设计师**记住**上一张长什么样，然后手工对齐大小和光位。

这是**手艺**，不是**机制**。换个设计师、隔一周再改，就漂了。而且它**无法被证明** —— 你只能说"看着像"，不能说"是同一个"。

## 3. 一张图到底由什么构成

这是整套提效设计的支点。人工做出来的每一张图，拆开都是四样东西。

### 3.1 四要素

```
一张成品图 = 主体 + 背景 + 文字 + 排版
              ↑       ↑      ↑       ↑
            实拍的   搭的   写的   套模板
```

| 要素 | 它是什么 | 人工从哪来 | **谁是事实的持有者** |
|---|---|---|---|
| **主体** | 商品长什么样 | 实拍抠图 | **原片** —— 唯一见过实物的东西 |
| **背景** | 处在什么场景、什么氛围 | 找图 / 生成 / 搭 | **没有人** —— 环境不是事实，是设计 |
| **文字** | 卖家对商品的断言 | 运营写的文案包 | **卖家** —— 只有他知道 |
| **排版** | 位置、字号、配色 | 设计规范 / 习惯 | 不涉及事实，是**规则** |

### 3.2 四要素的责任归属 → 决定了谁能碰

| 要素 | 错了会怎样 | 模型可否生成 | 根据 |
|---|---|---|---|
| 主体 | 实物不符 → 平台扣分 + 法律风险 | **否** | 它没见过实物，画出来的是**虚构事实** |
| 文字 | 虚假宣传 → 法律风险 | **否** | 它不知道商品真实性能，编出来是**虚构断言** |
| 背景 | 图不好看 → 只影响转化 | **是（全部）** | 环境不承载事实，谁画都不算撒谎 |
| 排版 | 不好看 | 不必 | 用规则做，可精确、可校验 |

> **这就是 `架构设计.md` §2.3 那条判据的人工版来源。** 它之所以成立，不是因为推导漂亮，而是因为**人工做图时的责任归属本来就是这样**——设计师不会自己编卖点，也不会把别人的产品 P 进来。系统只是把这个既定分工固化成了架构。

### 3.3 人工在这四件事上的成本，天差地别

| 要素 | 人工成本 | 可复现性 | 改一次 |
|---|---|---|---|
| 抠图 | 高（尤其毛发/透明/复杂边缘） | 手工艺 | 重抠 |
| **背景** | **最高（找图/合成/融合）** | 每次不同 | 重做整张 |
| 写文字 | 中（要想） | — | — |
| 排文字 | 中 | 手工艺 | 重排 |
| 对齐七张 | 高（肉眼） | 不可证明 | 全部重对 |

**读出来了吗**：人工成本最高的两块，一块是**重复劳动**（抠图做七遍），一块是**真正需要设计的部分**（搭背景）。而文字和排版本来是确定性的，却被烧进了位图。

## 4. 提效映射：人工环节 → 系统环节

### 4.1 逐环节映射

| 人工环节 | 性质 | 系统怎么接 | 为什么 |
|---|---|---|---|
| A1 定商品 | **判断** | 不接 | 选品是生意决策 |
| A2 写文案 | **断言** | **不接**，只要求输入 | 断言的持有者是人，工具编 = 虚假宣传 |
| A3 定规格 | **断言** | **不接**，只要求输入 | 同上 |
| B1–B4 拍摄 | **事实采集** | **不接**（但入口体检） | 工具修不了不合格的原片（水印压主体抠不掉） |
| C1 挑七张 | **判断** | 弱接（按坑位表分配） | 挑图是审美判断 |
| C2 抠图 | **重复劳动** | **接** —— 抠**一次**共享 | 同一主体抠七遍是纯浪费 |
| C2 搭背景 | **真正需要创造** | **接** —— 只在需要环境的坑位调模型 | 唯一该用模型的地方 |
| C2 写文字 | 断言 | 不接 | 见 A2 |
| C2 排文字 | **确定性** | **接** —— 字体文件绘制 | 可精确、可校验、改字 0.1s |
| C2 对齐一致性 | **手工艺** | **接** —— 数据约束（读同一个文件） | 从"肉眼对齐"变成"同一份资产" |
| C3 定稿 | 判断 | 弱接（校验 + 人工确认） | 最终审美由人定 |
| D 合规自查 | **规则** | **接** —— 分级校验 | 机器能验的机器验 |
| E 改图重传 | **返工** | **接** —— 重放 plan 第 k 条 | 改一个字不再重做整张 |

### 4.2 提效只有三个来源

| 来源 | 针对的瓶颈 | 做法 | 效果 |
|---|---|---|---|
| **共享** | 重复劳动 | 主体抠一次，七路读同一份 `subject.png` | 消掉 6 次重复抠图 |
| **解耦** | 返工 | 主体 / 背景 / 文字三层分离 | 改文字不动主体（0.1s，非 1 天） |
| **重放** | 返工 + 一致性 | `plan.json` 是唯一状态，改哪条重渲哪条 | 重做粒度 = 单张 |
| *（副产品）* **断言化** | 一致性 | 七路日志共享 `subject_hash` | "主体同一"从**感觉**变成**可校验** |

### 4.3 业务事务单位：一个商品 = 一次事务

人工的时间单位是"**一次上架**"，不是"一张图"。系统必须照抄这个单位：

| 维度 | 人工 | 系统 |
|---|---|---|
| 输入 | 商品事实（文案 + 规格）+ 原片库 | `inbox/<UPC>/`：原图 + 文案 +（可选竞品图） |
| 输出 | 七张成品图 | `out/<UPC>_<时间戳>/`：七张 + `plan.json` + 日志 |
| 失败单位 | 某一张图返工 | **单个坑位**失败，其余照常交付 |
| 重做单位 | 某一张图 | 重放 `plan` 第 k 条 |

> **"一次性为一个商品生成多张图" 这句话里的关节在"一次性"。**
> 不是"能生成一张图然后重复七次"，而是"**一次输入，一次产出整套**"。这决定了输入必须是商品包、输出必须是图集、失败必须可局部化。

### 4.4 只有一处调用模型

按 §3.2 的责任归属过滤后，七张图里**只有需要"环境"的坑位**才合法调用模型：

| 坑位 | 主体 | 背景 | 文字 | 调模型 |
|---|---|---|---|---|
| 1 主图 | 实拍抠图 | 纯白（平台硬规则【官方】） | 无 | **0** |
| 2 卖点 | 实拍抠图 | 纯色底 | 叠字 | 0 |
| 3 规格 | 实拍抠图 | 纯色底 | 叠字 + 标注 | 0 |
| 4 场景 | 实拍抠图 | **模型生成场景** | 叠字 | **1** |
| 5 细节 | 实拍裁切 | — | 叠字 | 0 |
| 6 内容物 | 实拍合照 | 纯色底 | 叠字 | 0 |
| 7 对比 | 实拍抠图 + 竞品图 | 纯色底 | 叠字 + 标注 | 0 |

**整条链路：7 次整张生成 → 1 次背景生成。**
"能用确定性做的，就不调模型" —— 因为调模型的每一处，都是一个**会失败、会漂移、要花钱、要等 70s** 的环节。

## 5. 系统的六个环节（从人工流程推出）

环节划分**不是重新发明**，是把 §4.1 的映射落成可执行的六步。与我们既有 `架构设计.md` §10 一致。

```
E0 收件体检 ──► E1 抠图（全局唯一一次）──► E2 规划 ──► E3 渲染 ×7 ──► E4 校验 ──► E5 交付
  │                    │                                │
  │              ★ 唯一共享资产                    ★ 唯一扇出点
  │              subject.png                      七路无依赖
  └ 拒收不合格输入
```

| 环节 | 对应人工哪一步 | 输入 | 处理 | 输出 | 失败 |
|---|---|---|---|---|---|
| **E0 收件** | D2 合规自查（前移）+ C1 挑图 | `inbox/<UPC>/`：原图 + 文案 + 竞品图 | UPC 校验 / 原图 ≥1000px / 文案非空 / **原图体检**（含文字水印？多件商品？） | `job` 或**拒收** | 拒收，不产生下游动作 |
| **E1 抠图** | C2 抠图（七次合一） | 原图 | 本地 BiRefNet 优先 → 抠图 → 算 bbox / 覆盖率 / `subject_hash` | `subject.png` + `subject.json` | **全局失败**（七路都靠它） |
| **E2 规划** | C1 挑图 + A2/A3 事实分配 | 文案 + `subject.json` + `slots.yaml` | 分配文案到坑位 / 排版参数 / **仅位置 4** 生成背景提示词 | `plan.json` | 无（纯确定性） |
| **E3 渲染 ×7** | C2 逐张制作 | plan 单条 + `subject.png` | E3a 造底 → E3b 贴主体 → E3c 叠字 | `final.jpg` 1600×1600 | **单路失败**，其余继续 |
| **E4 校验** | D2 合规自查 | `final.jpg` + 校验强度 | strict / medium / light | 写日志 | 不阻断交付，标 FAIL 交人工 |
| **E5 交付** | C3 定稿导出 | 七张 + plan + subject + 日志 | 按 `{UPC}_{序号}_{用途}.jpg` 命名 | `out/<UPC>_<微秒>/` | — |

### 五条流程控制规则

1. **唯一顺序依赖是 E1 → E3。** 抠图必须在七路渲染前完成，且只做一次。全链路唯一"必须串行"点。
2. **E3 七路无依赖。** 可串可并。只有位置 4 调模型 → 实际耗时 ≈ 抠图 26s + 生成 70s ≈ **2 分钟**。
3. **失败隔离按层级分。** E1 失败 = 全局失败；E3/E4 单路失败 = 局部失败（写日志继续）。
4. **重做 = 重放 plan 第 k 条。** 不重新规划、不重新抠图。改文案只动 `plan.json`，`subject.png` 一个字节不变。
5. **落盘边界 = 可复现边界。** 落盘的是 `subject.png` / `plan.json` / 日志 —— 这三样决定能不能重做、能不能断言、能不能算钱。

## 6. 人工 vs 系统 · 对照总结

| 维度 | 人工现况 | 系统 | 变化 |
|---|---|---|---|
| 抠图 | 做 7 次 | 做 1 次，共享 | 重复劳动归零 |
| 背景 | 每张都搭，靠手艺 | 只有位置 4 调 1 次模型 | 生成调用 7 → 1 |
| 文字 | 烧进像素 | 字体文件绘制 | 改字 1 天 → 0.1s |
| 一致性 | 肉眼对齐，不可证明 | 读同一份 `subject.png` + 日志断言 | 感觉 → 断言 |
| 失败 | 整张重做 | 单路隔离，其余照常交付 | 全废 → 局部 |
| 事务单位 | 一次上架 | 一个 `inbox` → 一个 `out` | 一致 |
| 人的位置 | 全程动手 | **只做判断**（选品 / 写文案 / 挑图 / 定稿） | 从"执行"退到"决策" |

> **提效的本质不是"让 AI 画图"。**
> 是把人工流程里**确定性的那部分**（抠图、叠字、对齐、合规）从手艺变成机制，
> 把**创造性的那部分**（背景）交给模型，
> 把**断言的那部分**（文案、规格）**继续留在人手里**。
> 三者混在一起，就是现在人工又慢又重复又改不动的原因。
