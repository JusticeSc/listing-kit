## 1. 目标、范围与既有基线

### 1.1 要交付的结果

把现有浏览器主导商品套图工具重构为可维护、可替换有限模型、可从持久证据恢复的产品：用户不需要理解内部版本/槽位/task/hash即可完成资料确认、套图调整、生成、图片比较、单图返工、采用和导出；维护者可以在协议 Adapter 与有效配置处变更模型而不改业务供应商分支；生命周期、持久化与执行顺序集中在业务 Module，而非散落在 DOM 闭包。

本轮以完整图片生产任务牵引，不以减少文件行数、迁移语言、引入框架为成功指标。UI 审计与工程化独立于第二模型评估推进，未确定模型不暂停这两条可达工作。

### 1.2 必做与非目标

必做：真实 UI 人体工程审计和任务原型；渐进前端类型检查与验证分层/CI接线；项目会话与生成/审核编排；统一有效模型配置、用途/能力与协议分离；BYOK为主、默认档受限试用；当前 DashScope 生图与一个经评估/授权的真实第二生图 Adapter；Prompt/确认/真实请求一致；同版本设置变化后的已提交任务恢复；同版本数据不丢、ZIP往返与单图隔离；必要的成熟系统设计研究；最终真模型/真浏览器/人审证据；V1有门禁的日落。旧版本/schema/项目包兼容和历史工件恢复不再要求。

不做：Node网关迁移、账户/租户/服务器项目数据库、云同步、服务端自主多步Agent、任意协议万能SDK、自动路由/降级/重试平台、自研密码学/HTTP/队列、全仓TypeScript或UI框架预选、无限公开共享付费key、直接复制不兼容或未经批准许可证代码。390px用于关键操作/信息可达与不遮挡，不承诺完整手机产品。

### 2.2 状态与权限
- `required`：已持工具真实返回的 Goal 标识（原样 UUID 或 16 位十六进制原生 handle），当前 v2 必须同时保存观察证据并逐字核对 ID；不能把原生 handle 补造成 UUID。`optional`：仅用于未观察到/未经确认的准备窗口。`session`：接口确实未返回 ID 时的会话观察绑定，`goal_id` 必须为 null；不得在接口已返回 ID 后继续谎称缺 ID。
- 观察证据：`goal_binding_evidence` 指向仓库内 JSON（schema `amz-goal-observation/v1`，`source: goal-tool`，`authorization: user_confirmed_current_goal`，非空 `user_confirmation`，`plan_ref` 与 state 一致）。required 的 `goal_id` 与 state 相等且 `id_unavailable: false`；session 则为 `goal_id: null`、`id_unavailable: true`。读数/时刻与 state 一致，新会话/恢复必须重读真实 Goal。旧观察保留为历史，不据此声称本会话已查询。
- JSON 保留 `observed_objective` 原始展示体，state 不复制 objective；与 §2.1 比对只剥离行首 `▏`/`│` 边框、明确的 `[13;28;13;0;0;1_`/`[13;28;13;1;0;1_` 展示码及布局空白，不剥普通标点和正文。`objective_sha256` 校验此处可读原文。不在本轮创建 Goal、不做 Goal 生命周期写入。
- `prepared`：计划与控制面已准备；当前 Goal 尚未完成会话绑定。`goal_id` 和 system 读数为空时原因非空，不存在 active 施工任务/阶段；已完成会话绑定的 state 不再称 prepared。本地把旧记录归档为 superseded 不修改系统旧 Goal；旧 Goal 的历史生命周期证据原样保留，不谎称旧 Goal 已暂停/完成。
- 绑定后的 active/paused 必须服从最新实际系统读数；阻塞时 next_action 指向可执行的核对/决策任务，不能指向依赖未过或 status=blocked 的施工任务。

- UI先实际审计，再原型，不预定三栏、六个强制步骤、全页唯一按钮或视觉风格。
- 本轮在用户已确认当前 Goal 后允许离线本地实现（含文档、状态、守卫/探针、冷恢复控制面检查与本地离线产品实现工作）；付费模型调用、上传私有素材、Git 提交/推送、Goal 生命周期写入、远程 Secrets 变更、新依赖选型、V1 日落与部署仍各自单独设门，未经对应授权不执行。

## 4. 不变量与目标职责

1. 未确认推断不是事实；VLM不是采纳者，不得产生平台硬BLOCK。
2. Prompt可查/可改，展示、记录与实际发送文本一致；规格/事实/实际模型能力变化按依赖范围失效。
3. action提交前持久化；已知task先核对；未知提交结果不自动重提，不因关闭视图等同于取消上游。
4. 保留旧候选、Prompt和选择历史；局部返工不改变无关Shot的Attempt/Blob/选择。
5. 事务内不得await外部网络；文档更新与追加任务观察有不同冲突语义。
6. 用户项目不落服务器；默认key不下发；BYOK不得被包/日志/诊断回显；用户endpoint不能继承默认key。
7. 历史执行身份冻结协议/目标/模型/影响请求的配置版本及凭据引用，不含secret；历史任务不能按当前设置猜目标；凭据轮换不机械使Prompt失效。
8. 开发态不兼容旧格式；不支持的库/包明确拒绝，不部分写入、不猜执行身份。同版本缺凭据/Unknown 按真实身份恢复，不伪造失败或新提交。
9. 固定HTTPS origin、浏览器支持与备份契约继续成立；不引入跨设备同步承诺。

职责：UI只投影/发出业务动作并管理视觉交互；项目会话Module持有身份、生命周期、快照、冲突与异步归属；生成执行Module统一单张/批量/返工的顺序；审核选择Module维护报告当前性/人工采纳；domain继续是纯规则；repository负责事务/版本/Blob；Python负责有效配置、凭据策略、协议Adapter与业务输入输出合同。Interface暴露业务动作及可渲染状态，Seam允许真实与fake Adapter走同一路径；不建立只转发参数的第二套facade。

## 5. 实施阶段与Gate

### Phase 0：计划准备与控制校准

**Gate G0：** 本计划、接受决策、Goal 原文、历史冻结、唯一 state 及下一动作落盘；守卫/反向探针通过，冷恢复仅靠仓库得出 R1.1 且未绑定前禁止产品施工。G0 不证明重构、Goal 绑定或 UI 改善。

### Phase 1：Goal 会话绑定、既有故障与基线

**Gate G1：** 当前 Goal 会话绑定落盘（用户已确认当前 Goal + 观察证据 + 重读核对）、旧 Goal 冲突显式处理；现有启动失败的证据链与处置任务明确；当前代码/配置可回退、同版本代表项目与关键主链基线可恢复；审计和调用权限明确。按 §2.3 不要求真实旧包或旧格式迁移。失败未根治不能发布，调查不要求无依据地循环复现。

### Phase 2：人体工程审计、原型与成熟设计核查

**Gate G2：** 七条任务的真实页面轨迹与问题分级齐全；冻结最终可判定UI合同及measure；可交互原型验证高风险路径；参考系统具体代码/文档与许可证据落盘，拒绝整体照搬。审计与原型不充当最终C17/C15。

### Phase 3：前端工程化与项目会话

**Gate G3：** 开发工具有锁/登记/PoC；类型检查与行为验证/CI分类接线执行；项目生命周期/编辑冲突/旧回调隔离真实浏览器证明；实现文本测试删除，未以新文案重钉。

### Phase 4：生图评估与模型/凭据/历史配置

**Gate G4：** 第二模型能力和预算/许可/访问策略获确认；统一有效配置及BYOK隔离；同版本执行身份、跨设置恢复与项目包校验正反例；不得以fake、仅聊天支持或删除下载白名单冒充真实生图兼容。

### Phase 5：生成纵向切片

**Gate G5：** 单张/批量/返工共享生成执行Module；两种实际图片Adapter可运行；Prompt/确认/请求一致；跨设置、刷新、服务重启与Unknown轨迹正确；旧执行路径清除。

### Phase 6：业务工作台切片与数据成本
