# V2.7.3 走查工具包（陌生人 / 产品发起人）

> CONTROL-STATUS: draft · AUTHORITY: V2.7.3 施工任务书
> 生效条件：V2.7.3 走查期间使用；走查结论与观察表归档后改登记为 `superseded`。
> 通过线只在计划 §10.1 / §11（C15、C17）里定义；本文件只管「怎么把这两条走完」。

## 1. 这次要证明什么

| 条目 | 通过线（计划 §11 原文） | 本工具包怎么采集证据 |
|---|---|---|
| C15 | 无命令行、JSON、开发者口授完成完整任务；介入为零 | 录屏 + 观察表（每秒谁在动手：被试 / 观察者） |
| C17 | 首页与六阶段同页工作台通过产品发起人走查 | 产品发起人逐阶段签署「可用 / 不可用 + 一句原因」 |

不通过就是证据：任何一次「观察者先说出口」都记为介入，按计划要求「修复后换人重验」。

## 2. 前置条件

1. 正式入口可访问：`https://47.115.172.233:8080/`（Chrome 或 Edge 当前稳定版；必须直接进入受信任的
   HTTPS 页面，不得要求被试接受证书警告）。
2. 上游可用：真实链路需要百炼账户有余额（`/api/v2/semantic/analyze` 不再返回
   `UPSTREAM_ACCOUNT_ARREARS`）。**账户欠费时不要开 C15 走查**——走不通的责任在上游，不在被试。
3. 兜底：账户不可用时，先跑 `uv run --locked python tools/verify_remote_no_model_roundtrip.py`
   证明「空白 → 资料 → 项目包 → 换浏览器恢复」这段真的可用（8 项，零模型调用）。
4. 素材：一个**非内置**品类的真实商品参考图（例如落地灯、食品、家具；不要用保温杯示例），
   1–3 张，短边 ≥1200px。

执行顺序：先由产品发起人完成 C17 逐阶段走查；若发现问题，修复、回归并部署后，再邀请未接触过
最终版本的人执行 C15。不能让 C15 被试承担发现显而易见产品缺陷的成本。

走查前界面基线：理解页工程标识已折叠；审核卡右栏显示当前检查摘要，已采用卡按钮禁用；整套检查
的非阻断风险在审核页与交付页均可见；生成前的语言风险只对允许图片文字的角色出现，并给出
“改英文后重新确认”的恢复建议。以上是观察者核对项，不念给被试。

## 3. 被试与观察者的分工

- 被试：第一次接触这个产品的人（不是开发者，也没读过本仓库文档）。
- 观察者：只记录，不指导。允许的唯一开口是「请继续」。
- 全程录屏（含鼠标指针与时间戳）；每张截图/下载包按时间戳命名归档到
  `evals/product-v2/evidence/v273-*`。

## 4. 任务脚本（念给被试，不解释界面）

> 「请用这个工具，为你手上这件商品做一套可以直接交付的 Amazon 商品图，最后导出交付包。
> 过程中如果卡住，请说出你在找什么。」

## 6. 归档要求（缺一不算完成）

- 录屏文件（或分段）+ 观察表（本文件第 5 节复制成实际记录）。
- 被试产出的**交付包**与**项目包**（真实字节）。
- 每次介入的时间点与原因；零介入时明确写「0 次介入」。
- 结论只写观察到的事实与分类，不写「用户体验良好」这类无法复核的判断。
- 只把最终一次有效走查的录屏、观察表、项目包、交付包和必要截图列入保留清单；失败走查保留问题
  证据，但重复截图和调试输出不进入版本库。禁止使用 `git add -A` 纳入整批过程文件。
