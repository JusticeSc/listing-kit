## 受控自举：用本方法改进本方法

用户已要求持续完善并实现可自举AI Coding。本项目把它落实为授权内的工程改进，不是自动扩大权限、任意自改验收或宣称模型能力自我进化。具体本地记录见 `_working/ai-coding-bootstrap/work.md`；`_working/**` 被 gitignore 忽略，该记录只在本工作树可读，不随仓库发布，也不进 INDEX 登记。它不替代原Product V2的计划、state或原生Goal。

方法改进按以下闭环执行，不另建任务库、代理调度器或评分平台：

1. **问题与假设**：从实际失败提出可证伪的原因与预期改变。把判错依据与非目标先写清，不能实现后再修改标准制造通过。
2. **保留退路**：修改前保存受影响文件原字节及必要输入；已有历史与用户改动保留。整理state未知项须逐条对应具体取代记录和全部/部分范围，原文按既有历史约定保留；没有取代证据就保留，部分取代不释放剩余Unknown/授权/预留。对照前后blockers/unknowns与原Goal/账本，不能靠删除历史使检查变绿。
3. **最小工具改变**：优先修改当前实际消费者。上下文只承载原则与入口，能够由程序判断的精确模式、退出码或身份错误应在相应执行位置处理。
4. **同判据比较**：必要时用保留的原始实现与候选实现检验同一失败条件；再运行正常消费者路径，核实没有用禁掉全部操作换取拒绝错误。判据独立于实现，不以更换作者或模型代替独立性。
5. **采用或撤回**：在既有Issue或方法记录分别保留分析结论、实际改动及独立判据下的效果证据；缺原反例/正常路径验证，不把“已实施”写成“已验证”。根据正确性、覆盖范围和新增成本决定保留、调整或撤回；只撤本轮差量，不覆盖用户后续修改。本地采用不等于获准提交、合并或发布。
6. **后续观察**：下一次相关真实操作中观察措施是否被使用、是否被绕过；同类复发重开原纠正项。没有足够记录不报效率百分比，完成一次闭环不声称无监督自主改进或永久不复发。

本地与CI使用既有 `tools/select_v2_checks.py` 选择影响范围，命令仍唯一取自CI verify目录，精确模式取自验证登记：

```bash
uv run --locked python tools/select_v2_checks.py evals/product-v2/harness/compare-panel.js --emit-github
```

将路径替换为本次真实改变；`--emit-github`只预览，`--run`才执行。普通说明/不可执行过程证据只选管理检查；已批准验证器及已知专用harness选对应消费者与必要构建前置；已知UI视图选业务消费者（独占的共享DOM根按源码实际读取派生要求集，不写手名单）；混合变更取并集。公共合同、锁或未知影响保守扩大；走查没有批准离线模式/必要输入时明确报缺口，不能用全产品回归代替走查证明。覆盖与合法扩展的判定规则只取`AGENTS.md` Testing Guidelines；不把运行结果反推成必需覆盖权威。

选择器先核对整份命令目录的精确入口、参数、批准与冲突，再启动首条命令；未登记或未批准模式拒绝，paid/remote/aggregate不进入普通执行，首个失败保留真实退出码。需要本地原始执行凭据时，在本次 `--run` 指定 `--result-json`，直接消费实际命令、退出码与受测身份；CI仍取原始run/step，不重抄另一份成功结论。凭据只证明其实际执行范围，源码身份不证明业务/像素合格。注册与选择不是用户授权，不能拦截绕过入口的工具调用；未变前提的有效证据按范围复用，最终必要两轮不随日期或文档HEAD重复。

凭据输出在启动命令前检查路径：源码/构建输入、`_working/`（含state与账本）、`docs/`、`.github/`、`.git`及根`AGENTS.md`/`README.md`/`.gitattributes`/`.gitignore`均不可作为目标；无法安全解析也拒绝。这是写入保护，不等于源码快照范围。请在普通证据目录（如`_stage-amz-control/`）使用本次独立文件名，避免覆盖旧结果；权威路径反例只对独立副本运行，不拿真实原件演示破坏。

CI的changes job使用真实base/head提交差量生成路由；坏基线失败，手动完整入口保留。PR/手动分类失败必须使required验证作业显式失败，不能条件skip伪装成功。verify消费同一结果；无运行/构建/发布闭包变化时明确记为不适用，不构建或部署相同内容，不冒称容器已验。实际实现/本地证据与远程是否生效须分别核对。
