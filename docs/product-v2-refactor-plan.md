## 1. 目标、范围与既有基线

### 1.1 要交付的结果

把现有浏览器主导工具重构为可控的商品套图产品：以参考图和商品资料为输入，允许纯人工或模型辅助形成已确认商品事实，按所选图片用途补齐必要信息，准备实际发送的 Prompt，生成、直接比较、局部返工、人工采用并导出。用户不需要理解内部版本/槽位/task/hash，也不必购买一次 AI 理解或复核才能完成任务；维护者在协议 Adapter 与有效配置处变更有限模型，不在业务层增加供应商分支。完整业务合同见 §14；生命周期、持久化与执行顺序集中在业务 Module，而非 DOM 闭包。

### 2.2 状态与权限
- `required`：已持工具真实返回的 Goal 标识（原样 UUID 或 16 位十六进制原生 handle），当前 v2 必须同时保存观察证据并逐字核对 ID；不能把原生 handle 补造成 UUID。`optional`：仅用于未观察到/未经确认的准备窗口。`session`：接口确实未返回 ID 时的会话观察绑定，`goal_id` 必须为 null；不得在接口已返回 ID 后继续谎称缺 ID。
- 观察证据：`goal_binding_evidence` 指向仓库内 JSON（schema `amz-goal-observation/v1`，`source: goal-tool`，`authorization: user_confirmed_current_goal`，非空 `user_confirmation`，`plan_ref` 与 state 一致）。required 的 `goal_id` 与 state 相等且 `id_unavailable: false`；session 则为 `goal_id: null`、`id_unavailable: true`。读数/时刻与 state 一致，新会话/恢复必须重读真实 Goal。旧观察保留为历史，不据此声称本会话已查询。
- JSON 保留 `observed_objective` 原始展示体，state 不复制 objective；与 §2.1 比对只剥离行首 `▏`/`│` 边框、明确的 `[13;28;13;0;0;1_`/`[13;28;13;1;0;1_` 展示码及布局空白，不剥普通标点和正文。`objective_sha256` 校验此处产品原文。规划Goal不得替换产品绑定，规划完成不完成产品Goal；独立规划授权见§15.6。
- `prepared`：计划与控制面已准备；当前 Goal 尚未完成会话绑定。`goal_id` 和 system 读数为空时原因非空，不存在 active 施工任务/阶段；已完成会话绑定的 state 不再称 prepared。本地把旧记录归档为 superseded 不修改系统旧 Goal；旧 Goal 的历史生命周期证据原样保留，不谎称旧 Goal 已暂停/完成。
- 新施工须核对最新实际系统读数；历史active/paused及绑定证据不是本会话执行许可。已绑定工程记录可把next_action保留在依赖已done的blocked前沿，但blockers须有以该任务ID＋`_`开头的非空具体原因；冷恢复只允许核对/解除阻塞，不执行受限施工。prepared只允许pending下一动作。工具返回No active goal或目标为独立规划时，保存实际观察并阻断产品施工，保留产品历史绑定，不伪造其暂停/完成。用户另行明确恢复后按§16.2处理真实产品Goal与绑定，不能把规划确认当成创建/施工/付费/发布许可。

## 4. 不变量与目标职责

1. 未确认推断不是事实；模型只能提议，原始商品事实确认及图片采用归人；规则仅可确认已注册确定性派生的derived事实，不得借派生名义猜测。AI复核按需且可不做，不产生平台硬BLOCK；未复核与确定性硬检查分开，详见 §14.8。
2. Prompt可查/可改，展示、记录与实际发送文本一致；规格/事实/实际模型能力变化按依赖范围失效。
3. action提交前持久化；已知task先核对；未知提交结果不自动重提，不因关闭视图等同于取消上游。
4. 保留旧候选、Prompt和选择历史；局部返工不改变无关Shot的Attempt/Blob/选择。
5. 事务内不得await外部网络；文档更新与追加任务观察有不同冲突语义。
6. 用户项目不落服务器；默认key不下发；BYOK不得被包/日志/诊断回显；用户endpoint不能继承默认key。
7. 历史执行身份冻结协议/目标/模型/影响请求的配置版本及凭据引用，不含secret；历史任务不能按当前设置猜目标；凭据轮换不机械使Prompt失效。
8. 开发态不兼容旧格式；不支持的库/包明确拒绝，不部分写入、不猜执行身份。同版本缺凭据/Unknown 按真实身份恢复，不伪造失败或新提交。
9. 固定HTTPS origin、浏览器支持与备份契约继续成立；不引入跨设备同步承诺。

职责：UI只投影/发出业务动作并管理视觉交互；项目会话Module持有身份、生命周期、快照、冲突与异步归属；生成执行Module统一单张/批量/返工的顺序；审核选择Module维护报告当前性/人工采纳；domain继续是纯规则；repository负责事务/版本/Blob；Python负责有效配置、凭据策略、协议Adapter与业务输入输出合同。Interface暴露业务动作及可渲染状态，Seam允许真实与fake Adapter走同一路径；不建立只转发参数的第二套facade。

## 5. 实施阶段与Gate

### Phase 0：计划准备与控制校准

**Gate G0：** 本计划、接受决策、Goal 原文、历史冻结、唯一 state 及下一动作落盘；守卫/反向探针通过，冷恢复仅靠仓库得出 R1.1 且未绑定前禁止产品施工。G0 不证明重构、Goal 绑定或 UI 改善。

### Phase 1：Goal 会话绑定、既有故障与基线

**Gate G1：** 当前Goal真实绑定、旧记录与新目标明确分开；代码/配置及同版本代表项目基线可恢复，审计/调用权限明确。已报告启动缺陷按§7.6逐项承接，调查完成不等于修复完成；未达到缺陷发布准出标准不得发布。按§2.3不要求旧格式迁移，不为确认用户报告循环复现。

### Phase 2：人体工程审计、原型与成熟设计核查

**Gate G2：** 七条任务的真实页面轨迹与问题分级齐全；冻结最终可判定UI合同及measure；可交互原型验证高风险路径；参考系统具体代码/文档与许可证据落盘，拒绝整体照搬。审计与原型不充当最终C17/C15。

### Phase 3：前端工程化与项目会话

**Gate G3：** 开发工具有锁/登记/PoC；类型检查与行为验证/CI分类接线执行；项目生命周期/编辑冲突/旧回调隔离真实浏览器证明；实现文本测试删除，未以新文案重钉。

### Phase 4：生图评估与模型/凭据/历史配置

**Gate G4：** 第二模型能力和预算/许可/访问策略获确认；统一有效配置及BYOK隔离；同版本执行身份、跨设置恢复与项目包校验正反例；不得以fake、仅聊天支持或删除下载白名单冒充真实生图兼容。

### Phase 5：生成纵向切片

**Gate G5：** 单张/批量/返工共享生成执行Module；两种实际图片Adapter可运行；Prompt/确认/请求一致；跨设置、刷新、服务重启与Unknown轨迹正确；旧执行路径清除。

### Phase 6：业务工作台切片与数据成本

**Gate G6：** 资料/方案、图片比较/返工/采用、交付/错误与模型设置按已冻结交互合同迁移；关键操作不遮挡/焦点不被重绘丢失；选择/门禁真实状态投影；存储扫描与契约复访有测量和必要改造或明确不改依据，无双状态权威。

### Phase 7：最终工程验收与发布冻结

**Gate G7：** §10适用矩阵全部proven，V1覆盖/消费者切换/恢复基线及删除后最终两轮离线回归、范围匹配真实能力、现有HTTPS发布/回退与最终指纹闭合。C17/C15仍是未发生的独立真人外部门，不冒充通过；模拟真人为工程E2E。未满足真实补证、缺陷因果准出、保护或线上验收时对应项保持未完成。
- 触发后阶段推进仍有顺序；R4.3离线可先行，不等待R4.2付费PoC；R5.1离线可先行，不被含尚未实测R4.2的G4阻断。真实证明、G4/G5/G6的最终通过与R7.1/R7.4不可豁免。

阶段推进有顺序；阶段内独立任务允许授权并行，但只有一份state和一个下一动作。R4模型研究可在G1后与UI/工程调查并行执行；进入Phase4前仍须G3，任务产物提前产生不等于提前推进阶段。

### 7.5 需求修订与完成状态

- done只证明其验收版本及证据范围。新合同改变结果/权限/输入输出时，在正式启动的一次差距核对中重新判定受影响任务及其依赖/Gate；未满足当前验收的任务改为pending或有具体原因的blocked，旧证据保留为历史，不清空、不重做未受影响成果。
- 同一任务包含跨批工作时，每批只追加已交付范围/证据；尚有新增消费者或当前验收未成立，不把批次成立写成整项done。例如R6.1人工批次可先形成可用输入，图文辅助后才闭合其整项；R6.3人工交付批次与全用途最终验收同理。不另建部分完成状态机或批次进度表。
- 调整依赖后，依赖尚未done的下游不得继续维持当前整项done；同时核对阶段，最多一个active阶段和一个准确next。不以历史状态绕前置，也不为保留旧阶段done反向放松验收。旧证明可复用，复用须按§15.3说明对应路径/合同未受影响。
- 当前只是准备，历史任务状态暂保留原范围并由state阻断施工；绑定新Goal时按本节一次同步，进入相应最早受影响任务，不固定停在R6.3，也不把全部任务重置。状态/依赖变更后提交前按AGENTS执行一次已有反向探针。

### 7.6 已报告缺陷的发布准出

- 用户报告按事实承接，不为确认报告重跑。逐项区分已证修复机制、对应用户现象和仍未知部分；优先复用已有阶段轨迹及消费者失败前/修复后证据。
- 准出要求：机制与报告现象有可核对对应，修复路径在受控条件下成立，受影响正式入口/恢复路径实际运行正确；明确剩余未知。只证明另一机制、只有连续绿色或不能建立对应关系，不能关闭原缺陷，RC19与发布保持未完成。
- 不要求捏造所有历史触发的完整根因；也不能用“覆盖了一个可能机制”自动放行。残余未知可能影响主链且证据不足时继续阻断；任何风险接受须用户明确批准，不由代理自行豁免。两轮回归是必要条件，不是根治证明。
- 基础设施故障与产品缺陷分别记录；恢复基础设施不等于产品修复。修复后只重验受影响项，到最终边界再完成必要回归，不加长超时或循环洗绿。

### 7.7 发布事务与回退边界

- 发布前固定上一可运行代码/镜像、配置指纹、可信HTTPS origin及对应数据恢复基线；日志/证据不含secret。只发布本轮相关PR，合并权限按§16.1和AGENTS；不能绕过审查/保护或强推。
- 旧可运行版本至少保留到容器、受信 HTTPS、静态资源（首页外壳与样式/脚本字节）及约定页面主链（实际启动/状态就绪/新建后刷新仍在/零错误）均通过并完成验收记录；任何必要环节失败都进入明确回退处置。不能在容器 healthy 后提前删除旧版本，再把 HTTPS、静态或页面失败只记退出码。
- 发布主链使用独立Chrome无头配置及隔离项目，验证实际资源/页面操作/保存恢复/下载；付费外发不混入默认线上smoke，新增真实调用只按§16.1专项准入。未覆盖的供应商效果不冒充线上通过。
- 在同一可信origin恢复旧服务并核对其实际可用性；涉及客户端格式时按§7.4保留对应库/包和已产生的新数据，不清日常用户库。回退失败保持精确故障与恢复点，不把容器重新启动当恢复成功。
- 发布事务由 `deploy/release-transaction.sh` 与流水线 deploy/acceptance/finalize/rollback 四步实现（R7.4 本项）：TLS/配置基线在变异前捕获并持久化（baseline→parked→new_healthy→tls_backed_up/tls_install_intent/tls_installed_new→tls_converged→https_ok），previous 应用容器与 Caddy 配置备份保留到 deploy 内验收（容器健康、受信 HTTPS、静态首页/样式/脚本）与事务外 acceptance（约定页面主链）及 finalize 重验全部结束才清理；无开放事务下 serving 与 previous 并存视为脏恢复点，deploy 直接拒绝、不自动删除旧容器；重验证失败（finalize exit 1，含健康/HTTPS/静态首页样式脚本重验）仍走 rollback，收尾失败（exit 4，新版本健康但清理不完）绝不自动回滚、需人工清理；过期 finalize 拒绝且 previous 保留。事务外验收用 `tools/release_transaction_probe.py --page-smoke`（受信 HTTPS 真实资源/页面主链，不带 BYOK、不做付费调用），事务机制用同探针 `--selftest`（真实调用脚本 deploy/finalize/rollback，一次性隔离容器/配置/HOME，缺 Docker/构建/Playwright 报 missing_prereq；容器 CI 在远程部署前先跑）；探针 green 不证明某次真实部署已发布成功，真实回退仍需按事件单独核对。实施仍复用既有流水线，不增加部署平台。

## 14. 商品套图业务与任务合同

本节是本轮讨论形成的**目标合同，不是当前实现说明**。适用有限现有模型、浏览器本地项目和已有工程任务；不改§2.1原文，不新增Agent平台、商品信息检索服务、付费额度或任务状态表。已确认选择按§13；交互表现由UI合同投影，技术承接由context说明。

### 14.1 用户结果与人机分工

- 输入：有权使用的商品参考图、商品资料及使用目标。结果：人确认的商品事实、可调整的图片任务、可追溯候选和人工采用的交付套图；不是自动承诺所有商品/平台合规或图片绝对忠实。
- 默认路径：资料 → 必要事实 → 选择图片用途并补相应信息 → 本地准备及查看发送摘要 → 明确生成 → 同图比较/按需返工 → 人工采用 → 确定性检查及导出。模型可辅助理解/创意/复核，但不成为购买后才可操作的必经门。
- 人决定：事实是否可信、用途/张数、创意范围、外发与费用、采用哪张、是否复核、是否接受已披露风险。系统承担重复提取/本地编译/依赖计算/身份记忆/状态追踪/精确定位，不把内部参数调度交给普通用户。
- “完整可控”指同一业务对象和动作可由人工完成/修改，不指默认摊开所有字段和底层按钮。默认任务视图、就地高级控制、独立诊断入口共享同一状态与执行路径，不建立三套数据、三种完成标准或模式切换迁移。

### 14.2 业务对象、来源与状态

| 对象 | 必须承载的语义 | 唯一责任/不得混淆 |
|---|---|---|
| Intake / ReferenceImage | 原始文字、原图字节/hash、用途角色、授权说明；原始与编辑草稿分开 | 资料是证据输入，保存原文不等于确认所有抽取事实 |
| FactSlot / ProductBrief | 注册或自定义的事实ID、标签/值类型、值、source、actor、status、证据/置信、版本；Brief只投影confirmed值 | 事实来源、操作者、确认状态是不同维度；模型来源经人确认后仍保留原来源 |
| SuitePlan / Shot | 动态1..N图片任务、稳定shot身份、用途/目标、事实依赖与参考图角色、排序/启用状态 | 不是六个UI阶段的副本；一个用途可有多张图，删/停任务不删历史 |
| StyleSpec / ShotSpec | 公共视觉偏好；单图目的、必须保留、允许变化、构图/背景/文案、规格与约束 | 事实与创意分开；尺寸/材质/成分/比较声明不能藏成“风格默认” |
| PromptRecord / Basis / Confirmation | 实际文本及人工/系统来源、消费的事实/规格/参考图/能力版本、实际发送摘要与确认指纹 | “编辑中”不等于已保存，“准备好”不等于已授权发送 |
| Action / Attempt / Candidate | 外发前登记的动作、冻结非秘密身份、观察状态与候选原字节/hash及来源链 | 提交结果未知不等于明确失败；同步结果可无provider task id |
| Review / Selection / ExportRecord | 确定性测量、可选AI报告及各自当前性；明确人工采用；追加式导出记录 | 查看/对照/采用不同；没调用AI不是模型判断Unknown，更不是PASS |

复用既有 `core_fixed/category_dynamic/user_custom/derived`、`user_input/reference_observation/model_inference/system_default/derived_rule`、`user/model/rule` 及事实状态，不另造一套人工表单模型。固定核心字段可由人编辑但不能被模型删除；模型仅propose，规则仅做可解释确定性派生。人工确认可以是明确“保存并确认”的一次操作，不要求同一值在两个页面重复确认。

actor是动作操作者，应能从权限动作/版本记录追溯，不要求在FactSlot另造同义根字段。人仅确认原提议、未改值时保留其来源；人重新写值则记录该编辑来源，同时保留原提议证据/历史。derived仅由规则依赖已确认输入和注册计算产生，不能把模型猜测或未确认值包装成确定性事实。

### 14.3 人工与模型辅助的同一事实路径

1. 资料可先存草稿。用户能直接填写/修订名称、品类、必须保留特征及自定义事实，不需要先调用分析接口才能得到事实编辑器或建立套图草案。现有三项核心事实构成商品识别基础；品牌/材质/尺寸/包装等不因注册存在而全部必填。
2. 人直接填入并明确保存确认的结构化事实，由actor=user走领域编辑/确认动作。导入的原文、模型抽取或猜测先作为提议；模型置信度只帮助排序，不授权自动confirmed。已确认事实与新提议冲突时保留原确认值和证据，交人处理，不覆盖。
3. 用户可选择真实图文理解：显示实际发送的原图/文字、理解模型、key就绪情况和费用后明确发起。模型返回带来源/证据的候选事实、外观保留项、矛盾/未知及信息缺口；只能写提议，不创建已采用图片、不直接生成或确认。
4. 仅文字理解应明确“未读取图片”；文件名、尺寸、hash和缩略元数据不是视觉理解。缺key/网络/模型输出失败只阻止该辅助动作，保留草稿与人工入口，不将商品状态伪装为空项目或已理解。
5. 可以先选图片用途，再补对应字段；规划可保存不完整任务。生成就绪按具体Shot消费的已确认事实与参考图、单图规格及模型能力计算，不把“所有槽位已填/所有UI阶段完成”当门。

### 14.4 图片用途与信息需求

共同基础：有合法参考原图、已确认商品识别/必须保留特征、明确用途和输出规格。事实字段只在该图将使用/展示对应声明时成为依赖；事实未知可不使用，但不得以默认值、Prompt扩写或创意描述伪造。默认模板是可编辑起点，不固定图数或把八类全部塞入每个项目；动态N仍服从既有SuitePlan上限与有效模型能力，单次生图n=1不等于整套只能一张。

| 既有用途/模板 | 本图额外需要的人确认信息 | 可由规则默认或模型提议的创意 | 缺项影响 |
|---|---|---|---|
| 主图 / main_clean | 商品主体与参考图保留范围；平台主图约束 | 主体布局、光照、合规背景 | 锁本图；不因缺尺寸/包装锁主图 |
| 场景图 / scene_lifestyle | 本图若使用的真实用途/限制声明 | 场景、构图、道具；不暗示未经确认的防水/性能/安全特性 | 缺相关事实则去掉该声明或补事实，不锁无声明场景 |
| 卖点信息图 / infographic_benefits | 选定卖点及逐项事实依据、要出现的准确文字 | 排版、图标、视觉层次 | 没依据的卖点不外发；可减少文案 |
| 材质细节图 / detail_material | 需展示的材质/结构/细节已确认且有可用依据 | 放大位置、照明、布局 | 缺材质只锁材质声明；可改为有依据的外观细节 |
| 尺寸图 / size_dimensions | 要标注的轴向/对象、数值、单位与确认依据 | 标注位置、视角、版式 | 不完整或歧义测量锁尺寸图，不影响其他图 |
| 对比图 / comparison_competitor | 对比对象身份、比较维度、双方所述值/声明的确认依据 | 对比布局、色彩、标记 | 不凭空创造竞品或优越性；缺依据锁对应比较 |
| 成分/原料图 / ingredient_composition（role=ingredient） | 明确成分/原料事实与要展示的标签 | 分组、构图、背景 | 不从外观推断化学成分或认证；缺事实锁本用途 |
| 包装清单图 / packaging_contents | 确认包含物、数量和包装关系 | 摆放方式、标签、留白 | 未知附件不自动加进图；可只展示已确认清单 |
| 自定义图 / custom | 用户写明目标、绑定要断言的事实、必须保留/可变范围 | 用户控制全部创意与完整Prompt | 不绕过事实、能力、发送及交付硬约束 |

上述表是产品信息需求；字段注册/依赖规则继续集中在既有domain，不在UI或网关复制模板表。尺寸表单收集明确对象/轴向、有限正数与显式单位，逐项对应人确认依据；形成可核对的已确认表达，不凭模型换算/猜单位或从像素推算实物长度。现有自由文本 `size_summary` 或任意绑定事实不能仅因非空就满足尺寸标注，需要解释它具体提供哪项测量；有歧义可保留草稿但不可外发尺寸断言。比较/成分等扩展事实复用自定义或品类动态FactSlot及明确绑定，不建设新商品知识库。

每个缺项必须说明“哪张图、要表达什么、缺哪个已确认值/参考图/能力、如何修复或改用途”。未选择用途的字段不抢占默认视图；补一次共用事实可解除所有真实消费者的缺项，不能要求逐图复制。

### 14.6 本地编译、变更与恢复

- 编译输入是confirmed事实及所消费版本、Shot目的/依赖、保留/可变项、风格/规格、参考图角色/hash和实际模型能力；输出为确定性Prompt、Basis和实际发送摘要。同输入复用版本，不用一次文字模型调用“提高智能”作为默认编译前置。
- 可以另外主动请求创意候选，由人选择进入ShotSpec再本地编译；不能把模型创意直接覆盖事实、人工Prompt或已确认发送摘要。高级自由文本可编辑，但不得宣称程序已穷尽识别所有潜在虚假声明；界面保留依据/风险与人的复核责任。
- 事实变化只使实际消费它的图及下游确认过期；单图规格只影响该图；公共风格影响真正消费该风格的图；参考图按实际角色/字节依赖；实际模型/参数/能力变化影响新编译/确认。key轮换、导航、查看图、AI复核及不相关事实不机械改变Prompt或候选身份。
- 自动准备仅处理缺失/过期系统文本。人工版本过期保留原文、草稿与原因；允许明确复核保存到当前依据或明确放弃后重编译，不静默覆盖。
- 已外发动作及成功候选使用原身份，不随新设置重定向。刷新保留项目/事实/任务/候选/选择/历史及Unknown，BYOK需重给；恢复核对不是重新生成。旧队列继续使用其原确认集合和身份。
- 局部返工创建目标图的新动作/候选，不更改旧候选、旧采用和无关图的记录/hash。失败、停止和Unknown不回滚已经成功的其他图。新结果只提供查看入口，由人决定改选。

### 14.7 有限模型、真正看图与Agent边界

**目的与能力**：商品理解包含图文/仅文字两个明确选项，生图和复核是其他目的；同一个图文模型可服务理解及复核，但请求/输出合同、UI文案、动作身份各自正确。设置只选择有限受支持配置与自己的key，不开放任意model ID/base URL；不增新供应商或框架。

- 文字理解复用现有 `deepseek-v4.1-flash`，其当前配置 `reference_images:false` 不得声称已看参考图。目标图文理解复用现有 `qwen-vl-max` 和已批准的多模态传输能力，建立商品事实提议合同；不能拿要求candidate的图片复核schema冒充商品分析。
- 图文理解输入：明确动作/配置身份，当前资料版本与文字，实际参考图bytes/base64、media type、sha256及角色，已确认事实（用于保留及识别冲突）。输出：原输入身份、实际图像发送事实、可校验FactSlot提议、来源/证据/置信、外观保留提议、冲突/未知和缺项。事实值只用既有标量/标量数组类型；证据能指回所发原图/hash或原文，无法验证时不装成证据。禁止把像素推算尺寸、外观猜测材质/成分/认证当已确认事实。
- 生图继续限定 `qwen-image-3.0` 和大陆火山 `doubao-seedream-5-0-flash-260915`。DashScope异步task与火山同步返回都走同一候选/动作合同；同步没有task id不是缺实现，不伪造status/result外呼。
- BYOK覆盖理解/生图/复核消费者，按当前页内存及单请求HTTPS使用；可按provider复用内存凭据，身份只存非秘密credential reference。缺key就说明哪个动作不可用；保存本地、查看、手工事实/规划/编译/采用/备份不受模型key门。默认付费档fail-closed，不静默替用户承担费用。
- 固定业务流程可承载动态用途/数量/缺项和局部返工，不等于智能不足。先用领域依赖、局部操作和模型提议解决已知任务；本轮不引入自主Agent、Memory、检索/路由/重试平台或新依赖。
- 未来仅在有实际任务证明“预先不可枚举的动作选择/搜索/迭代”值得其成本时再评估Agent。Agent最多产出通过现有合同校验的提议，不自行确认事实/采用/付费/取消权限；Skill是方法和上下文，不是持久状态、权限或执行器。本条是边界，不是Agent实施任务。

当前实现差距：现有semantic分析是文字合同，候选VLM是复核合同；image BYOK不能证明其他用途接通。必须据正式装配/出站捕获和后续获准真实调用分别证明能力；本轮不调用模型，不把目标字段、现成模型名字或历史复核证据当已完成图文理解。

**图文理解合同的最小边界（目标，不是新增已实现API）**

| 边界 | 约定 |
|---|---|
| 用途与模式 | 仍属商品理解用途，显式区分text/vision；有限配置绑定实际模型/能力，review条目不能作为商品理解已接通的证明。业务请求/提案演进在semantic合同及正式消费者，不复用candidate审核端点充当分析 |
| 请求输入 | 资料快照/版本、platform/locale/focus、原文及confirmed事实；vision还带1..3张去重参考图的role/media_type/sha256/data_base64。严格base64、真实PNG/JPEG签名、解码字节hash复算；单图≤4MiB、合计≤12MiB解码字节，复用现有图文校验/传输模式而非审核输出词表 |
| 超限与未发图 | 提交前定位具体图片/字段，拒绝且零外呼；不静默裁图、缩图或丢参考图，不谎报reference_images_sent。可回人工/明确仅文字路径；text模式不送字节且明确未看图 |
| 输出提案 | 复用RawProposal/to_fact_slots及其类型/authority/证据限制，产生slots/questions/summary与实际provider/model/request及输入身份/使用说明；图像发送事实据实际传输记录，而非模型自述。扩展外观/缺项必须能映射提议或问题，不另存一个不受FactSlot权限控制的“理解结果” |
| 输出校验与并发 | 未知字段/非法类型/越权confirmed/伪造证据或图hash拒绝，不局部洗成合法结果；模型文字不能提供权限。合规提案只归属原资料快照；资料变化的晚返回保留历史/提示过期，不覆盖当前确认值，不自动发起新请求 |
| 凭据与错误 | 请求级凭据按provider内存引用，不随请求体/包/日志回显；缺key、鉴权、超限、超时、上游或结构错误用既有错误族说明，保留人工操作。已有有界文字/提案数约束沿用semantic契约，不复制第二套限制 |

上述上限是保守目标输入界限，不意味着当前semantic接口接受图片字节；真实模型能力仍须正式接线与获准证据。若原图超过目标界限，可人工完成，不自动新增压缩/预处理平台或收费降级。


### 14.8 可选AI复核与确定性交付门

本轮用户明确选择：**允许未做AI复核导出**。需要迁移将“未运行AI”折叠为Unknown/强制补复核的耦合；当前确定性单图/整套报告门仍保留，不是删除报告门或用空报告、假PASS、默认Unknown、假回执绕旧代码。

- 人工采用仍强制；确定性测量仍强制：所需任务有合法选择，候选/原资产字节和hash存在且一致，格式/规格及注册平台硬规则有效，事实/规格/来源和原动作链可追溯，当前必要依据满足领域合同；已知确定性BLOCK不能凭风险确认放行。平台规格规则及严重度仍由已注册domain规则统一裁定。
- 当前单图/整套确定性检查报告仍须合法、当前且可追溯，由本地检查产生/更新，不要求附AI结果才能成立。AI维度单独记录 `not_run/current/stale/unknown/failed`（目标状态），缺AI报告本身不构成硬阻断；建议不能造平台BLOCK、替代人工采用或认证忠实度。原 `export.report_current`/整套当前性检查应按确定性消费依据保留，不能把选择链/测量合法性一起删掉。
- 未运行不创建虚假模型发现，不因not_run造UNKNOWN并要求知悉；真实发起后失败/未知及已报告风险仍保留当前身份和必要知悉。可在同一摘要明确确认并按身份记录，不逐屏重复点击，也不改写发现为PASS。确定性未知不能声称已验证；处理方式按注册规则，禁止一律降为警告。
- 改选/规格变化使受影响的AI建议过期时仍保留历史及明确状态，不强制补付费复核；确定性检查按真正消费的新输入重算。自动本地检查不是自动AI调用。
- `checks.json`/manifest明确区分确定性规则的实际测量、AI是否运行/当前性/原报告身份、人工采用及风险知悉。README不得把“未AI复核但硬门通过”写成“模型确认无问题”；导出来源取采用候选原Prompt/原请求，不取当前编辑区。
- 提交结果Unknown是另一类执行状态，仍不得自动重提/洗成失败。未采用的无关Unknown不一律锁全项目；所选候选的执行与字节链必须成立；无task另发仍需额外付费风险确认及预算授权。

图片忠实度、文字渲染、尺寸标注视觉准确、不同图的商品一致性是质量风险，不由HTTP成功、schema通过、假图或截图非空证明。沿用现有最少必要真图证据，指出具体失败边界；不得为了新规约重复付费洗绿，也不把AI复核当真人C15/C17。

## 15. 详细施工批次与验证成本纪律

用户明确担忧“各种验证测试没有实际稳步推进开发进度”，要求仅做必要验证。以下把§14映射为**按可操作成果推进的施工顺序**，不是新增任务ID、另一份进度表或立即施工授权。正式任务/依赖仍在§6/§9；实际进度在state，各批的结果写入所承接既有任务的最少证据。历史done按原证明范围保留，施工前重新核对新缺口。

§15.2保留业务成果的原设计顺序，不是当前待重建清单；§15.6规定已实现版本的有限收口。恢复时先读取state，再按详细设计§11.5处理差距，不能从设置或原子联调组A重新开发。

### 15.1 开始条件与推进原则

- 首次正式启动只按§16.2做一次真实Goal/范围、受影响任务及代码/数据基线核对；真实绑定和前沿以state为准，不因每改一个文件重做启动审计。首次产品写入前必须取得实际数据恢复基线，方案或代码快照不代替运行证明。
- 顺序为**设置接线 → 人工事实/用途 → 默认生成 → 比较/返工/交付 → 图文辅助 → 最终集成**。先形成可控完整人工主链，之后图文理解只替换输入生产方式，不另建执行系统。

- 采用已有domain/repository/执行Module和已批准协议，不重做存储/两生图Adapter、引入框架/Agent、重跑选型研究或购买重复证明。按§7.4在切片边界保存可回退基线，不为每次文本编辑另做一套备份和检查。

### 15.2 批次、具体改动与可见完成点

#### 设置接线：用户的配置真的进入请求

承接R4.3/R4.4/R6.3。先实现统一用途设置草稿/应用和当前页内存凭据；贯通**现有**文字理解、生图、单图/整套复核消费者，图文商品理解由后续批次补齐，不提前显示可用。

**主要位置**：workspace及设置投影、generation请求、product_v2_server、providers registry/credentials/outbound和现有semantic/review/suite_review消费者。

### 17.3 批次依赖与原子交付规则
