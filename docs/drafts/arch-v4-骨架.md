## 2. 五个层（取代 v2 的「主体 / 背景 / 文字」三层）

v2 按**图层**分层；v4 按**责任与可验证性**分层 —— 因为 v2 的"背景层"与"文字层"在 v4 里
都不再是独立的层（不变量 B 反转、C 删除，见 `slots-v4` §1）。

| 层 | 持有者 | 性质 | 谁在读 |
|---|---|---|---|
| **① 事实层** | 参考图集（每 UPC 一份 · 14 槽位） | **不可生成** | 所有生成调用 |
| **② 指令层** | 六段提示词（①②④ 冻 / ③⑤⑥ 变） | 冻资产 + 每格变量 | 提示词引擎 |
| **③ 生成层** | `gen_from_ref`（**唯一模型出口**） | 生成性 · 不可复算 | —— |
| **④ 判定层** | 客观规则过滤 + VLM 8 项 + 风险等级 + **人裁** | 机器只做预筛 | 闭环 |
| **⑤ 留档层** | `run.jsonl` + `lock_sha256` + 候选集 + 采纳记录 | 证据 | 回归 / 归因 / 算钱 |

**同源的保证方式换了**：v2 靠"结构上不可能错"（数据约束，A 不变量的原形态），
v4 靠"**锁 + 复用 + 校验**"三重锁（参考图集唯一 · 保真段逐字复用 · 风格锁逐字复用）。
⇒ 失败面从"只有环境层"扩大到"整张图"，代价已记在 `slots-v4` §8。

## 3. 第一性判据换了（架构层最要紧的一处）

v2 §2.3 的判据是：**模型只能创作它不承担事实责任的部分** ⇒ 结构上排除模型画商品。

**v4 直接违反了它** —— `slots-v4` §1 把不变量 B「生成层看不见主体」判为**删除并反转**：
参考图**必须**进模型。所以 v4 必须有替代判据，否则整份设计没有第一性根据。
草案里此前没有这条，本文补上：

> **判据 v4**：模型**可以**创作它承担事实责任的部分，
> 前提是**每一条事实主张都可被外部对照发现、且发现后可阻断**。

v2 §2.3 特意把"能不能被对照发现"称为**症状描述**，把"归属责任"称为更根本 ——
v4 恰恰把可发现性抬回成判据。这不是逻辑倒退，是**买卖换了**：

| | v2 | v4 |
|---|---|---|
| 买到的 | **结构安全**（主体不可能被改） | **呈现能力**（整图版式 / 场景融合 / 跨类目） |
| 付的 | 版式能力受限（引线、复杂构图做不了） | 失败面扩大 + 需要检测能力 |

**这笔交易的前提是 v4 新增了 v2 没有的检测能力**：k 张候选 · VLM 质检 8 项 · 风险等级 · 人裁 · 留档。
没有这些，"可被外部对照发现"就是空话 ⇒ 它们**不是附加功能，是这条判据的组成部分**。

⚠ **判据 v4 的硬边界**：它只对"能被对照发现"的主张成立。发现不了的（实测已见：
**纹理精细度退化**、审美品味）仍需 v2 式确定性兜底或纯人判 ⇒ 见 §5 末行。

## 4. 运行时：一次调用的形状

```text
E0 收件     体检 + 禁用词过滤；不合格 ⇒ 整批拒收（工具修不了不合规的输入）
      ↓
E1 事实层   抠图 / 归集 ⇒ 参考图集（每 UPC 一份，所有生成调用共享）· 唯一顺序依赖的另一端
      ↓
E2 指令层   读冻结锁段 ①②④（逐字）+ 填 ③⑤⑥（查表）⇒ plan.json（唯一状态）
      ↓
E3 扇出七路 ─┬─ 主路（2–7）：生成 k 张 → 客观规则过滤 → VLM 质检 8 项
             │                ├ 达标 ⇒ 留下这一轮
             │                └ 未达标 ⇒ 修正句尾部回灌 → 下一轮（≤ maxRounds；无修正句即止损）
             └─ 例外（1）  ：确定性合成（零模型调用）
      ↓
E4 判定层   人从 k 张挑 1（机器只预筛，不替人做审美判断）· 采纳按日志顺序判定
      ↓
E5 留档层   命名导出 + run.jsonl + lock_sha256 + 候选留档 + 采纳记录
```

**唯一顺序依赖：E1 → E3。** E3 七路彼此无依赖（与 v2 同）。
**重试分四层**（`slots-v4` §4.3）：R0 换 seed / R1 尾部追加修正句 / R2 换配方 —— 三者**都不动锁段**；
R3 改锁段须人签字。**"不动锁段"是重试的作用域边界。**

## 4.1 纯文本流程图（五条线）

### 线 1 · 资产线（离线 · 做完冻结 · 此后只读）

```text
新类目 ──┬─ 锁段 ①②④ 起草 ──→ 人签字 ──→ assets/locks/<category>.json
         │                                   │ 逐字复用 · lock_sha256
         │                                   │
新商品 ──┴─ 参考图集（每 UPC · 14 槽位）────┤ 事实层：不可生成
                                             │
failure_modes.json（FM-01…）→ 渲染否定句 ────┤ 唯一出处，写与校两边都读
                                             │
                                      （冻结后只读）
```

### 线 2 · 主干 E0–E5（在线 · 一批跑一次）

```text
E0 收件 ─不合格─→ 整批拒收 rc=3（工具修不了不合规输入）
   │合格
   ↓
E1 事实层   抠图 / 归集 ⇒ 参考图集（唯一顺序依赖的上游）
   ↓
E2 指令层   读冻结锁段逐字 + 查表填变量 ⇒ plan.json（唯一状态）
   ↓
E3 扇出七路 ─────────────────────────┐  七路彼此无依赖
   ↓                                 │
E4 判定层   人从 k 张挑 1（机器只预筛）│
   ↓                                 │
E5 留档层   run.jsonl / lock_sha256 / 候选 / 采纳
```

### 线 3 · E3 内部：一个主路 + 一个例外

```text
                ┌ 主路 · 位置 2–7 ───────────────────────────────┐
plan.json ──────┤  生成 k 张 → 客观规则过滤 → VLM 质检 8 项        │
                │        ↑                          │            │
                │        └─ 尾部追加修正句 ←── 未达标（≤maxRounds）│
                │                                   └ 达标 ⇒ 留候选│
                └────────────────────────────────────────────────┘
                └ 例外 · 位置 1 ─ 确定性合成 · 零模型调用
```

### 线 4 · 重试四层与作用域边界

```text
R0 换 seed              ┐
R1 尾部追加修正句        ├ 不动锁段 ⇒ lock_sha256 不变 ⇒ 差异可归因于 seed/修正句/随机性
R2 换配方（模板/镜位）   ┘   熔断：拿不到修正句即止损；`--accept` 是可调阈值线
════════════════════════╪════════════════════════════════ 作用域边界
R3 改锁段（人签字）      └ 动锁段 ⇒ 此后同批格与新锁段不同源（处置未定）
```

### 线 5 · 五层的数据流（谁能写、谁只能读）

```text
① 事实层 参考图集 ──┐
                    ├──→ ③ 生成层 gen_from_ref（唯一模型出口）
② 指令层 锁段+变量 ─┘              │ k 张候选
                                    ↓
                    ④ 判定层  规则过滤 → VLM 8 项 → 风险等级 → 人裁 1
                                    │ 采纳（按日志顺序判定）
                                    ↓
                    ⑤ 留档层  run.jsonl / lock_sha256 / 候选集 / 采纳记录
```

**读图关系的要点**：② 只被 ③ 读；① 被 ③ 读一次、被 ⑤ 留档；④ 不写 ②，只产出「修正句」交给
③ 的下一轮尾部 —— 即 **判定层永远不直接改指令层**，改锁段只能走线 4 的 R3 签字口。

## 6. 差量与未定

**差量**（按本骨架归位，顺序即 `slots-v4` §7 那七步）：

| 步 | 落在哪一层 |
|---|---|
| 1 提示词引擎（纯组装 · 不联网 · 不需要 key） | ② 指令层 |
| 2 `gen_from_ref`（1 个渲染器取代 5 个） | ③ 生成层 |
| 3 客观规则从"判定唯一张"改为"过滤候选" | ④ 判定层 |
| 4 VLM 质检 8 项 + 修正句 | ④ 判定层 |
| 5 闭环回灌（maxRounds / `--accept` / 熔断） | ④ → ③ |
| 6 候选集 + 人裁（k 挑 1） | ④ 判定层 + 界面 |
| 7 删 5 个确定性渲染器与三档重做（**最后删**） | 全局 |

**第 1 步是唯一"能先做完再谈钱"的一步** —— 它不联网、不需要 key、零调用。

**未定项**一律指向 `slots-v4` §10（一类=只有用户能答 · 二类=我已自定 · 三类=可实验前提），
**本文不复制第二份清单。**
