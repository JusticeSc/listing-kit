# 项目入口、工作台、资料与理解
[返回 product-v2-ui-contract.md](product-v2-ui-contract.md)

## 4. 逐视图契约

### 4.1 项目首页

| 层 | 内容 |
|---|---|
| 信息（默认） | 产品名与数据归属说明（一行）；新建输入框与主按钮；导入项目包（次）；项目列表：名称、状态徽标、更新时间、打开 |
| 信息（展开） | 每行的更多操作（重命名、复制、导出项目包、删除）；存储诊断（仅异常时） |
| 行为 | 新建、打开、导入、重命名、复制、导出项目包、删除 |
| 状态 | 空白（无项目）、列表、创建中、导入中、导入失败、存储能力失败 |
| 规则 | 空列表时突出“新建项目”；删除需二次确认；导入失败不产生半份数据 |
| 反馈 | 创建中禁用提交并显示进度；导入显示进度与结果；失败给分类原因与重试 |
| 导航 | 打开项目 → 工作台；返回 → 首页 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 新建项目（主） | 空白启动的唯一起点 | 名称非空 | 创建 IndexedDB 项目并进入工作台 | 名称缺失/存储失败的行内错误 |
| 导入项目包（次） | 跨浏览器/机器恢复 | 无 | 校验后写入本机并出现在列表 | 包损坏/版本过高等分类原因，不写入 |
| 打开 | 继续一个已有项目 | 项目存在 | 进入工作台并定位到当前阶段 | 打开失败 → 行内错误 |
| 更多：重命名/复制/导出项目包/删除 | 低频管理动作收进菜单，避免列表噪音 | 项目存在 | 对应结果或二次确认 | 行内错误，删除失败不改变列表 |

### 4.2 工作台外壳

| 层 | 内容 |
|---|---|
| 信息（默认） | 返回入口；项目名；六入口导航（当前/待处理/就绪）；模型设置及对应缺凭据状态；当前任务区；真实保存状态 |
| 信息（展开） | 项目元数据（创建/更新时间、schema 版本、存储用量）收进“项目信息” |
| 行为 | 切换任务区、打开设置、返回首页、重命名（低频）、导出项目包（交付区次操作） |
| 状态 | 草稿、就绪、处理中、部分失败、Unknown、可交付、存储错误 |
| 规则 | 操作就绪由领域与能力派生；导航/展开不授权外发、不改事实或采用；允许 §4.6 的本地准备记录，设置关闭回原任务 |
| 反馈 | 保存状态常驻；异步状态以 live region 提示，不抢焦点；明确跳到问题才将焦点落在问题标题 |
| 导航 | 错误靠近受影响操作，并提供“设置此用途/查看缺项/核对原任务”等具体入口 |

### 4.3 阶段一：资料

| 层 | 内容 |
|---|---|
| 信息（默认） | 参考图网格（缩略、角色、数量）；名称、介绍/卖点及草稿保存状态；“自己填写商品事实”与可选“AI辅助理解”入口 |
| 信息（展开） | 单张参考图的原始尺寸/哈希/去重说明；角色说明 |
| 行为 | 添加/设角色/删除参考图、编辑资料、保存草稿、进入人工事实、明确发起图文或仅文字理解 |
| 状态 | 缺输入、保存中、已保存、辅助理解中、提议待处理、失败；未调用AI不称商品无法理解 |
| 规则 | 生成所需资料按计划 §14；辅助理解按钮按实际输入/能力/key判断，保存或人工编辑不受key门；相同内容图不重复登记 |
| 反馈 | 字段旁给具体原因；失败保留资料并提示仍可人工完成。结果只更新其原资料身份的提议，异步不夺取正在编辑的任务/焦点 |
| 导航 | 人工入口无外呼；AI按钮显示“图文/仅文字”、实际模型、发送图片/文字和费用，缺key就地设置，配置完成不自动发起 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 添加参考图 | 生成必须以真实商品图为依据 | 无 | 登记参考图（按内容去重） | 非图片/超限/重复给行内说明 |
| 自己填写商品事实（主或次，随当前路径） | 不购买分析也能完整控制 | 项目ready | 打开相同事实编辑器，无外呼 | 未保存资料提示仍有草稿，不伪造已确认 |
| AI辅助理解（可选） | 从所发资料提出候选事实 | 图文/仅文字能力匹配、输入/key就绪，明确外发 | 正式理解消费者写提议及来源/证据，人在同一事实编辑器处理 | 分类错误/原输入过期如实显示，保留人工入口；不自动重试/覆盖确认事实 |
| 保存草稿（次，自动） | 避免丢输入 | 有改动 | 写入IndexedDB，不自动确认抽取结果 | 保存失败常驻提示，可重试 |

### 4.4 阶段二：理解

| 层 | 内容 |
|---|---|
| 信息（默认） | 可直接填写的核心事实；所选用途真正所需缺项/冲突及提议值；来源与状态可辨，非阻塞已确认项折叠 |
| 信息（展开） | 全部事实、置信及原图/原文证据、消费者/影响范围、自定义事实表单 |
| 行为 | 人工编辑并保存确认、确认/修订模型提议、处理冲突、标未知、增删自定义事实 |
| 状态 | 人工草稿、辅助提议待处理、冲突/缺项、已确认；未分析不是阻断状态 |
| 规则 | 人明确保存确认是一次确认性操作，不再要求下一页重复确认；模型仅提议。字段需求及确认权限取计划 §14.2–14.4，同一事实供多图复用 |
| 反馈 | 保存与确认反馈真实；缺项说明受影响哪张图/哪个声明，能直接修复。来源/actor/status不混为“模型说过就确认” |
| 导航 | “编辑图片方案”始终可导航；不完整任务可先建，具体生成动作按所需已确认输入判断 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 人工保存并确认 / 确认提议 / 处理冲突（行内） | 事实决定生成内容，权限归人 | 字段类型/动作有效 | 同一FactSlot写新版本并更新真正消费者；一操作不重复确认 | 行内错误/版本冲突，旧确认值与草稿保留 |
| 显示全部事实（次） | 渐进披露，默认只看异常 | 无 | 展开已确认项 | —— |
| 新增自定义槽位（次） | 允许扩展，不锁死在预设 | 标识/名称/值合法 | 新增并纳入依赖统计 | 校验错误行内提示 |
| 编辑图片方案（主） | 先选用途再补对应信息 | 项目ready | 进入方案，无外呼不确认事实 | 缺项在具体任务呈现，不阻断导航 |
