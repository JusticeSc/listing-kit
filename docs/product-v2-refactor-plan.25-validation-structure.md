### 15.3 验证选择与停止规则

| 改动/时点 | 默认最小检查 | 何时扩大；不做什么 |
|---|---|---|
| 连贯批次中的单次编辑 | 不启动回归/探针；按正常编辑/类型诊断工作 | 不“保存一次跑一次”，不每改一处重启全链 |
| 文案/样式/局部交互 | 批次结束实际看受影响页面，操作该控件及相关焦点 | 不新增文案/源码断言，不全跑模型/ZIP/状态机 |
| 事实/依赖/Prompt纯规则 | 最接近的既有行为/边界用例，外加消费该规则的一条实际路径 | 规则跨多用途则覆盖实际消费者；无传播依据不全跑浏览器矩阵 |
| 配置/凭据/共享执行身份 | 受影响用途的正式装配和实际请求/保存/恢复，重点隔离/秘密/Unknown | 不能只看设置框或mock回声；协议未改不重复供应商付费证明 |
| 事务/记录格式/Blob/ZIP | 受影响操作、持久化/冲突及真实字节往返 | 公共数据不变量受影响或范围无法界定才扩大对应宿主回归；不例行重做压力测量 |
| 普通进度/证据更新 | 批次结束一次状态/恢复一致性；已有冷恢复入口包含登记和状态核对，不重复包三层相同检查 | 不把状态探针当每次编辑前置；阶段/任务/依赖改变后的提交前探针仍按AGENTS一次执行最新基线 |
| 权威归属/依赖锁/守卫/状态协议改变 | 对应登记/状态检查及能判红的既有反例，串行 | 只有这些合同改变才重核其失败判据，不因普通产品代码修改跑64向状态探针 |
| 最终候选/跨切片影响不可界定 | 既定必要完整回归与正式入口任务，按R7.1/R7.4 | 最终两轮不变成日常两轮；无新问题/改动不连续重跑“提高信心” |

选择验证先回答“本次可能破坏哪条消费者行为、哪项输出能证明没有破坏”。答不出不得加检查。已有证据复用条件是对应代码路径/合同/输入和运行前提未受影响，不是仅看旧pass或任意全仓hash变化就全部失效。

失败先保留事实，定位最早失效层；修复后只重验受影响项，再在最终边界完成必要回归。基础设施故障先恢复基础设施，不盲跑产品验证；Unknown不转失败、不自动重提；费用无法界定/额度到停止门即停止付费。

永久回归、一次性smoke、本次运行集合及用例保留/合并/删除的唯一工作规则在AGENTS Testing Guidelines；本节只规定运行时点/扩大条件。具体必要测试与重复验证清理归Issue #7，不复制测试登记平台。

每批记录一段即可：**交付了什么、修改位置、实际验证及其结果/耗时（可测时）、限制/阻塞、下一批**。不按测试数或报告数计进度，不规定虚假的工时/验证占比，不为留证据新建计时/验证平台；真实检查输出可附在同一既有证据下。

### 15.4 同时完成当前 Goal 与结构重构

2026-10-06用户明确要求“我要你同时完成goal和重构”。本轮将下列结构工作纳入原工程交付，不以先补丁发布、以后重构拆开交付，不另建Goal、不更改§2.1正文或降低RC验收；原栈、预算、秘密边界、分支保护及V1日落外部门不变。承接R5.1/R5.3、R6.1–3、R7.5及最终R7.1/R7.4，不新建平行任务权威。

2026-10-06用户追加要求详细设计，并明确重构应主动消除代码/设计问题、重复冗余、历史材料和脆弱测试，而非等用户逐项指出。详细设计唯一在 `product-v2-refactor-design.md`；2026-10-07有限收口按本计划§15.6与设计§11.5承接，不新增平行依赖/任务/RC。原Goal已覆盖完整结果与必要结构收口，故本次无需改其text正文；用户允许必要文档修订不等于解除施工停工门。

- **工作台职责与状态所有权**：按详细设计§2–4/§9.1建立输入、Prompt、生成授权及执行、单图报告/采用、整套交付的唯一业务所有者；工作台仅装配生命周期、发业务动作与投影视图，不保留业务Map/序列。强耦合授权合入生成，删除独立转发层，不把闭包拆成共享可变context与callback网。执行及UI消费同一领域判据；当前性/授权消费/包一致性须有实际版本和事务证明，冻结Snapshot或单页Set不替代。
- **验证的稳定Interface**：测试通过稳定业务Interface，删留按AGENTS Testing Guidelines，不把重构或普通措辞变更钉成合同。确认即提交按本次授权/shot/action的新消费证明，旧attempt行不能充当新动作证据。共同UI前置只维护一处，验证器不互作万能库；无业务落盘及反向控制探针在隔离受测根上验证，不临时改真实current state或以全库证据写入判产品红。
- **重复冗余的主动治理**：每包审查变化原因、规则/状态/前置复制、过宽Interface、callback环、薄wrapper、别名/重导出和双维护TS/JS；语义一致者合并，已失效者在全部消费者迁移同包删除。按详细设计§6–8分类源码/生成物/历史证据/失败/账本/许可/用户原件，不以全部归档、文件拆分或大量回归代替设计与清理；不扩大到无关业务或未授权删除。
- **历史运行与交付物**：本轮R7.3按V2覆盖、消费者切换及代码/数据恢复基线删除V1活路径，不盲删用户历史原件/许可/失败。生产闭包只含真实V2依赖；源码TS与生成JS按SEL-021单一维护，历史证据不作为现行实现或恢复指令。
- **联合完成判据**：原§14.9人工和辅助完整任务、恢复/隔离/两类ZIP/秘密/实际HTTPS发布继续成立；详细设计§9.1六项结构准出逐项有证据。普通业务修改局部集中、移动Implementation不触发源码形状假红，调用方不需要重建持久化/授权/外发顺序；所有旧读写/别名/双轨调用清除、历史分类及稳定行为判据保留。类型/生成一致性覆盖所有改变的Module及消费者；切片只实跑改变路径和相关判据，既定最终两轮回归在整合完成后执行。不得以文件数/行数减少、语法通过或假模型结果宣布结构或Goal完成。
