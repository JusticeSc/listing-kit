# Product V2 交互与视觉契约（V2.UI.2）

> CONTROL-STATUS: draft · AUTHORITY: ui-interaction-contract（产品发起人走查确认前为设计草案；确认后转 current 并补入 INDEX 路由）
> 本文件只定义“用户看到什么、能做什么、什么状态下能做什么、操作后系统如何反馈”，以及支撑它的表现层基线。
> 目标、对象、数据所有权与状态机由 `docs/product-v2-goal-and-implementation-plan.md` 与
> `docs/product-v2-project-context.md` 管辖；本文件不改写它们，只做投影。

## 1. 目的与边界

- 把业务模型编译成界面模型：对象 + 信息 + 行为 + 状态 + 规则 + 反馈 + 导航 + 表现。
- 适用范围：项目首页与同页六阶段工作台（资料—理解—方案—生成—审核返工—交付）。
- 不改：领域对象与状态机、IndexedDB 所有权、Provider 语义、服务端 API 合同、既有数据格式。
- 完成判据：产品发起人在真实页面（正式入口 + fake provider）走查并确认信息层级、主操作、图片比较与视觉方向。

## 2. 业务对象与全局规则

**对象（用户视角）**

| 对象 | 用户看到什么 | 可以做什么 |
|---|---|---|
| 项目 Project | 名称、状态、更新时间、参考图、当前套图 | 新建、打开、重命名、复制、导出项目包、删除 |
| 参考图 Reference | 缩略图、角色（主图/细节/场景/竞品…）、数量 | 添加、设角色、删除 |
| 商品事实 FactSlot | 名称、值、来源（用户/模型）、确认状态、置信 | 确认、修改、标未知、移除、增删自定义槽位 |
| 套图计划 SuitePlan | 有序图片任务（角色、目的、依据） | 生成推荐、添加模板/自定义、复制、删除、排序、编辑 |
| 公共风格 StyleSpec | 背景、光线、色调、构图、避免项、版本 | 编辑、保存为新版本、恢复上一版本 |
| 单图规格 ShotSpec | 每图的保留项/允许变化项/审核清单 | 编辑、保存新版本、恢复 |
| Prompt 版本 | 每图 Prompt 全文、语言策略、版本、hash | 查看、编辑并另存新版本、重新编译 |
| 生成记录 Attempt | 状态、进度、task id、基于的版本 | 提交、核对、重试（仅已确认失败）、新建 action |
| 候选 Candidate | 图片、尺寸、哈希、检查报告、来源 | 预览、比较、返工（生成新候选）、采用 |
| 采用 Selection | 每图当前选中的候选与状态 | 采用、改选、取消采用 |
| 交付 | 选择总览、阻断项、导出 | 导出项目包；交付包待 V2.6.2 接入 |

**全局规则**

1. 同一时刻只有一个视觉主操作；主操作随当前阶段推进，禁用时必须说明缺什么。
2. 工程信息（Prompt 全文、hash、action/task id、provider 身份、版本号、指纹）默认收进“详情”，但都可查看、复制。
3. 状态来自真实记录与派生（repository/domain），界面不写死假状态；fake provider 只替代外部模型调用。
4. 上游变化让下游过期（STALE）时，显示“已过期 + 原因 + 重新生成入口”，不静默丢弃历史。
5. 未确认的模型推断不算事实；未人工采用的候选不算选择；未通过门禁不能交付。
6. 任何失败都要给出：发生了什么、影响什么、下一步做什么（重试/核对/换入口）。
7. 页面不预填示例商品；空白启动是默认路径。

## 3. 信息架构

首页（项目）+ 同页工作台六阶段：

| # | 阶段 | 目标 | 完成条件 | 默认展开 | 完成后的摘要 |
|---|---|---|---|---|---|
| 1 | 资料 | 收集生成依据 | 名称 + ≥1 张主图 | 参考图与商品资料 | 名称 · 参考图 n 张 |
| 2 | 理解 | 把提议变成已确认事实 | 关键事实全部确认 | 异常/低置信优先，已确认折叠 | 已确认 n 项 · 未知 m 项 |
| 3 | 方案 | 决定拍哪些图、什么风格 | ≥1 张图且无未满足硬依赖 | 图片任务列表；风格与规格折叠 | n 张图 · 风格 v |
| 4 | 生成 | 产出候选 | 每张必需图有候选或已确认失败 | 确认单 + 逐图进度 | n 成功 · m 失败 · k 待核对 |
| 5 | 审核返工 | 处理问题并人工采用 | 每张必需图有当前采用 | 图片为中心的候选与清单 | n/m 已采用 · 问题 k |
| 6 | 交付 | 通过门禁并导出 | 全部门禁通过 | 选择总览与阻断清单 | 就绪 / 阻断原因 |

导航规则：阶段条始终可见；可达阶段可点击切换，不可达阶段禁用并给出原因；进入工作台默认停靠最靠后的“有未完成动作”的阶段；已完成阶段可回看并显示摘要。

## 4. 逐视图契约

### 4.1 项目首页

| 层 | 内容 |
|---|---|
| 信息（默认） | 产品名与数据归属说明（一行）；新建输入框与主按钮；导入项目包（次）；项目列表：名称、状态徽标、更新时间、打开 |
| 信息（展开） | 每行的更多操作（重命名、复制、导出项目包、删除）；存储诊断（仅异常时） |
| 行为 | 新建、打开、导入、重命名、复制、导出项目包、删除 |
| 状态 | 空白（无项目）、列表、创建中、导入中、导入失败、存储能力失败 |
| 规则 | 空列表时突出“新建项目”；删除需二次确认；导入失败不产生半份数据 |
| 反馈 | 创建中禁用提交并显示进度；导入显示进度与结果；失败给分类原因与重试 |
| 导航 | 打开项目 → 工作台；返回 → 首页 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 新建项目（主） | 空白启动的唯一起点 | 名称非空 | 创建 IndexedDB 项目并进入工作台 | 名称缺失/存储失败的行内错误 |
| 导入项目包（次） | 跨浏览器/机器恢复 | 无 | 校验后写入本机并出现在列表 | 包损坏/版本过高等分类原因，不写入 |
| 打开 | 继续一个已有项目 | 项目存在 | 进入工作台并定位到当前阶段 | 打开失败 → 行内错误 |
| 更多：重命名/复制/导出项目包/删除 | 低频管理动作收进菜单，避免列表噪音 | 项目存在 | 对应结果或二次确认 | 行内错误，删除失败不改变列表 |

### 4.2 工作台外壳

| 层 | 内容 |
|---|---|
| 信息（默认） | 返回入口；项目名；阶段条（序号+名称+完成/当前/锁定）；当前阶段面板；保存状态（已保存/保存中/保存失败） |
| 信息（展开） | 项目元数据（创建/更新时间、schema 版本、存储用量）收进“项目信息” |
| 行为 | 切换阶段、返回首页、重命名（低频）、导出项目包（交付阶段的次操作） |
| 状态 | 草稿、就绪、处理中、部分失败、Unknown、可交付、存储错误 |
| 规则 | 阶段可达性由既有领域状态派生；切换阶段不触发写操作；离开页面不丢失草稿 |
| 反馈 | 保存状态常驻但安静（小字）；异步完成后焦点落到结果标题或首个问题 |
| 导航 | 阶段条即导航；错误提示内联在对应阶段面板顶部 |

### 4.3 阶段一：资料

| 层 | 内容 |
|---|---|
| 信息（默认） | 参考图网格（缩略图、角色、数量）；商品名称（必填）、介绍、卖点、本次重点；草稿保存状态 |
| 信息（展开） | 单张参考图的原始尺寸/哈希/去重说明；角色说明 |
| 行为 | 添加参考图、设角色、删除参考图、编辑资料、保存草稿（自动+手动） |
| 状态 | 缺输入、保存中、已保存、分析中（进入下一阶段的过渡）、失败 |
| 规则 | 名称与至少一张主图齐全前，“分析商品资料”禁用并说明缺什么；相同内容图片不重复登记 |
| 反馈 | 行内错误紧邻字段；分析失败给分类原因与重试；成功后自动切到阶段二 |
| 导航 | 主操作推进到“理解” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 添加参考图 | 生成必须以真实商品图为依据 | 无 | 登记参考图（按内容去重） | 非图片/超限/重复给行内说明 |
| 分析商品资料（主） | 让系统提出商品理解，而不是要求用户写提示词 | 名称 + ≥1 主图 | 调用语义 provider，写入“模型提案”，进入阶段二 | 分类错误 + 重试；不静默，不覆盖用户输入 |
| 保存草稿（次，自动） | 用户不应担心丢失 | 有改动 | 写入 IndexedDB | 保存失败常驻提示，可重试 |

### 4.4 阶段二：理解

| 层 | 内容 |
|---|---|
| 信息（默认） | 待处理项（冲突、未知、低置信、必确认）：名称、提议值、来源、置信、操作 |
| 信息（展开） | 全部事实（含已确认）、来源与依据、依赖关系；新增自定义槽位表单 |
| 行为 | 确认、修改、标未知、移除、新增槽位（可授权模型提议） |
| 状态 | 未分析（空）、分析中、待确认 n 项、已确认 |
| 规则 | 模型提议不自动确认；关键事实未确认不能进入方案；每个决定写新版本而不是覆盖 |
| 反馈 | 每项操作即时更新进度（已确认 n/m）；阻塞项直接指向第一条未处理 |
| 导航 | 主操作推进到“方案” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 确认 / 修改 / 标未知 / 移除（行内） | 事实决定后续全部内容，必须逐项可控 | 槽位存在 | 写入新记录并更新依赖状态 | 行内错误，旧值保留 |
| 显示全部事实（次） | 渐进披露，默认只看异常 | 无 | 展开已确认项 | —— |
| 新增自定义槽位（次） | 允许扩展，不锁死在预设 | 标识/名称/值合法 | 新增并纳入依赖统计 | 校验错误行内提示 |
| 确认并进入方案（主） | 推进的单一出口 | 关键事实全部确认 | 进入阶段三 | 禁用并列出未确认项 |

### 4.5 阶段三：方案

| 层 | 内容 |
|---|---|
| 信息（默认） | 图片任务列表：缩略/角色、名称、目的、依据满足或阻断、顺序操作 |
| 信息（展开） | 公共风格（背景/光线/色调/构图/避免）、单图规格（保留项/允许变化项/审核清单）、模板说明 |
| 行为 | 生成推荐方案、添加模板图、添加自定义图、复制、删除、排序、编辑风格与规格、恢复上一版本 |
| 状态 | 锁定（理解未完成）、空、编辑中、依赖阻断、就绪 |
| 规则 | 列表顺序即最终顺序；条件依赖（对比图必须有竞品参考图等）精确阻断并说明原因 |
| 反馈 | 每次操作写到新版本；依赖阻断时在主操作旁列出缺什么 |
| 导航 | 主操作推进到“生成” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 生成推荐方案（空态主） | 默认方案降低门槛 | 理解已确认 | 生成 1..N 张图的推荐列表 | 失败保留空态并给原因 |
| 添加模板图 / 添加自定义图 | 支持人工增减 | 理解已确认 | 追加图片任务 | 依赖不足时标记阻断 |
| 复制 / 删除 / 上移 / 下移（行内） | 常规编排 | 至少一张图 | 更新顺序或集合 | 失败不改旧计划 |
| 编辑风格/规格（折叠区） | 需要时精确控制 | 有图 | 新版本并标注影响范围 | 保存失败保留旧版本 |
| 准备生成（主） | 推进的单一出口 | 无硬阻断 | 编译 Prompt，进入阶段四 | 禁用并列阻断原因 |

### 4.6 阶段四：生成

| 层 | 内容 |
|---|---|
| 信息（默认） | 确认单（张数、每图任务、将发送的资料摘要、未消除风险）；逐图进度（状态徽标、进度、候选缩略） |
| 信息（展开） | 每图 Prompt 全文与版本、hash、action/task id、provider 身份、Attempt 历史 |
| 行为 | 重新编译 Prompt、编辑 Prompt 另存新版本、生成前确认、整套生成、停止新增提交、核对进行中、重试失败、单图重新生成、查看候选 |
| 状态 | 阻断（缺 Prompt/过期/依赖）、就绪待确认、已确认、生成中、部分失败、Unknown、完成 |
| 规则 | 确认记录绑定指纹，上游变化即失效；Unknown 不自动重提，先核对；重试只针对已确认失败 |
| 反馈 | 逐图进度条与状态徽标；失败行给原因与“重试/核对”动作；完成行给“去审核”入口 |
| 导航 | 主操作推进到“审核返工”；单图完成可直达该图的审核 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 生成前确认（主，首次） | 明确将发送什么、花多少张 | 无阻断 | 记录确认（绑定指纹） | 阻断项列出并可定位 |
| 整套生成（主，确认后） | 一次产出整套 | 确认记录当前 | 逐图提交并显示进度 | 部分失败不丢成功；可停止/重试 |
| 停止新增提交 / 核对进行中 / 重试失败 | 处理异常而不重启整批 | 对应状态 | 停止排队、核对 task id、重试已确认失败 | Unknown 只核对，不自动重提 |
| Prompt 编辑并保存（展开区） | 需要时精确修正 | 图存在 | 新版本，旧版本保留 | 校验失败保留原版本 |

### 4.7 阶段五：审核返工

| 层 | 内容 |
|---|---|
| 信息（默认） | 每图一张审核卡：当前候选大图、候选缩略串、审核清单（先看项/问题）、采用状态 |
| 信息（展开） | 完整检查报告、Prompt 与版本、候选来源（参考图/历史/返工）、hash |
| 行为 | 比较候选、切换候选、按问题返工、自定义方向返工、预览返工 Prompt、采用/改选/取消采用 |
| 状态 | 未审核、有问题（高/中/低）、报告过期、返工中、已采用（当前/过期）、Unknown |
| 规则 | 自动检查只提示不阻断，不产生采用；返工只影响目标图；旧候选与历史保留；改选必须显式 |
| 反馈 | 采用状态逐图可数（n/m）；比较面板键盘可操作；异常优先排序 |
| 导航 | 全部必需图采用后，主操作推进到“交付” |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 比较候选（行内） | 直接比较是审核的核心动作 | ≥1 候选 | 打开比较面板（参考图/历史/新） | 面板内错误不阻塞其它图 |
| 按问题返工（行内） | 把“不满意”变成可执行方向 | 有候选 | 收集问题+方向，预览 Prompt 后生成新候选 | 失败保留旧候选；可重试 |
| 采用这条候选（行内/面板） | 人工决策是唯一选择来源 | 候选当前且可用 | 写入 Selection | 写失败不改旧选择 |
| 取消采用（行内） | 允许纠正 | 已采用 | 标记未采用 | —— |
| 去交付（主） | 推进的单一出口 | 全部必需图已采用 | 进入阶段六 | 禁用并列出未采用图 |

### 4.8 阶段六：交付

| 层 | 内容 |
|---|---|
| 信息（默认） | 选择总览（每图：已选候选缩略、状态、跳转）；阻断清单（未选、Unknown 待核对）；整套一致性落点（V2.5.5 接入前显示为待接入） |
| 信息（展开） | manifest 预览（选定图、规格版本、检查结果）；导出历史 |
| 行为 | 定位阻断到对应阶段、导出项目包、生成交付包（V2.6.2 接入后可用） |
| 状态 | 阻断、就绪、生成中、已生成、失败 |
| 规则 | 缺选或硬检查失败不能导出；Unknown 必须人工核对；导出记录 append-only |
| 反馈 | 阻断项可点击直达修复位置；导出失败给分类原因并可重试 |
| 导航 | 返回审核/生成修复阻断；导出完成显示结果与复检入口 |

**按钮清单**

| 按钮 | 为什么需要 | 前置 | 结果 | 失败反馈 |
|---|---|---|---|---|
| 定位到阻断项（行内） | 阻断必须可修复 | 存在阻断 | 跳到对应图片/阶段 | —— |
| 导出项目包（次） | 完整历史可迁移（已实现） | 项目存在 | 浏览器生成项目 ZIP | 失败给原因 |
| 生成交付包（主） | 最终交付物 | 全部门禁通过（V2.6.2 接入） | 浏览器生成交付 ZIP | 精确指出未通过的检查 |

## 5. 表现层基线

**token（单一来源：`app/product_v2/styles.css` 的 `:root` 变量，组件不写死颜色/间距）**

- 颜色：中性底 `--bg` / 面板 `--surface` / 边界 `--border`；主色 `--accent`（一个品牌蓝，深浅两档）；
  语义 `--success` / `--warn` / `--danger` / `--info`；文本 `--text` / `--text-muted`；焦点 `--focus`。
- 字体：系统字体栈；字号 12 / 13 / 14 / 16 / 20 / 24；行高 1.4–1.6；字重 400 / 600；等宽仅用于 hash 与 id。
- 间距：4 的倍数（4 / 8 / 12 / 16 / 24 / 32）；圆角 6 / 10；边框 1px；阴影仅用于浮层，不用于普通卡片堆叠。
- 图片：缩略 64 / 96；审核大图最长边 ≥ 420；统一 `object-fit: cover` 与固定宽高比，避免布局跳动。

**组件与状态**：按钮（primary / secondary / ghost / danger / link；default / hover / focus-visible / disabled / loading）、
输入与文本域（label / 帮助 / 错误 / 只读）、卡片（标题 + 说明 + 内容 + 动作区）、列表行（含徽标与行内动作）、
状态徽标（空白 / 进行中 / 成功 / 警告 / 失败 / 未知 / 过期）、步骤条、进度条、空态、错误条、
浮层面板（比较 / 返工 / 采用）、`<details>` 渐进披露区。

**无障碍与响应式**：正文与控件对比度 ≥ 4.5:1；移动端触控目标 ≥ 48px；所有输入有可见 label（不用 placeholder 代替）；
表单使用语义元素；`:focus-visible` 2px 可见轮廓；tab 顺序与视觉顺序一致；异步结果用 `role="status"`/`role="alert"`；
1440px 主布局内容最大宽度约 1120px；390px 单列、阶段条横向滚动；200% 缩放不出现关键操作遮挡或横向滚动条。

## 6. 代表状态清单（证据要求）

1. 空白首页（1440 / 390）；2. 已有项目首页；3. 存储或能力错误（HTTP 负例或数据库打开失败）；
4. 资料缺输入（主操作禁用并说明缺什么）；5. 理解异常待确认（含低置信/未知）；6. 方案编辑（含依赖阻断）；
7. 生成中；8. 部分失败与 Unknown；9. 候选比较（参考图/历史/新）；10. 返工面板（问题+方向+预览）；
11. 已采用状态（阶段五完成）；12. 交付阻断与就绪；13. 200% 缩放；14. 键盘路径（Tab 完成主流程）。

## 8. 走查、变更与生效

- 走查脚本：首页（空白）→ 新建 → 资料 → 理解 → 方案 → 生成（含部分失败与 Unknown）→ 审核返工（比较/返工/采用）→ 交付（阻断与就绪）→ 错误状态 → 390px 与 200% 缩放。
- 走查确认项：信息层级、主操作、图片比较、视觉方向；任何“需要旁边解释才知道点哪里”、工程字段压过业务信息、关键操作被遮挡或仍像调试表单，都判未通过。
- 生效：产品发起人确认后，本文件 CONTROL-STATUS 转 `current`、INDEX 管辖事实转 `架构设计` 并补入路由；任务的完成证据与被否项一并记录。
- 变更：实现偏离先改本文件再改代码；界面不得引入第二套状态源；任何新增视图/按钮必须补充到第 4 节对应清单并说明理由。
